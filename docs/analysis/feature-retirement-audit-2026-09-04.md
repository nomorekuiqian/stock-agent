# 功能删减建议：生产证据审计

日期：2026-09-04 PDT。用户要求 UI 不改，先列删减建议并统一模型。本次未下线功能、未修改 UI、未改生产 schedule、未发送邮件、未操作账单。

## 判断

建议优先退出 **持仓体检、独立 Research-KB 聊天、个股独立新闻/宏观分析生成器**；把 **KOL 助手并入统一研究入口**；继续冻结旧 Monitor 与 Panda 独立服务。真正值得压缩的持续加工是 **全量 KOL 推文摄入与逐条 AI 加工**，不能把已停用任务再次包装成新增节省。

核心保留：用户选择持仓/关注股票 → 与这些股票有关的简报 → 针对简报继续追问 → 邮件交付、账号和订阅。详细股数、成本、止损、评分不应成为开始使用的前置要求。

## 优先削减的持续加工：全量 KOL 数据链路

- 最近 30 天存入的推文发布时间落在窗口内的记录 **116,742 条，326 位作者**；这是存量中按推文发布时间筛选的数量，不等于抓取 API 请求数。
- 当前 KOL 抓取 schedule 每小时运行；列表同步每日，向量索引每日 4 次。
- `twitter_digest.enrich` 的 LLM 调用 **4,997 次**，占可观测全部生成调用 **7,562 次的 66.1%**，记录输入约 3,821 万 token、输出约 335 万 token。加工一次不等于一位用户的一次需求。
- Twitter 摘要近 30 天有 **31 位外部登录用户、97 次成功读取**，邮件中指向摘要的链接有 **23 次点击、5 位外部收件人**。所以“整个 KOL 日报无人用”不成立。

建议砍掉无差别全量加工：先用规则/元数据筛掉重复、闲聊与无关内容，优先持仓 ticker、相关产业链和必要宏观事件，再做 AI 加工；保留少量优质宏观来源，避免只匹配 ticker 漏掉间接影响。同一事件只分析一次，再按用户持仓筛选分发。先对历史样本与小范围新数据做漏报对照，再缩减来源/频率；目前没有逐来源 ROI 或人工标注召回率，**不承诺一个未经验证的节省比例**。

## 模型升级和费用口径

本地运行时模型已统一为 `gemini-3.8-flash`，唯一配置为 `backend/app/core/ai_models.py`。Brew 免费/付费共用模型但保留权益判断与分别计量；ADK Agent、辅助抽取、KOL follow-up、个股分析、周报、旧可调用生成入口均同步。原 DeepSeek 结构化调用已迁移 Gemini 原生客户端。Research/KOL 的 `MINIMAL` 改为 `LOW`；个股 503 保留同模型一次重试，避免共享对象临时切换。

Embedding 模型、历史缓存 model 标签和离线人工导入 provenance 保留；没有把历史分析冒充新模型。旧缓存无模型信息时返回 `unknown`。

按 [Google 当前价格](https://ai.google.dev/gemini-api/docs/pricing)，3.8 Flash 标准价格在 2026-12-31 前为输入 $0.75、缓存输入 $0.075、输出含 thinking $3.75 / 百万 token，2027-01-01 起翻倍。[模型文档](https://ai.google.dev/gemini-api/docs/models/gemini-3.8-flash) 明确不支持 MINIMAL。

**仅把上述旧 30 天 token 样本按新价格重算，约 $102.89；其中推文加工约 $41.22，付费档 Brew 加工约 $34.82，KOL 研究约 $16.75。**这是固定旧 token 的反事实重算，不是实际账单，也不是新模型月度预算；模型换代后输出/思考量会变，旧 LLM 归因 user_id 均缺失、部分 thinking 未上报，另有 metering 断档，不含数据服务/搜索/缓存存储等费用。

费用展示已补充 3.8 价格与 thinking/cache 的聚合字段；**需要后台和 `llm-usage` Edge Function 一起发布**。本次未提交、推送或部署，所以生产服务目前尚未切换。

验证：相关业务测试 270 项通过；后续新客户端/计价/Edge Function 回归 16 项通过（与 270 有重叠，不相加）；23 个运行时模型常量加载检查全部为 3.8；真实 Gemini JSON 与 ADK 工具调用 smoke 成功，无持久化或发送。

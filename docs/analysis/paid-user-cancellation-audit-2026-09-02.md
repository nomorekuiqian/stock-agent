## 口径说明

“当前持续扣费用户”以 Stripe 实时订阅为准，不直接使用数据库中的 `plan=pro/max` 数量。数据库共有 40 个有效 Pro/Max 权益，但其中 8 个不是当前循环扣费：6 个为终身权益，2 个为特殊授权。

“已经完成退订并离开”要求同时满足：存在金额大于 0 的已支付 Stripe invoice；存在已取消的正价订阅；按邮箱跨 Primary 与 Legacy 两个账户去重；当前没有任何有效循环订阅。这样可以排除免费记录、未完成支付、重复订阅，以及账户迁移产生的旧订阅取消。

数据库中虽然有 291 行 `status=canceled`，但它们大多不是实际付费流失，不能用作付费退订人数。

## 退订失败检查

- Railway 当前保留的近 30 天记录中，`POST /api/payment/cancel-subscription` 有 5 次，全部返回 HTTP 200；未发现 4xx/5xx 或取消异常日志。这里是调用次数，不等同于 5 个唯一用户。
- 当前 4 个 `cancel_at_period_end=true` 的订阅已逐个向 Stripe 实时查询，均为 `active` 且已设置到期取消；数据库与 Stripe 完全一致。
- 当前没有 `past_due` 或 `unpaid` 的订阅。
- 现有系统没有独立的“退订意图/退订尝试”审计表，因此无法识别只打开 Billing Portal、但没有确认取消的人；这类行为不能算作退订失败。

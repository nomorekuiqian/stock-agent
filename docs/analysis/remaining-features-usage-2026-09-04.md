# 剩余功能与邮件用量审计

统计截止：2026-09-05 04:00 UTC（2026-09-04 21:00 PDT，北京时间 2026-09-05 12:00）。

目前更接近一个以邮件交付为主、站内轻使用的投研服务。最近一周每个工作日，专属日报送达约 32 人，盘前早报与 KOL 日报各约 40 人；站内记录到 22 位外部登录用户。不能将各栏目的用户数相加，很多用户同时使用多个功能。

本次为只读审计，没有修改网站、发送邮件、改变任务或套餐。

## 统计口径

- 30 天窗口：2026-08-06 04:00 至 2026-09-05 04:00 UTC；近 7 天：08-29 04:00 起；前 7 天：08-22 04:00 至 08-29 04:00，均左闭右开。
- 站内行为、对话、持仓与邮件指标：排除生产 `ADMIN_EMAILS` 中 5 个管理员、1 个文档测试账号，以及 `@example.com`。各表只按能关联到的账号排除，不推断未知账号身份。
- 站内来源为 `user_activities` 的成功 API 请求和 `agent_session_events` 的实际 `user_message`，不是 PV。后台自动拉取、刷新和缓存读取可能形成多次请求。
- 该 API 记录器只覆盖携带 Bearer token 且命中 token cache 的请求；公开页面、匿名访问、未进入记录器或丢失的缓冲事件不能完整覆盖。不能把“未观测到”当作“没人访问”。
- 当前 PostHog 浏览器停留在登录页，未取得其页面分析数据；也未取得 Vercel 的全站访问统计。公开盘后晚报和宏观页面 UV/PV 因此保留为未知。
- `llm_usage` 是全系统历史记录，包含管理员/测试/后台调用；大量旧记录没有 user_id，无法按普通用户完整过滤。一次 AI 对话可能包含多次 LLM 调用。
- 本窗口绝大部分发生在功能暂停和模型升级之前，不能用它判断改版后的效果，也不能直接当成新模型的月度账单。

## 邮件：按同一批送达邮件计算

打开率 = 窗口内首次送达、且截至统计时间至少打开一次的邮件数 ÷ 窗口内首次送达邮件数。
点击率同理，每封邮件只计一次。收件人、打开人数、点击人数另外按邮箱去重。重复打开、重复点击不重复增加分子；窗口前送达、窗口内才打开的旧邮件不混入。

现有 webhook 没有存储 `email.sent` 事件，因此用户表采用“已送达”作为明确可核对的分母。52 个广播批次另外向 Resend 读取发送/送达指标，含内部账号共发送 5,733 封、送达 5,707 封、退信 26 封，另有 12 封被抑制未发。52 个批次的送达数逐个与数据库完全一致。专属日报和欢迎信属于直接发送，不包含在这组广播数中。

广播邮件的数据库 channel 原本全部为 unknown，但 broadcast_id 完整。本次按 Resend 真实广播名称映射晚报、早报、KOL、周报；专属日报和欢迎信使用原有明确标签，不靠主题猜分类。

前一周的邮件拥有更长的打开观察期，最新邮件还可能继续被打开，因此短期打开率变化不完全等于用户兴趣变化。

每送达 100 封专属日报，约 61 封记录到打开、不到 1 封记录到点击。KOL 日报约 56 封打开、2.6 封点击，在现有栏目中点击率最高，但 30 天只有 6 位点击者；不应把 23 封点击邮件当成 23 个用户。

打开是追踪像素加载信号，不是确认人工阅读。图片屏蔽可能漏记，隐私预加载/安全扫描可能多记；本数据库也没有可靠的人机过滤标识。Resend 的说明见 [打开率准确性](https://resend.com/docs/knowledge-base/why-are-my-open-rates-not-accurate)。邮件中直接提供了正文，点击率低也不能单独证明内容没有价值。

本次专属日报打开率 60.77%。在完全相同的时间窗口中，直接用打开事件对应邮件数除以送达数会得到 510/724 = 70.44%；其中 70 封是窗口前送达、窗口内被打开的旧邮件。本报告剔除这些旧邮件，统一采用同一批送达邮件作分母。此前较早截止时间的粗算约 70.6%，不应作为 cohort 打开率使用。

## 晚报的发送故障

`email_broadcast_runs` 记录 08-06 至 09-02 共 20 个交易日发送失败。失败原因一致：群发名单存在 `@example.com` 测试地址，被 Resend 拒绝。

09-03 与 09-04 的 2 次任务已记录完成；每次分 Free CTA / Paid CTA 两个广播，共 4 个广播批次，向外部用户合计送达 3,323 封。Resend 的真实批次记录与数据库相符。30 天生成 22 期，而成功发出 2 期，正常广播任务成功率只有 2/22（9.1%）。

这解释了发送量为什么集中在最近两天：不能将旧期间的零送达解释为没有订阅者。23.29% 的晚报打开率主要来自这两次广泛触达，且最新邮件观察时间很短，不能与持续发送给约 40 人的早报直接比较。本次未重发任何历史邮件，也没有修改发送系统。

## 我对优先级的判断

1. 产品核心应围绕“维护关注股票 → 收到有用的专属信息”。已有 39 位月内收件人和 30 位记录到打开的收件人，是目前最贴近新方向的使用证据。若要做真实持仓管理，仍需验证用户愿意录入股数/成本，而不是把 1,065 份自选列表当作真实持仓用户。
2. 日常邮件已经有几十人的稳定交付规模；站内频繁操作的证据较少。现阶段优先保证送达和内容价值，比扩大站内功能更符合已有使用方式。
3. KOL 日报在邮件中相对更能带来点击，但后台处理最重。后续值得讨论降低 enrich 频率、先规则筛选再调用模型、按用户持仓相关性筛选；这是优化方向，本次没有改变它。
4. 晚报先按已经恢复发送后的连续正常周期再评估。历史发送故障与真实阅读意愿需要分开判断。

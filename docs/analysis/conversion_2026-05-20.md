- **试用中但零使用**: 当前试用 139 人里，**49** 人 0 对话且 0 digest（35.3%） —— 这批人按现有趋势几乎必然转不了
- **试用过期未清理的 lapsed row**: 45 人 status='active' 但 access_expires_at 已过 —— webhook 或 cron 异常，影响数据准确性
- **注册后零活动**: 165 (36.6%) —— 注册流程后激活路径有问题

## 9. 核心洞察

**真实数字: 451 个注册中只有 10 人真正付费（2.2%）**。这是非常低的转化率，但要分清三个独立的漏斗失败点：

1. **注册→启动试用流失 139 人 (30.8%)**：注册了但没创建订阅行 —— 要么注册流程后没有触发 trial 自动创建，要么 Stripe 调用失败留下了无 plan 用户。值得先看代码 / 监控这条路径。
2. **试用→付费流失：157/167 失败 = 94.0%**。且 100% 的 cancel 都发生在试用期内（access_expires_at 还在）—— 没有任何用户付费后再取消。
3. **试用期内不激活 = 不转化**：试用期 cancel 的中位生命周期 ~14 天，且 49/139 现在试用中的人是 0 对话 + 0 digest 状态 —— 按当前趋势，他们也会流失。
4. **GIFT2026 几乎没转化（0/44）**：这是预付的礼物码，收的人本身不是自驱选择产品，零转化在意料之中，但说明送码做增长不靠谱。
5. **数据健康问题**：45 个试用过期但 DB 仍是 active，说明 Stripe webhook 或定时清理没正确执行 —— 影响所有「当前活跃用户」指标。

## 10. 建议的下一步动作

1. **优先调查注册→启动试用的 139 人黑洞**：注册了但没 plan。如果是 Stripe 调用失败，修这一条就能立即提升进入试用的总人数；如果是设计上「邀请码注册才送 trial」，那要重新评估默认行为。
2. **试用激活闭环**：当前 139 个试用中用户里 49 人零使用，对这部分人在 day 1 / day 3 / day 7 触发激活提醒（带具体动作建议，比如「先加 3 只自选股」），不是「再读 morning report」这种被动话术。
3. **采访 5-10 个 canceled 且对话 ≤1 的用户**：他们的 cancel 中位发生在 14 天 = 临近自动扣款。直接问 「为什么试用期间没怎么用」「Stripe 提醒邮件到的时候你的第一反应是什么」。
4. **修 webhook / cron**：45 个 lapsed-active row 让所有「活跃用户」指标都偏大；现在公司决策可能基于错误数字。先把数据底层修对。
5. **埋点补全**：当前 `user_activities` 只有 `api_call`，要拆出「打开 morning_report 邮件」「点击 stock 详情」「设置 watchlist」「打开 chat」等真实激活动作，这样下次能定位「第几个动作之后留存率提升」。
6. **缩短试用窗口要看 cancel 时机分布**：当前 5 / 157 在 ≤7 天取消；大部分集中在 8-14 天 = 临近 Stripe 扣款 = 「忘了取消」恐慌 cancel。砍试用长度只会把这个尾部前移，不会增加转化。更可能有效的是把试用从「14 天后自动扣款」改成「14 天后需主动续费」（去掉 sticker shock）。

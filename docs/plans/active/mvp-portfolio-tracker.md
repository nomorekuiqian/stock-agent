# TheMarketBrew MVP：持仓追踪 + 每日推送

> Status: Planning（定位确认于 2026-10-17；第 0 步进行中）
> Supersedes: [restart-2026q4.md](restart-2026q4.md) 中「定位：博主共识地图」及第 1、2 步。该文的**第 0 步（工程归位与度量修复）继续有效**，执行细节以那份文档为准。
> Related: backend/app/features/brew/.context.md、backend/app/features/stock/.context.md、backend/app/features/twitter_digest/.context.md、frontend/src/app/.context.md、wip/2026-09-local 分支上的 `docs/plans/active/portfolio-first-refresh-proposal.md`（9/04 版持仓简报 UI 方案，可复用）

## 定位

**替用户盯着他的持仓和关注股：每天自动告诉他「发生了什么、跟上次比变了什么」，并把新闻、资金面、社交媒体这些分散的信息源聚合到每只股票上。**

- 目标用户：中文区北美美股散户，偏新手，也包括懂技术、会用 AI 工具的人。
- 不做 Agent，也不做一站式投研平台。用户自己的 ChatGPT/Claude 负责「问」，我们负责「盯」和「记」：
  - **盯**：Agent 是无状态的，不会主动去看。我们每天自动检查，有事才推送。
  - **记**：每只股票都有持续累积的档案，所以能算出「变化」。这是一次性搜索做不到的。
- 每份档案同时能被 Agent 读取（提供 Markdown 版本或 MCP 接入），所以资源站的价值作为一个出口自然包含在内，不作为主产品。
- 另一端单独练习增长：在 X 上持续发 AI 和美股内容，从第一天开始，不等产品完工。

> 方向变化记录：9/04 持仓简报 → 10/15 博主共识地图 → 10/17 回到持仓追踪，并把 KOL 观点降为档案里的一个信息源。这次回来的理由：KOL 日报虽然点击率最高，但它是**信息源**，不是用户每天回来的理由；用户的核心任务是「我的股票怎么了」。

## MVP 范围

### 四个对象

```
关注列表 ──生成──▶ 个股档案（每只股票一份，持续累积）
                      ├─ 每天的变化 ──▶ 今日简报（跨所有关注股排序）
                      └─ 重要事件 ────▶ 即时提醒
```

### 页面清单（MVP 只保留这些）

| 页面 | 路由（暂定） | 说明 |
|---|---|---|
| 落地页 | `/` | 一句话：替你盯着持仓。直接放一份真实的简报样例，唯一主 CTA 是「添加你的股票」 |
| 关注列表 | `/watchlist` | 支持粘贴代码、截图识别券商自选股（复用 `holdings_sync` 的截图解析）、热门组合一键添加。提交后立刻能看到档案 |
| 今日简报 | `/today` | 登录后的首页。三档深度：30 秒（3 件事）/ 5 分钟（每只股票一张卡）/ 深度（进入档案）。按重要度排序，没有变化的股票折叠起来 |
| 个股档案 | `/stock/[symbol]` | 核心原子单元，见下一节。对公开访问开放基础版（用于 SEO 和分享） |
| 历史 | `/today/history` | 过去的简报 |
| 定价 / 登录 / 设置 | 现有 | 设置里加推送通道 |

### 个股档案的模块

每个模块都是独立的卡片，以后新增信息源只是多加一张卡。

| 模块 | 变化速度 | 数据来源（现有优先） |
|---|---|---|
| 一句话状态（今天发生了什么） | 快 | 由下面各模块汇总生成 |
| **自你上次查看以来的变化** | 快 | 档案的状态差异（新增能力） |
| 投资逻辑：靠什么赚钱、3 个驱动、3 个风险，带版本记录 | 慢 | fundamentals、earnings，加 LLM 生成，只在有实质变化时更新 |
| 催化剂日历：财报、宏观事件、产品发布 | 中 | `calendar.py`、`earnings.py` |
| 新闻 | 快 | `news.py`（FMP） |
| 资金面 | 中 | 见下一节 |
| 社交媒体：KOL 共识、分歧、代表性观点 | 快 | `twitter_digest`、`kol_research` 现有管线 |
| 关键数字：估值、增长、与同行对比 | 慢 | `valuation.py`、`peers.py` |
| 时间线：每天简报的条目沉淀在这里 | 累积 | 新增 |
| Agent 出口：复制 Markdown、MCP、分享卡片 | — | 现有 MCP，加上新的 Markdown 导出 |

**新增的核心能力只有一个：档案的状态和版本管理。** 每天把各模块的快照存下来，与上一份对比，得出「变化」和「重要度」。简报、提醒、时间线都从这里派生。

### 资金面（MVP 先做一到两个，跑通卡片结构）

| 候选 | 用户能否看懂 | 数据现状 | 建议 |
|---|---|---|---|
| 内部人交易 | 容易 | `fmp_service.get_insider_trading_*` 已有 | **MVP 必做** |
| 机构持仓 / 13F 变化 | 中等 | yfinance 只有持股比例；FMP 13F 需确认当前套餐（$69/月）是否包含 | 先确认数据，季度更新，放在慢变量区 |
| 卖空比例 / 借券利率 | 中等 | 未接入 | 第二批 |
| 期权异动 / Put-Call | 较难 | 未接入，数据源偏贵 | 第二批，先评估成本 |
| ETF 资金流 / 板块资金 | 中等 | 未接入 | 适合放在简报顶部的大盘区块，第二批 |
| 国会议员交易 | 容易，有话题性 | FMP 有接口，需确认 | 适合做 X 内容素材 |

### 推送通道

- 每日简报：网页（PWA，可加到手机桌面），同时推送一条摘要。
- 即时提醒：只推重要事件（异动超过阈值、财报出来了、评级变化、KOL 突然集中讨论），宁少勿多。
- 通道候选：Telegram Bot、微信（现有 `wechat` 模块，推送限制较多）、PWA Web Push。MVP 先做 PWA，再用一个小实验在付费用户里问清楚大家实际用哪个 App，然后只接一个。
- 邮件保留作为兜底通道。现有付费用户在新简报上线前继续收原来的邮件。

## 保留 / 下线清单

**原则**：页面先下线（入口和导航隐藏，路由返回 404 或跳转），后端代码等 MVP 稳定后再删。**付费用户正在收的邮件管线，在替代品上线前不停。**

| 去留 | 前端路由 | 后端模块 |
|---|---|---|
| 保留并重做 | `/`、`/today`、`/stock`、`/pricing`、`/login` 等认证页面、`/settings`、`/profile`、`/unsubscribe` | `brew`（专属日报，改造为简报引擎）、`stock`、`watchlist`（`shared/user_watchlists`）、`notification`、`payment`、`subscription`、`quota`、`flags`、`webhooks`、`admin` |
| 并入档案或简报 | `/morning`、`/kol`、`/twitter-digest`、`/macro` | `morning_report`、`daily_report`、`twitter_digest`、`kol_research`、`macro`（作为信息源保留，不再作为独立页面） |
| 待定 | `/research`（付费权益 AI 研究对话）、`/mcp` | `screener`（research agent）、`okx_mcp` |
| 下线 | `/for-you`、`/frank-agent`、`/qinbafrank`、`/panda`、`/feedback`（并入设置）、`/request-access`、`/dev`、`/email-test` | `watchlist_monitor`、`portfolio_health`、`research_kb`、`onboarding`、`community_access`、`zsxq_ingest`、`agent_runtime`、`memory`、`for_you` |
| 复用其中的能力 | — | `holdings_sync`（截图识别）、`portfolio`（持仓权重） |

具体到每个文件的删除，在第 2 步执行前再逐项确认。

## SOP

| 步骤 | 内容 | 完成标准 |
|---|---|---|
| 0 | 工程归位与度量修复（见 [restart-2026q4.md](restart-2026q4.md) 第 0 步） | 仓库能复现线上；只从 git 发布；能回答「这周的注册从哪来」 |
| 1 | 定 MVP 范围（即本文） | 用户确认保留/下线清单和模块清单 |
| 2 | 砍：页面下线，导航收敛为「今日 / 关注 / 历史」 | 线上只剩 MVP 页面；付费邮件不受影响 |
| 3 | 设计系统，加上 5 个核心页面的重设计 | 设计 token 统一；落地页、关注列表、今日、档案、定价都完成高保真稿并上线 |
| 4 | 简报引擎重做：档案快照、变化计算、重要度排序、内部人交易卡片 | 每天自动为所有关注股生成档案，变化正确，简报按重要度排序 |
| 5 | 推送：PWA 加一个外部通道；老邮件用户迁移到新简报 | 用户可以选择通道；原来的早报和专属日报由新简报替代 |
| 6 | 系统化增长：内容 Agent、SEO 档案页、漏斗周报 | 每周能按来源看到注册和留存 |

**并行**：从第 0 步开始就在 X 上发内容（重做进展、每天的档案截图），全部带 UTM。

## 衡量标准（初始，待确认）

- 激活：注册后 24 小时内添加 ≥3 只股票的比例。
- 留存：每周至少打开 3 次简报的人数（取代邮件打开率作为北极星指标）。
- 推送：提醒的点击率，以及关闭通知的比例。
- 获客：X 和 SEO 带来的注册，能否稳定超过约 5–10 人/天的自然基线。

## 待定问题

1. 推送通道选哪个？需要问付费用户。
2. `/research`（AI 研究对话）还要不要作为付费权益保留？它是 6 月数据里用得最多的功能（548 人），但跟「不做 Agent」的方向冲突。
3. 免费层和付费层怎么切？候选方案：免费 5 只股票、只有每日简报；付费不限数量，加即时提醒、资金面和社交媒体模块。
4. 公开档案页（未登录可看）开放多少内容？开放越多越利于 SEO，但会削弱付费动机。
5. 13F、期权异动的数据成本，是否值得为 MVP 升级 FMP 套餐。

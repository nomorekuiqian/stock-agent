## 当前基建评估

### 知识库层 — 70%

| 已有 | 数据源 |
|------|--------|
| 市场实时数据 | yfinance + FMP |
| 财经新闻 | FMP 3 个 API |
| 经济日历 / 财报日历 | FMP |
| 技术分析 | tvscreener + pandas-ta（30+ 指标） |
| 宏观流动性 | FRED 7 个系列 |
| 宏观风险 | FRED 30+ 指标，4 维度评分 |
| 个股财务 | OpenBB + FMP + yfinance |
| 三级缓存 | Memory -> DB -> API |

**缺失**: 历史事件库、用户画像、社交情绪、跨分析记忆

### Skills 层 — 30%

| 已有 | 能力 |
|------|------|
| Market Agent | 市场日报（叙事连续性） |
| Stock Agent | 基本面 7 段 + 技术面分析 |
| Weekly Report Agent | 4 维风险 + 投资建议 |
| Sector Agent | 12 板块日报 |
| Digest Agent | 按 watchlist 个性化摘要 |

**缺失**: 组合诊断、多视角辩论、用户画像驱动、风险预警、反馈闭环

### CRON 层 — 40%

| 已有 | 频率 |
|------|------|
| 日报邮件 | 每日 |
| 专属摘要邮件 | 每日 |
| 欢迎邮件 | 一次性 |

**缺失**: 实时预警推送、周报邮件分发、多渠道分发 (Telegram)

## 技术决策记录

### 为什么不直接集成 TradingAgents

1. 架构不兼容（LangGraph vs Google ADK）
2. 数据层比我们粗糙，集成后反而降级
3. 产品定位不同（交易工具 vs 投研平台）
4. 借鉴架构思路（多空辩论、记忆系统）比直接集成更有价值

### 推送渠道优先级

| 渠道 | 优先级 | 理由 |
|------|--------|------|
| 邮件 (Resend) | 已有 | 基础设施已完成 |
| Telegram Bot | P1 | 技术门槛低、海外用户主力 |
| 微信服务号 | P2 | 国内用户需求，审批流程长 |
| 移动端推送 | P3 | 需要先有 App |

### 数据边界

- 不依赖付费券商 API (Plaid 等)，用户手动提供持仓
- 不触碰用户真实账户数据，只使用用户主动提供的 ticker 列表
- Digest Agent 继续使用 Gemini Flash，单次成本 < $0.03

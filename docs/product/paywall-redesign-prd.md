# 产品需求文档 (PRD): TheMarketBrew 渐进式 Paywall 与会员体系重构

**文档状态**: Draft
**日期**: 2026-04-15
**目标受众**: 产品经理、UI/UX 设计师、全栈工程师

---

## 1. 背景与目标 (Background & Objective)

### 1.1 当前痛点诊断
目前的 Paywall 策略是**整页拦截（Hard Block）**。免费用户登录后，点击 `/stock`、`/macro`、`/for-you` 等核心页面会直接遇到 `PaywallGuard` 的 LockScreen。
- **破坏投资心流**：用户无法感知产品 UI 质感和 AI Agent 的实际工作能力。
- **“橱窗效应”失效**：未能利用系统本身作为转化工具，过度依赖外部邮件转化。
- **缺乏价值锚点**：用户在未体验具体功能解决什么问题时，面对空洞的付费弹窗，转化率容易遇到瓶颈。

### 1.2 重构目标
将 Paywall 从“一刀切”转向**“渐进式解锁 (Progressive Unlocking)”** 与 **“基于用量 (Usage-based)”** 的混合模式。
- **提升免费用户粘性**：让产品对免费用户有吸引力，培养每日打卡习惯。
- **优化转化漏斗**：通过“试探性体验”和“认知饥渴”自然激发用户的付费意愿。
- **明确阶梯价值**：清晰界定 Pro 与 Max 的核心差异，推动用户向上升舱。

## 2. 核心理念与心智模型 (Core Philosophy)

在投资场景中，用户的需求层次分为：**数据 (Data) -> 资讯 (Information) -> 智能/洞察 (Intelligence)**。

基于此漏斗，我们重新定义用户分层的核心投资心智：

| 用户层级 | 投资心智定位 | 核心价值交付 | 权限范围 |
| :--- | :--- | :--- | :--- |
| **Free (免费)** | **入局与习惯养成** | 提供“基础数据”和“表层信息”。作为吸引用户的橱窗。 | 基础图表、表层结论、限量自选股、**体验额度(Teaser)** |
| **Pro ($9.99/月)** | **Information (信息聚合与效率)** | 告诉用户“世界发生了什么”。消除信息噪音，省时间。 | 完整历史数据、个性化信息流、异动推送盯盘 |
| **Max ($9.99/月)** | **Execution & Decision Making (辅助决策)** | 告诉用户“这对我意味着什么”及“我该怎么做”。降维打击。 | AI 深度归因、交易剧本/备忘录、压力测试、无限 AI |

## 4. 高价值新增 Feature 提议 (High-Value Features) - [P2 优先级]

> **执行优先级说明**：
> - **P0 核心任务**：首先改造现有的 Paywall（即本文档第 3、5 节所列的渐进式解锁与 FeatureGuard），让现有的核心功能对免费和 Pro 用户体验更平滑，避免过度拦截，同时用优雅的高斯模糊和体验额度等机制自然地吸引用户付费升舱。
> - **P2 增量任务**：本节所列的新增 Feature 暂时不强制要求立刻实现，可作为第二阶段提升各 Tier 价值的储备库。

为支撑 Pro 和 Max 的心智定位，建议在未来补充以下轻量级高价值功能：

### 🚀 Pro 级新增：强化 Information 效率
1. **个性化异动盯盘推送 (Portfolio Alerts)**:
   - **机制**: 后端 Cron Job 监控用户的 Watchlist，日内波动 > 5% 或发布财报时，通过邮件/App 内推送通知。
   - **价值**: "信息找人"，省去用户盯盘时间。
2. **多空情绪温度计 (News Sentiment Bar)**:
   - **机制**: 用轻量模型 (Gemini Flash) 批量打标当日个股新闻，前端渲染红绿进度条展示整体情绪。
   - **价值**: 将长文本资讯高度可视化。

### 👑 Max 级新增：强化 Decision Making 辅助
1. **AI 交易备忘录生成器 (Trade Thesis Generator)**:
   - **机制**: 结合“个股分析缓存 + 宏观环境 + 用户持仓”，生成结构化的《交易计划》(入场逻辑、止损参考、目标价)。
   - **价值**: 直接赋能 Execution，提供可执行的剧本草稿。
2. **持仓压力测试 (Portfolio Stress Test)**:
   - **机制**: 在 `/for-you` 页面，用户设定假设场景（如“CPI 超预期”），AI 评估 Watchlist 中各股票的脆弱性排名。
   - **价值**: 机构级别的风控视角辅助。

## 5. 交互与 UI 执行细节 (Execution & UI Mockups)

### 5.1 组件级拦截 (`FeatureGuard`)
废弃部分整页级的 `PaywallGuard`，开发 `FeatureGuard` 包裹具体区块。
- **未解锁状态渲染**: 后端返回基础数据，高阶数据返回 `null`。前端渲染**高斯模糊 (Gaussian Blur)** 的占位骨架屏。

#### UI Mockup: 模糊占位态 (Blurred State)
```text
[ 个股详情页 - AAPL ]
------------------------------------------------------
💰 当前价格: $173.50 ( -2.1% )
🤖 AI 评级: 🔴 短期偏空

[ 深度做空逻辑与催化剂分析 ]
|----------------------------------------------------|
|  ( 背景文字被严重模糊，隐约可见长篇段落排版 )            |
|                                                    |
|         ✨ 解锁 AI 分析师的 1500 字深度做空逻辑         |
|      [ 💎 升级到 Max ]  或  [ 🎁 使用免费 AI 额度 (2/2) ] |
|                                                    |
|----------------------------------------------------|
```

### 5.2 免费额度机制 (Usage-based Quotas)
- **后端支持**: 无需引入 Redis 等新依赖，直接在现有数据库（如 InsForge / PostgreSQL）中新建一张轻量级的 `user_quotas` 表，记录 `user_id`、`feature_name` 和 `used_count`。由于初期并发量不高，数据库完全能胜任这种轻量级的额度扣减。
- **前端展现**: 按钮旁显示剩余次数。耗尽后弹出转化 Paywall："您已体验 AI 深度决策辅助，升级 Max 获取无限次权限并在极端行情中保护利润。"

## 6. User Stories (转化场景推演)

- **The Hooked User (被额度吸引的小白)**：看大盘跌了，用免费额度解锁了一次深度做空逻辑，根据支撑位操作赚了钱。几天后额度耗尽，为了在动荡行情中获得持续的交易指导，直接跨过 Pro 订阅 **Max**。
- **The Efficient Reader (讲求效率的中产)**：每天看免费早报，把 5 只股票加入 Watchlist。收到系统提示“升级 Pro 盘中异动自动推送”。因为不想每天主动刷新闻，为了“信息找人”订阅了 **Pro**。
- **The Level-Up Trader (认知升级的老手)**：作为 Pro 用户，看到宏观流动性紧缩，但不知道对自己持仓的影响（被 Max 专属的“压力测试”功能模糊拦截）。为了消除“知道会跌但不知道该卖谁”的 FOMO 焦虑，补差价升舱至 **Max**。

## 7. 成功衡量指标 (Success Metrics)

1. **转化率提升**: 免费 -> Pro 的转化率 (追踪 `/pricing` 页面来自各种局部 `FeatureGuard` 按钮的转化归因)。
2. **体验额度使用率**: 免费用户对 2 次 AI 体验额度的激活和耗尽比例。
3. **升舱率**: Pro -> Max 的转化率 (验证 Decision Making 功能的吸引力)。
4. **留存与日活**: 免费用户在网站的平均停留时间 (Time on Site) 与次日留存率 (由于不再是直接弹窗拒之门外，应有显著提升)。�

## 附录：真实的 UI Mockup 生成与联调方案

在后续的开发执行中，为了不依赖复杂的 Figma 等设计软件并加速开发，我们将采取“本地组件级 Mock”的策略：

1. **直接生成可运行的 React / Tailwind 组件**：
   - 依赖项目已有的 `shadcn/ui` 组件库与 Tailwind 颜色主题 (如 `primary`, `amber-400` 等)。
   - 使用 AI 结合当前的字体库 (如 `font-editorial`, `font-data`) 以及设计规范，直接在代码库中生成隔离的 Mock 组件（例如 `frontend/src/components/mockups/FeatureGuardMockup.tsx`）。
2. **使用真实数据结构 (Data Schema)**：
   - 使用真实的 Mock 数据渲染这些组件（例如：含有支撑位、阻力位、胜率等真实字段的假 JSON 数据），以确保排版在真实内容下依然合理。
3. **本地开发服务器联调**：
   - 将生成的 Mock 组件临时挂载到一个供内部预览的路由或测试页下。
   - 启动本地开发服务器 (`npm run dev`)，在浏览器中直观感受高斯模糊、按钮交互及响应式布局等细节，满意后再将其接入真实的业务逻辑中。

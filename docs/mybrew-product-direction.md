## North Star

**让每一个普通投资者都拥有一个 24 小时在线的 AI 投研搭档——它了解你的持仓、理解你的风格、替你盯盘、替你研究、在该提醒时提醒你、在不该打扰时保持安静。**

MyBrew 不是一个 Dashboard，不是一个新闻聚合器，也不是一个交易工具。它是一个**主动型 AI Agent**——陪伴用户的投资旅程，保护用户的持仓安全。

### 产品愿景的三次跃迁

```
现在                     近期                        未来
专属日报                  AI 投资助手                  个人投研 Agent
Personalized Digest  →   MyBrew Copilot           →  MyBrew Agent

"按你的股票筛选新闻"      "告诉你该关注什么、          "替你执行研究流程、
                         该怎么做"                   持续学习你的偏好、
                                                    越用越懂你"
```

### 一句话定位

**Market Daily 让你看懂市场，MyBrew 帮你做出决策。**

| | Market Daily (免费日报) | MyBrew (AI投资助手) |
|---|---|---|
| 回答的问题 | "今天市场发生了什么？" | "这对我的钱意味着什么？我该怎么办？" |
| 输出风格 | 信息摘要、教育解读 | 决策建议、风险预警、行动信号 |
| 个性化 | 无（所有人相同） | 深度个性化（持仓、风格、框架） |
| Agent 行为 | 被动生成、定时推送 | 主动监控、事件驱动、智能沉默 |
| 商业定位 | 获客入口、品牌 | 付费核心、留存引擎 |

## 用户洞察

来自用户访谈的关键发现：

1. 用户大多是被动或轻度主动投资者，投资组合以指数基金 + 科技股 + RSU 为主
2. 标准日报订阅率不错，但专属日报 onboard 率低
3. 付费意愿不强——不是不愿花钱，而是当前个性化功能的感知价值不够高
4. 根本原因：onboarding 门槛高（手动逐个添加股票），但回报不够明显（只是按股票筛选了新闻）

**核心假设**：北美科技大厂员工（被动/轻度主动投资者）愿意为"零摩擦的个性化投资情报"付费，前提是价值感足够强，且不要求他们成为主动投资者。

## 设计原则

1. **顺应行为，不改变行为** — 不要试图把被动投资者变成主动投资者。被动用户用预设模板，主动用户可深度自定义，两者共存
2. **零摩擦个性化** — 用户提供最少信息即可获得个性化服务。个性化的门槛渐进式递增：一键选模板 → 简单问卷 → 高级自定义
3. **AI 主动服务，用户被动接收** — 不是给用户工具让他们研究，而是 AI 替他们研究好了送到面前
4. **沉默即信号** — 没有异常不推送，本身就是最有价值的服务。"你的持仓今天一切正常"就是安心感。这条原则约束预警系统：推得准比推得多重要
5. **日报走邮件，预警走即时** — 每日摘要通过邮件推送（深度阅读场景）；异常预警通过 Telegram 等即时渠道推送（时效性场景）
6. **系统会进化** — Agent 追踪自己建议的准确率，持续调优，越用越聪明

## 产品架构

### 两个场景，一套系统

| 场景 | 核心问题 | 数据源 | 更新频率 | 触达渠道 |
|------|---------|--------|---------|---------|
| **我的持仓** (防守) | "我的钱还好吗？" | 用户实际持有的股票 | 每日 + 异常触发 | 邮件 + 即时预警 |
| **我的关注列表** (进攻) | "该出手了吗？" | 用户感兴趣但未持有的股票 | 事件驱动 | 邮件（关注列表板块仅在有事件时出现） |

### 关注列表事件触发条件

没有触发事件的日子，关注列表板块不出现。这降低了噪音，也让每次出现都更有价值。

- 股价大幅波动 (日涨跌 > 3%)
- 财报临近 (7 天内)
- 分析师评级变动
- 到达关键技术价位
- 重大新闻/事件

## 里程碑

从当前的"专属日报"到未来的"AI 投资助手"，需要依次完成系统能力的升级。每个里程碑独立交付价值，不依赖后续里程碑。

### M0: 专属日报价值升级 — 让 Agent 真正有用 (当前优先)

> **核心问题**：日报除了"替你读新闻"，还能创造什么价值？
>
> **完成标志**：用户打开日报后觉得"这个 AI 真的在帮我思考"，而不只是"帮我整理了新闻"。

#### 为什么优先

M1-M5 都是系统能力的扩展，但当前日报本身的**内容价值**尚未最大化。在增加新功能之前，应先把核心产品做到位。M0 的实现成本极低（纯 prompt 层面改动），但能显著提升用户感知价值。

#### 日报价值的三层模型

```
Layer 3: 替你连线 (Connect Dots)     ← 完全缺失，最大增量
         跨持仓关联、集中度风险、板块联动

Layer 2: 替你判断 (Judge for You)     ← 当前薄弱，核心提升点
         噪音 vs 信号判断、是否需要关注

Layer 1: 替你读 (Read for You)        ← 已做得不错
         压缩信息获取时间、新闻摘要
```

**Layer 1: 替你读** — 当前已经做得不错。用户不用自己翻 10 个新闻源，日报帮他们压缩信息获取时间。

**Layer 2: 替你判断** — 当前最大的提升空间。日报应该对每条新闻/每个异动做出"噪音 vs 信号"的判断：
- 这条新闻对你的持仓**有没有实质影响**？
- 这个下跌是**正常波动**还是**需要关注的信号**？
- 用一句话告诉用户：要不要在意这件事？

示例对比：
```
❌ 当前: "NVDA 下跌 3.2%，受 AI 芯片出口限制消息影响"
✅ 升级: "NVDA 下跌 3.2%，受出口限制消息影响。但这是市场对旧消息的过度反应
         ——实际限制范围远小于预期，对 NVDA 数据中心业务影响有限。
         噪音概率高，无需操作。"
```

**Layer 3: 替你连线** — 完全缺失的能力。当用户同时持有多只股票时，单看个股分析是碎片化的。日报应该帮用户发现跨持仓的关联：
- **集中度风险**: "你的 5 只股票中有 4 只高度依赖 AI 叙事，实质上是同一个赌注"
- **板块联动**: "今天半导体板块整体下跌，你持有的 NVDA/AMD/TSM 同时受影响，这不是个股问题"
- **对冲盲区**: "你的组合缺少防御性资产，在市场回调时没有缓冲"
- **相关性警告**: "GOOGL 和 META 走势高度相关，持有两只等于加倍同一方向"

#### 需要做的事

**1. 升级 Digest Agent Prompt — 注入判断框架**

在 Agent 的 instruction 中加入信号判断规则：
- 对每条新闻标注: `信号` (影响基本面/估值逻辑) vs `噪音` (短期情绪/旧消息炒作)
- 对每个异动标注: `正常波动` vs `需关注` (附理由)
- quick_take 从"发生了什么"升级为"要不要在意 + 为什么"

**2. 升级 Digest Agent Prompt — 注入连线分析**

在 Agent 的 instruction 中要求：
- 分析用户持仓之间的相关性（板块集中度、主题重叠）
- 当多只股票受同一因素驱动时，指出共因而非逐个分析
- 在 summary 中给出组合层面的判断，而非仅个股加总

**3. 调整 Output Schema (小幅)**

- StockSummary 的 `quick_take` 字段：从纯描述升级为"判断 + 理由"格式
- Summary 新增组合层面的 cross-holding 分析段落
- 无需新增独立字段，利用现有结构即可

#### 关键决策

| 决策 | 结论 | 理由 |
|------|------|------|
| 日报是否加入 PE/PS 等估值指标？ | **否** | 估值指标日变化极小，不适合日报场景。深度估值分析放在网站端 |
| 日报是否加入技术面指标？ | **否** | 同上，技术分析是网站端功能 |
| 日报是否加入"组合速览"卡片？ | **否** | 用户可从券商 App 看到，日报不需重复 |
| 是否区分"实仓"和"关注列表"？ | **暂不区分** | 增加 onboarding 摩擦，且核心改进不依赖此区分。推迟到 M2 onboarding 中通过模板自动分类 |
| 实现方式？ | **纯 Prompt 改动** | 不需要新增数据源、不需要新增 API 调用、不需要修改数据模型。成本最低、风险最低 |

#### 技术路径

- 修改 `digest/agent.py` 中的 `DIGEST_INSTRUCTION` prompt
- 注入信号判断框架和连线分析要求
- 可能微调 `models.py` 中 Summary 的 description/example
- 预计工作量: 1-2 天

### M1: 历史 Context — 让 Agent 拥有记忆

> **核心问题**：Agent 知道历史上发生过什么吗？
>
> **完成标志**：当市场出现异常信号时，Agent 能自动输出"当前环境与历史上 X 时期高度相似"。

#### 为什么重要

当前系统每次分析都是"无状态"的。Agent 不知道 2022 年加息周期长什么样，不知道 2020 年疫情崩盘后多久恢复，不知道日元套利平仓会引发什么连锁反应。没有历史记忆的 Agent 只能描述当下，无法判断未来。

#### 需要做的事

**1. 建立结构化历史事件库**

收录对市场有重大影响的历史事件，每个事件包含：
- 时间线 (起止日期、关键节点)
- 触发条件 (哪些指标先异动)
- 市场反应 (各类资产的表现)
- 恢复路径 (多久恢复、什么条件下恢复)

初期事件库：
| 事件 | 时间 | 核心特征 |
|------|------|---------|
| 2008 金融危机 | 2007.10 - 2009.03 | 信用违约 → 流动性枯竭 → 系统性崩盘 |
| 2018 年末暴跌 | 2018.10 - 2018.12 | 加息过快 + 贸易战 → 估值压缩 |
| 2020 疫情崩盘 | 2020.02 - 2020.03 | 外部冲击 → 流动性危机 → 史上最快熊市 |
| 2022 加息周期 | 2022.01 - 2022.10 | 通胀 → 激进加息 → 成长股估值重估 |
| 2022.08 日元套利平仓 | 2022.08 | 日元急升 → 套利平仓 → 全球风险资产联动下跌 |
| 2023 银行业危机 | 2023.03 | 利率风险 → SVB/Signature 倒闭 → 区域银行恐慌 |
| 2024 日元 Carry Trade 平仓 | 2024.08 | 日央加息 → 套利逆转 → 全球闪崩 |

**2. 模式匹配引擎**

当宏观指标出现异常时，自动将当前信号组合与历史事件的触发条件做相似度匹配：
- 输入：当前异常的指标组合 (来自 macro_risk + liquidity 模块)
- 处理：与历史事件库的触发条件做向量/规则匹配
- 输出："当前流动性收紧信号与 2022.08 日元套利平仓前的模式相似度 78%"

**3. 情绪管理语境 (快速实现)**

在市场大跌日 (>2%)，MyBrew 在日报顶部自动插入历史语境：
- "标普自 2000 年以来经历过 47 次类似跌幅，平均 18 个交易日恢复"
- "你的组合年初至今仍 +X%"
- 防止被动投资者在恐慌中做出错误决策

#### 技术路径

- 事件库初期用结构化 JSON/Markdown 存储，喂入 Agent prompt
- 匹配引擎初期用规则系统（指标阈值组合），后期可升级为向量相似度
- 情绪语境可直接复用已有 macro_risk 历史数据

### M2: 个性化 Skills — 让 Agent 理解你

> **核心问题**：Agent 知道这个用户的投资逻辑吗？
>
> **完成标志**：同一条市场新闻，价值投资者和趋势交易者看到不同的解读和建议。

#### 为什么重要

当前的个性化仅限于"你持有哪些股票"。但两个都持有 NVDA 的人，一个可能是长期价值持有，另一个可能是短线趋势交易。同一条新闻（"英伟达下调指引"），前者需要听到"基本面是否改变"，后者需要听到"技术面支撑位在哪"。不理解用户的投资逻辑，Agent 就只能给出通用建议。

#### 需要做的事

**1. 渐进式用户画像收集**

遵循"零摩擦个性化"原则，分三级收集：

| 级别 | 触发时机 | 收集内容 | 用户成本 |
|------|---------|---------|---------|
| L1 模板选择 | Onboarding | 持仓模板 ("我在Google"/"芯片赛道"/...) | 1次点击 |
| L2 快速问卷 | 使用1周后 | 投资风格（保守/均衡/积极）、关注维度（基本面/技术面/宏观）、风险容忍度 | 3个问题，30秒 |
| L3 自定义规则 | 主动开启 | 自定义选股标准、预警阈值、板块权重偏好 | 高级用户自助配置 |

大部分用户停留在 L1-L2 即可获得良好体验。L3 为少数高级用户提供。

**2. Onboarding 模板**

预设投资组合模板，一键完成设置：
- "科技大厂员工" → AAPL, MSFT, GOOGL, AMZN, META, NVDA + SPY/QQQ
- "芯片赛道" → NVDA, AMD, TSM, AVGO, QCOM, MU...
- "中概股" → BABA, PDD, JD, BIDU, NIO...
- "指数基金为主" → SPY, QQQ, VTI, VXUS, BND
- "我在 [Google/Apple/Meta...]" → 公司 RSU + 科技大盘

选完模板后立刻展示「今天的 MyBrew 预览」→ 即时价值感。

**3. 持仓 vs 关注列表分离**

在 Onboarding 中区分：你持有的 / 你感兴趣的。数据模型：`user_watchlists` 表增加 `list_type` 字段 (`holding` / `watching`)。两者的推送逻辑不同（见产品架构部分）。

> **注**: M0 阶段暂不做此区分（增加 onboarding 摩擦，且日报核心改进不依赖此区分）。M2 阶段通过 onboarding 模板自动分类，用户选"我在 Google"→系统自动将 GOOGL 标为 holding，其余为 watching。

**4. 用户画像驱动 Agent 行为**

基于用户画像调整 Agent 的分析角度和建议风格：

| 用户画像 | Agent 行为调整 |
|---------|-------------|
| 保守型 / 被动投资者 | 侧重风险提示、历史对比、"无需操作"信号 |
| 均衡型 | 平衡风险与机会、给出概率性建议 |
| 积极型 / 主动投资者 | 侧重技术面信号、仓位建议、买卖时机 |
| 关注基本面 | 财报解读权重高、估值对比突出 |
| 关注宏观 | 流动性/利率影响翻译层优先 |

#### 技术路径

- L1/L2 画像存储在 Insforge `user_profiles` 表
- 画像信息作为 context 注入 Digest Agent 的 prompt
- 不同风格对应不同的 prompt 模板（或 system instruction 中的条件分支）

### M3: 信息→决策升级 — 让 Agent 告诉你该怎么做

> **核心问题**：Agent 能给出可执行的投资建议吗？
>
> **完成标志**：用户打开 MyBrew 后，30秒内知道今天是否需要操作、操作什么。

#### 为什么重要

当前专属日报的输出是叙述性的——"NVDA 下跌 3%，受 AI 芯片出口限制消息影响"。用户看完之后的反应是："所以呢？我该怎么办？" 从"信息"到"决策"的最后一步，目前由用户自己完成。MyBrew 应该帮用户完成这一步。

#### 需要做的事

**1. 每日策略输出**

在 MyBrew 日报中新增"今日策略"板块：

```
-- 今日策略 --

整体判断：维持现有仓位，无需操作
信心度：高 (宏观环境稳定、持仓无异常)

需要关注：
- NVDA 周五财报，建议关注 AI 芯片订单指引
- 如果盘后指引低于预期，考虑评估仓位

下一个关键节点：
- 2/25 NVDA 财报
- 3/7 非农就业数据
```

大多数交易日的策略是"无需操作"——这本身就是价值（设计原则4："沉默即信号"）。

**2. 宏观翻译层**

把通用的宏观事件翻译为对用户个人持仓的含义：
- 通用："美联储维持利率不变"
- MyBrew："对你的持仓影响中性——你的组合以科技股为主，利率不变意味着估值压力不会增加。继续持有。"

**3. 持仓归因分析**

不只告诉用户"今天涨/跌了"，还要告诉"为什么"：
- 组合今日 -1.2% (vs SPY -0.8%)
- 主要拖累：NVDA -4.5% (贡献 -0.9%)，受芯片出口限制消息影响
- 亮点：AAPL +1.2%，服务收入超预期

**4. 关注列表机会信号**

当关注列表中的股票触发事件时，给出更具体的分析：
- "AMD 回调至 $145，接近你上次关注的价位区间 ($140-150)"
- "TSM 财报超预期，上调全年指引。当前估值处于近1年中位数水平"

#### 技术路径

- 升级 Digest Agent 的 output schema，新增 `daily_strategy`、`portfolio_attribution`、`action_items` 字段
- 宏观翻译层：在 prompt 中注入当日 macro_risk 关键变化 + 用户持仓特征
- 信心度：基于宏观风险评分 + 持仓波动率综合计算

### M4: 预警系统 — 让 Agent 主动保护你

> **核心问题**：Agent 能在风险来临时第一时间通知你吗？
>
> **完成标志**：用户不打开 App/邮件，也能在关键时刻收到 Agent 的提醒。

#### 为什么重要

日报是"一天一次"的节奏。但市场风险不会等到第二天早上才发生。如果 VIX 突然飙升、用户持仓的某只股票盘后暴跌 10%、或者流动性指标出现异常信号，用户需要**立即知道**——而不是明天邮件里才看到。

预警系统是 MyBrew 从"日报产品"升级为"主动 Agent"的关键分水岭。

#### 需要做的事

**1. 定义预警触发规则**

基于已有的 macro_risk + liquidity 数据，设定阈值：

| 类型 | 触发条件 | 预警等级 | 说明 |
|------|---------|---------|------|
| 宏观风险 | 综合评分 > 7 (红色区间) | 高 | 整体宏观环境恶化 |
| 流动性 | 净流动性单周下降 > 5% | 高 | 市场资金面收紧 |
| 波动率 | VIX > 30 | 中 | 市场恐慌情绪升温 |
| 利率 | SOFR 单周变化 > 0.5% | 中 | 资金成本异常波动 |
| 持仓异常 | 用户持仓个股单日跌幅 > 5% | 高 | 个股异常波动 |
| 财报提醒 | 用户持仓个股财报发布前1天 | 低 | 重要时间节点 |

用户可以在 L3 自定义模式下调整这些阈值。

**2. 预警内容生成**

预警不只是一条通知，而是一条**有 context 的分析**：

```
[MyBrew 预警] VIX 突破 30

当前 VIX: 32.4 (+28% 日内)
触发原因: 市场对 [事件] 的恐慌反应

对你的持仓影响:
- 你的组合以科技股为主，科技股对 VIX 飙升最敏感
- 历史上 VIX > 30 后，标普平均 22 个交易日恢复

建议:
- 暂不恐慌性卖出 (历史上这个水平大多是短期超调)
- 如果持续 3 天 VIX > 30，考虑减少杠杆/降低集中度
```

**3. 实时推送渠道**

Telegram Bot 作为第一个即时推送渠道（技术门槛低、海外用户主力）：
- 用户在 MyBrew 设置页绑定 Telegram
- 预警触发时通过 Bot 即时推送
- 日报仍走邮件（深度阅读场景不变）

**4. 监控调度器**

后端新增定时监控任务：
- 每 30 分钟检查宏观指标阈值
- 每 5 分钟检查用户持仓个股异常波动（盘中）
- 财报提醒：每日上午检查 T+1 的财报日历

#### 技术路径

- 新建 `features/alert/` 模块（monitor + rules + sender）
- 复用 macro_risk + liquidity 现有数据（加一层阈值判断）
- Telegram Bot 用 python-telegram-bot 库
- 监控调度器用 APScheduler 或外部 Cron

### M5: 反馈闭环 — 让 Agent 越来越聪明

> **核心问题**：Agent 能从自己的表现中学习吗？
>
> **完成标志**：用户能看到"MyBrew 过去 30 天建议准确率 72%"，且这个数字在持续上升。

#### 为什么重要

没有反馈闭环的 Agent 永远不会比第一天更聪明。它可能这周建议"减仓科技股"是对的，下周建议"加仓能源"是错的——但它不知道。M1-M4 让系统**能用**，M5 让系统**越用越好**。

这也是用户信任的基础：当 Agent 能展示自己的历史战绩，用户才愿意真正跟随建议行动。

#### 需要做的事

**1. 建议追踪系统**

记录每条决策建议，追踪后续结果：

| 记录字段 | 说明 |
|---------|------|
| `advice_date` | 建议日期 |
| `advice_type` | 类型 (调仓/预警/持有/关注) |
| `advice_content` | 建议内容摘要 |
| `target_symbols` | 涉及标的 |
| `market_context` | 当时的宏观环境快照 |
| `outcome_7d` | 7天后结果 |
| `outcome_30d` | 30天后结果 |
| `accuracy_score` | 准确性评分 |

**2. 用户反馈收集**

在每条建议下方增加简单的反馈机制：
- "这条建议有用吗？" [有用] [一般] [没用]
- 比当前 feedback 模块（只收集对报告整体的满意度）更精细
- 反馈数据与建议追踪数据合并分析

**3. 准确率看板**

在 Portfolio Dashboard 中展示：
- 过去 30/60/90 天的建议准确率
- 按建议类型分类的表现（预警准确率、调仓建议收益率等）
- 趋势图：准确率是否在提升

**4. Agent 自我调优**

基于追踪数据调整 Agent 行为：
- 哪类信号的预警准确率高 → 提升该信号的权重
- 哪类建议用户反馈"没用"多 → 调低该类建议的频率
- 哪些宏观指标组合对用户持仓最有预测力 → 强化关注

#### 技术路径

- 新建 `advice_tracking` 表存储建议记录
- 定时任务：每天回填 T-7、T-30 的市场数据，计算历史建议结果
- 调优逻辑初期用规则（权重调整），后期可接入更复杂的学习机制
- 准确率数据展示在 Portfolio Dashboard 中

## 网站端：AI 持仓深度分析

邮件日报承载"快速概览"，网站端承载"深度分析"。两者形成自然动线：**日报看概览 → 网站看深度**。

### 当前网站能力与缺口

| 已有 | 缺失 |
|------|------|
| `/stock/[symbol]` 个股页：资料 + 报价 + 财务 + 估值对比 + AI 基本面(7段) + AI 技术面(4段) | 个股分析是**孤立的**，不考虑用户持仓背景和宏观环境 |
| `/macro` 宏观仪表盘：风险评分 + 流动性 + 利率 + 情绪 | 宏观数据与个股分析**断裂**，用户需自行关联 |
| `/for-you` 自选股管理 + StockCard 网格 | 只是一个列表，没有**组合层面的分析** |
| 邮件日报有个股摘要 | 邮件→网站没有**深度衔接链路** |

核心问题：**三层分析（基本面、技术面、宏观）各自独立，缺少以用户持仓为中心的融合视角。**

### 方向 1: 组合视角 — `/for-you` 升级

当前 `/for-you` 只是 StockCard 列表。升级为组合分析视角：

**组合健康诊断**（只需 ticker 列表，不需要持仓成本和数量）:
- **板块集中度**: 持仓在哪些板块？集中度是否过高？
- **风格因子**: 成长 vs 价值？大盘 vs 中小盘？
- **相关性矩阵**: 哪些股票走势高度相关（实质是同一个赌注）？
- **宏观敏感度**: 组合对利率/通胀/流动性变化的敏感度如何？

这个方向的价值：用户单看个股觉得"都挺好"，但组合视角能揭示隐藏风险（"你以为分散了，其实都押在 AI 上"）。

### 方向 2: 个股分析升级 — 注入宏观 + 组合语境

当前 AI 基本面分析和技术分析是独立生成的。升级后应注入上下文：

- **宏观关联**: "当前利率环境对 NVDA 估值意味着什么？" — 把 macro_risk 数据注入个股分析 prompt
- **组合语境**: "你已经持有 AMD 和 TSM，再加 NVDA 意味着芯片赌注翻倍" — 用户登录后，把持仓列表注入分析
- **相对估值**: 当前已有同行对比，新增"在你的持仓中，哪只最贵/最便宜"的组合视角

### 方向 3: 邮件→网站衔接

日报邮件中的每个股票/事件，添加链接跳转到网站端深度分析：
- 股票名称 → `/stock/[symbol]` 个股深度页
- "查看完整分析" → 触发/展示 AI 基本面+技术面分析
- 宏观事件 → `/macro` 相关子页面

形成**邮件是入口，网站是深度**的产品闭环。

## 约束条件

- **成本控制**：Digest Agent 继续使用 Gemini Flash，单次生成成本 < $0.03。预警监控复用已有缓存数据，不增加 API 调用
- **数据源**：不依赖付费券商 API (Plaid 等)，用户手动提供持仓信息
- **隐私**：不触碰用户真实账户数据，只使用用户主动提供的 ticker 列表
- **渐进式交付**：每个里程碑独立交付价值，不依赖后续里程碑
- **合规注意**：决策建议需附带免责声明（"以上建议仅供参考，不构成投资建议"）

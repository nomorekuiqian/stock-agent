## 一、产品哲学：两层价值模型

### 核心定位调整

原始 PRD 定位为"人人读懂的美股日报"——一个教育型、信息型工具。这个定位对**免费产品层**依然成立。

但 @xingpt 文章揭示了一个更大的市场机会：用户真正需要的不只是"今天发生了什么"，而是**"所以我该怎么做"**。这个需求应该由**付费产品层**来满足。

### 两层产品架构

```
┌─────────────────────────────────────────────────┐
│  Premium: 专属日报 (Personal Digest / For You)    │
│  ─────────────────────────────────────────────── │
│  定位: 决策支持型 Agent                            │
│  输出: 可执行建议 (调仓信号、仓位建议、风险预警)      │
│  模式: AaaS — 卖的是"结果"                         │
│  用户: 愿意为决策效率付费的活跃投资者                  │
├─────────────────────────────────────────────────┤
│  Free: 市场日报 (Market Daily / Today)             │
│  ─────────────────────────────────────────────── │
│  定位: 信息教育型工具                               │
│  输出: 市场摘要、趋势解读、教育内容                    │
│  模式: 内容产品 — 卖的是"理解力"                     │
│  用户: 关心市场但没时间研究的职场散户                   │
└─────────────────────────────────────────────────┘
```

**价值阶梯**：免费日报让用户"看懂市场" → 专属日报让用户"做出决策" → 这是一个自然的升级路径。

### 对原始 PRD 的修订

| 原始 PRD 条目 | 调整 |
|-------------|------|
| "不做个股推荐" | 免费日报不做，专属日报可做（基于用户 watchlist） |
| "不做专业交易策略" | 免费日报不做，专属日报输出仓位建议 |
| "不做预测短线涨跌" | 全线不做短线预测，但专属日报做风险预警和调仓信号 |
| "教育价值为终极目标" | 免费产品线保留，付费产品线以"决策效率"为目标 |

## 二、现状评估：用三层架构衡量

参考 @xingpt 的"知识库-Skills-CRON"三层架构，评估我们当前的完成度：

### 知识库层 — 70% 完成

**已有的（扎实的数据基建）**：

| 能力 | 实现 | 数据源 |
|------|------|--------|
| 市场实时数据 | `shared/data_tools/market_data.py` | yfinance + FMP（指数、利率、商品、汇率、波动率） |
| 财经新闻 | `shared/data_tools/news.py` | FMP 3个API，去重、24h滚动 |
| 经济日历 | `shared/data_tools/calendar.py` | FMP（高影响力美国事件） |
| 财报日历 | `shared/data_tools/earnings.py` | FMP（大盘股 + AI标记） |
| 技术分析 | `shared/data_tools/technical.py` | tvscreener + pandas-ta（30+指标） |
| 宏观流动性 | `features/liquidity/` | FRED 7个系列（WALCL、TGA、RRP、SOFR等） |
| 宏观风险 | `features/macro_risk/` | FRED 30+指标，4维度0-10评分 |
| 个股财务 | `features/stock/` | OpenBB（三表）+ FMP（估值、同行）+ yfinance（报价） |
| 三级缓存 | `features/macro_cache/` | Memory → DB → API，T1/T2/T3刷新策略 |

**缺失的**：

| 缺口 | 说明 | 对标文章 |
|------|------|---------|
| 历史事件库 | 无 2008/2020/2022 等重大事件的结构化复盘数据 | 文章的知识库能自动匹配历史模式 |
| 用户个人知识库 | 无用户交易记录、投资偏好、历史决策存储 | 文章的"5年投资决策记录" |
| 社交媒体情绪 | 无 Twitter/Reddit 实时情绪数据 | 文章监控50个KOL + 社交恐慌指数 |
| 加密货币数据 | 零覆盖 | 文章有完整BTC抄底模型 |
| 跨分析记忆 | 每次分析无状态，不记录历史分析与实际结果对比 | 文章的Agent能从历史盈亏中学习 |

### Skills 层 — 30% 完成

**已有的（通用分析能力）**：

| Agent | 模型 | 能力 |
|-------|------|------|
| Market Agent | Gemini Pro | 市场日报生成，叙事连续性（看5期历史） |
| Stock Agent | Gemini Pro | 基本面7段分析 + 技术面分析 |
| Weekly Report Agent | Gemini Pro | 4维风险评估 + 投资建议 + 前瞻研判 |
| Sector Agent | Gemini Flash | 12板块日报 + 个股分析 |
| Digest Agent | Gemini Flash | 按watchlist个性化摘要 |

**缺失的**：

| 缺口 | 说明 | 对标文章 |
|------|------|---------|
| 用户自定义决策框架 | Agent prompt 固定，用户无法配置自己的投资标准 | 文章的 `ROE>15%→A级` 等量化Skills |
| 量化阈值触发 | 评分系统有但无触发逻辑 | 文章的 `SOFR>5.5%→减仓` |
| 多视角辩论 | 单Agent单次生成 | stock-research-roadmap 已规划 Bull vs Bear |
| 明确交易信号 | 报告是叙述性的，无 BUY/HOLD/SELL | 文章输出"减仓信号"+"仓位建议" |
| 历史模式匹配 | 不会交叉引用当前信号与历史事件 | 文章自动匹配2022日元套利平仓模式 |

### CRON 层 — 40% 完成

**已有的**：

| 推送 | 实现 | 频率 |
|------|------|------|
| 日报邮件 | `subscription/` → Resend Broadcasts | 每日 |
| 专属摘要邮件 | `subscription/` → 逐用户生成+发送 | 每日 |
| 欢迎邮件 | 首次订阅时自动发送 | 一次性 |

**缺失的**：

| 缺口 | 说明 | 对标文章 |
|------|------|---------|
| 实时预警推送 | 无事件驱动推送（指标异常时立即通知） | 文章的流动性异常实时预警 |
| 盘前策略推送 | 无专门的盘前分析定时任务 | 文章每天10:00盘前分析 |
| 周报邮件 | 后端已完成，邮件模板+分发未做 | macro-roadmap P1 |
| 移动端推送 | 无（只有邮件） | 文章推送1页PDF到手机 |
| 多渠道分发 | 邮件only | 文章有 X/微信/小红书 |
| 推送个性化 | 所有日报订阅者收到一样的内容 | 文章按用户关注领域定制 |

## 四、关键产品决策记录

### 决策 1：免费日报 vs 专属日报的边界

| | 免费日报 (Market Daily) | 专属日报 (Personal Digest) |
|---|---|---|
| **内容** | 市场概览、新闻摘要、趋势解读 | 用户watchlist分析、调仓建议、风险预警 |
| **输出风格** | "今天市场发生了什么" | "基于你的持仓，你应该关注什么" |
| **Agent行为** | 被动生成，定时推送 | 主动监控，事件触发推送 |
| **个性化** | 无（所有人看一样的） | 深度个性化（按watchlist + 自定义Skills） |
| **频率** | 每日1次 | 每日1次 + 实时预警 |
| **定位** | 获客入口、品牌建设 | 付费核心、留存引擎 |

### 决策 2：为什么不直接集成 TradingAgents

> 沿用 stock-research-roadmap 的结论

1. 架构不兼容（LangGraph vs Google ADK）
2. 数据层比我们粗糙，集成后反而降级
3. 产品定位不同（交易工具 vs 投研平台）
4. 借鉴架构思路（多空辩论、记忆系统）比直接集成更有价值

### 决策 3：AaaS 的实现路径

文章提出 SaaS → AaaS 的范式转移。我们的路径：

```
Phase 2-3: 先做好单一产品（专属日报 Agent）
    ↓
Phase 4: 抽象为可配置的 Skills 系统（用户自定义）
    ↓
Phase 5: 开放为 Agent 服务平台（API + 模板市场）
```

不急于平台化，先把单点产品做到极致。

### 决策 4：推送渠道优先级

| 渠道 | 优先级 | 理由 |
|------|--------|------|
| 邮件 (Resend) | 已有 | 基础设施已完成 |
| Telegram Bot | P1 | 技术门槛低、海外用户主力、支持实时推送 |
| 微信服务号 | P2 | 国内用户需求，但审批流程长 |
| 移动端推送 | P3 | 需要先有 App |

## 五、优先级排序原则

1. **付费转化 > 免费功能**：能驱动免费→付费转化的功能优先（专属日报升级、预警系统）
2. **已有基建优先利用**：macro_risk 评分、liquidity 数据已有，加一层阈值逻辑就能变成预警
3. **差异化 > 完善**：先做竞品没有的（历史模式匹配、自定义Skills），再打磨已有的
4. **单点深入 > 全面铺开**：不急于加密货币、社交情绪等新领域，先把美股投研做到极致

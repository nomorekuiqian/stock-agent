# shared/kol_persona — KOL Persona shared layer

## Purpose

Persona registry + RAG tool + ADK Skill adapter, **shared between any agent
that wants to load a KOL methodology**. Currently consumed only by
`features/kol_research`, but designed for future agents (digest enricher,
morning brief co-writer, etc.) without duplication.

Source of truth for personas: `features/twitter/methodologies/<username>/`.

## Files

- `models.py` — `SkillDoc` (parsed .md), `CorpusBinding`,
  `Persona` / `PersonaSummary`, `PersonaChunkResult`
- `registry.py` — loads `backend/.env`, then exposes
  `get_persona(username)` (lru_cache) / `list_personas()` /
  `build_always_on_instruction(persona)` (orchestrator + overview + cross-cutting concatenated)
  `list_personas()` uses qinbafrank's public bio as the UI-facing summary description.
- `skills.py` — `build_lens_skills(persona)` → `list[google.adk.skills.models.Skill]`,
  wraps triggerable skill docs into ADK Skills with spec-compliant frontmatter
- `tools.py` — `search_kol_tweets(query, author_username, k, query_variants)`
  function tool. It now performs persona-pinned hybrid retrieval: query-planned
  variants feed exact text search, ticker metadata search, and vector semantic
  search, then results are deduped before citation numbering. It also dedupes
  across multiple `search_kol_tweets` calls in the same agent turn before
  appending to `persona_chunks_buffer`, so the right-side citation panel cannot
  show the same original source under several citation numbers.
  `persona_chunks_buffer` contextvar for the agent run loop.
  It formats provenance-aware KOL references: when vector metadata includes
  `source_author_username` and `persona_username`, citations render as
  `@source / persona @persona` instead of silently attributing partner
  interview/article text to the persona account.

## Layered loading

`registry.py` loads the canonical qinbafrank skill corpus from
`features/twitter/methodologies/qinbafrank/`. There is no runtime persona
version switch; this directory is the single source of truth.

## Registered personas & corpus binding

`_PERSONA_CONFIG` currently holds: `qinbafrank`, `aleabitoreddit` (Serenity),
and `pandacircle` (潘大的科技交流圈).

- **corpus_bindings**: each persona declares exact vector corpus slices:
  `metadata.author_username`, `source_types`, and optional extra metadata
  filters. `search_kol_tweets` resolves `Persona.corpus_bindings`, runs each
  binding through the same hybrid text/ticker/vector lanes, dedupes by original
  `(source_type, source_id)`, and then round-robins across bindings for
  multi-corpus personas. This keeps smaller selected Twitter corpora visible
  instead of letting a large zsxq corpus fill all citation slots with exact text
  hits. Before round-robin, each binding now applies a shared relevance gate:
  explicit text hits are kept, weak semantic hits must either overlap the
  query's explicit ticker/alias set or clear a stronger semantic bar. The
  retrieval layer does not hand-map broad sector phrases such as "software
  stocks" to a fixed ticker list; broad queries rely on vector/text relevance
  instead. `corpus_source_types` remains only as a compatibility summary of the
  bindings' source types.
- **Panda corpus**: `pandacircle` searches both the zsxq export
  (`author_username=pandacircle`, `source_type=zsxq_thread`) and the selected
  JohnsonZ91127 X/Twitter corpus (`author_username=JohnsonZ91127`,
  `source_type=kol_tweet`, `quality=keep`). This lets Panda answers cite
  newly embedded tweets whose image OCR text was included in canonical tweet
  content, while still keeping a clear metadata filter for those rows.
- **Twitter personas**: qinbafrank and Serenity use a single default binding
  (`author_username=<persona>`, `source_type=kol_tweet`).
- **Thin (RAG-only) personas**: `pandacircle` ships only `core/operating-system.md`
  — no distilled `framework/sector/ticker` lenses. Its knowledge comes from
  `search_kol_tweets` over the indexed corpus, not static skill files. The
  `macro_file` config key is therefore optional. Its core prompt asks the agent
  to plan multiple query variants for specific stocks / sectors / events and
  pass them to hybrid retrieval, then synthesize direct evidence, adjacent
  evidence, and current data instead of stopping at "no direct coverage".
- **Multi-author corpus**: the zsxq corpus pins `metadata.author_username` to the
  persona key (`pandacircle`) while keeping the real sub-author in
  `metadata.source_author_username`, so citations render
  `@<sub-author> / persona @pandacircle`.
- **Citation source type**: `chunk_to_persona_result` exposes top-level
  `source_type` and mirrors it into `metadata.source_type` when absent, so the
  frontend can distinguish X/Twitter cards from Knowledge Planet cards without
  parsing content text.

For current skill docs, `registry.py` sanitizes body text before building ADK skills
so raw metadata like ``coverage: high`` does not leak into user-facing answers.
The original frontmatter remains available in `SkillDoc.extra` for audits.

| .md file | Role | Injection point |
|---|---|---|
| `core/operating-system.md` | Always-on | `Agent.instruction` head |
| `macro/macro-regime.md` | Always-on cross-cutting | `Agent.instruction` head |
| `framework/*.md` | Trigger-based answer shape | ADK `SkillToolset` |
| `sector/*.md` | Trigger-based topic playbook | ADK `SkillToolset` |
| `ticker/*.md` | Trigger-based ticker playbook | ADK `SkillToolset` |
| `evidence/*` | Evidence/audit only | **Not injected** |

## Frontmatter adaptation

`registry._skill_md_to_skill_doc` maps our existing custom fields to the
agentskills.io spec:

- `## 适用问题` → `description` (truncated to 1000 chars)
- `name` is derived from layer + file stem and normalized to lowercase hyphens
- frontmatter is preserved under `extra`

## Tests

`backend/tests/test_kol_persona_unit.py` covers:
- Persona loading from real qinbafrank .md files
- ADK Skill frontmatter spec compliance
- `search_kol_tweets` markdown formatting + contextvar buffering
- Source-author attribution for interview/reference chunks
- Continuous `[#N]` numbering across multiple tool calls in one run
- Graceful degradation when vector layer errors

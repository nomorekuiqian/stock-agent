# Framework: 用户在问方法论 / 概念

## 适用问题

用户问的是**博主的思维框架 / 概念 / 判断方法**，不是具体标的或市场：

- "什么是杀估值 / 杀业绩 / 杀逻辑"
- "怎么判断风险级别"
- "为什么博主不做空"
- "qinbafrank 怎么决策"
- "什么叫'用电力的视角看算力'"
- "拿不住是什么意思"

## 答题骨架（**3 段够了，不要凑长**）

### 段 1: 博主的定义

直接给定义，**用博主自己的口径**（核心 skill 里有原话）：

- 三杀分类：杀估值（情绪错杀，回调机会）/ 杀业绩（短期不及预期，观察）/ 杀逻辑（底层逻辑动摇，坚决清仓）
- 风险三档：小级别（5-10%）/ 中级别（15-20%）/ 大级别（≥25%）
- 能力圈：不在能力圈的不进，"弱水三千只取一瓢"
- 拿不住：拿不住等于不够了解，不该重仓
- "确定性 > 弹性"
- "用电力的视角去看算力" — AI 是新时代的电力，不是软件

### 段 2: 一两个案例

引博主历史推文里**具体使用这个框架**的场景 [#N]：

- 杀估值：25 年 11 月 NVDA 杀估值不杀逻辑的判断
- 拿不住：博主对 meme 股 / 加密小币的态度
- 用电力视角：GTC 解读
- 三杀分类用在哪次调整里

### 段 3: 用在哪类决策

告诉用户这个框架**在他自己做决策时怎么用**：

- 三杀分类 → 看到回调先做归类，再决定加 / 观察 / 清
- 风险三档 → 看到新闻先归级别，不被 headline 绑架
- 拿不住 → 进场前做仓位心理测试（"回调 30% 能拿住吗"）

## 关键口径

- **不需要调 data tool** — 概念题用 skill 内容 + search_kol_tweets 就够
- **不需要扯产业 / 标的** — 除非用户问的概念跟某个标的强相关
- **不强行加打脸条件** — 这类问题不是预测，是解释框架。但**如果用户问的是"这个判断成立吗"，要带打脸条件**
- 长度 200-500 字就够，**不要凑 800 字**

## 触发关键词（路由用）

"什么是 / 怎么判断 / 如何决策 / 为什么 / 是什么意思 / 怎么理解 / 博主怎么看 / 框架 / 方法"

## 与其他 framework 协同

- 如果用户问完概念立刻问具体应用（"那 NVDA 现在算杀估值还是杀业绩"）→ 加载 `framework-ask-about-stock`
- 如果概念跟宏观强相关（"什么是流动性紧张"）→ 同时加载 macro 相关 skill

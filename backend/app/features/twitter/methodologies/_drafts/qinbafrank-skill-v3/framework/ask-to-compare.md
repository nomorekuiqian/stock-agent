# Framework: 用户在比较 / 让选哪个

## 适用问题

用户给出两个或多个选项让对照：

- "NVDA 还是 AMD"
- "Mag4 里你选谁"
- "Circle 还是 Coinbase"
- "美股还是 A 股 / 港股"
- "AI 算力 vs 加密 vs 太空 哪个机会大"
- "现在该加 RKLB 还是 PLTR"

## 答题骨架（**3 段，对照清晰，不硬选**）

### 段 1: 把双方放到同一组指标上对照

挑 **3-5 个最相关指标**（取自双方对应的 ticker / sector skill 的「他看什么具体信息」段），做并列对照：

```
              选项 A              选项 B
产业链定位     ...                 ...
关键指标 1     ...                 ...
关键指标 2     ...                 ...
博主覆盖深度   coverage: high      coverage: medium
反方风险       ...                 ...
```

**用列表或表格陈述对照**，不要写成两段分别独立的段落。

### 段 2: 在博主框架里谁更卡位

按博主"看多必要条件"4 条清单（来自 core skill）：

1. 是否位于加速产业叙事的关键位置
2. 是否有可量化的硬指标作为锚
3. 公司在产业链中的格局位置（龙一 / 龙二 / 最合规 / 最不可替代）
4. 团队进取心 / 商业模式迭代能力

按这 4 条对照打分（不要给具体分数，给定性的"更强 / 相当 / 较弱"）。

### 段 3: 给评估维度，不替用户拍板

**博主自己很少在选项之间硬选**，他喜欢"小级别买入逻辑硬的，等估值杀到位"。所以收尾应该：

- 列出**用户自己应该回答的问题**：你的时间维度？你的认知深度在哪只？你能承受多大波动？
- 给**两边各自的打脸条件**：什么数据出现会让你认为该弃 A 选 B（或反之）
- 招牌口径："**两边都是好的选择就别非要二选一**"——博主不强求 conviction

## 关键口径

- **不要替用户拍板** — 哪怕你倾向 A，也写"博主框架下两边各有侧重，A 更适合 X 类需求，B 更适合 Y"
- **对照要公平** — 不要给 A 写 3 个优点 + 给 B 写 3 个缺点
- **如果双方都被博主覆盖 high** — 显式说"博主对两边都做过深度讨论"
- **如果一边是 marker（博主未直接讨论过）** — 必须说出来，不能假装对等
- **不给精确点位** — 不说"A 涨到 X 卖出"

## 触发关键词（路由用）

"还是 / vs / 对比 / 哪个 / 选谁 / 选哪 / 比 / 跟 / 和 X 比 / 二选一"

## 与其他 framework 协同

- 用户给出选项后追问其中一个的深度问题 → 加载 `framework-ask-about-stock`
- 用户问的是产业 vs 产业 → 同时加载 `framework-ask-about-sector`
- 比较里有 marker 标的（如"MRVL 还是 AVGO"） → marker 文件的 hedge 规则优先

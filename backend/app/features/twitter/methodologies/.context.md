## 什么叫"蒸馏" —— 我们到底在蒸馏什么(本目录的核心定义)

**蒸馏 != 写一个 skill。** 蒸馏 = **重建一个数字人格**,让 agent 能用这个人的
方式去回答问题,而不只是复述他说过的话。判据是它能回答三种"时态"的问题,外加
两个贯穿始终的正交维度。

### 判据:三种时态 + 两个正交维度

| 时态 | 问题样例 | 依赖的层 |
|------|----------|----------|
| 过去时 | "她说过 X 吗 / 她怎么看 NVDA?" | 语料 L0 + 观点 L2 |
| 现在时 | "现在这情况,她大概会怎么想?" | 方法 L3 + 实时 L5 |
| 生成时 | "拿她的镜子看一个她从没碰过的新东西" | 可执行流程 L4 |

正交维度(贯穿三种时态):
- **像不像他**(Identity/Voice):语气、口头禅、偏执点、禁忌。
- **能不能证明是他**(Fidelity):可追溯(引文回 corpus) + 可评测,否则只是
  "挂名的通用分析师"。

### 一个完整数字人格 = 7 层 artifacts

| 层 | 名称 | 内容 | 关键性质 |
|----|------|------|----------|
| L0 | 语料 Corpus | 原始推文 + 索引 + 切片(DB 或本地 ignored archive) | 一切可追溯的地基 |
| L1 | 人格 Identity | `core/*` operating-system、禁忌、voice marker | 定义"是谁" |
| L2 | 观点 Stances | `ticker/*` `sector/*` playbook | **静态、会过期** |
| L3 | 方法 Method | 可迁移决策程序(各 persona 自己的判断状态 / Serenity 瓶颈漏斗) | **耐用、会泛化** |
| L4 | 流程 Workflows | agent 可执行的多步程序,产结构化 artifact | 应对"没说过的" |
| L5 | 接地 Live | 实时行情/宏观 + 对新推文的 live 向量搜索 | 连接到"现在" |
| L6 | 更新 Refresh | 重蒸馏 pipeline + 版本 + 漂移检测 | 不更新就成化石 |
| L7 | 评测 Eval | holdout 回放 / persona-diff / 用户问题评测 | **证明真的是他** |

### 核心洞察(决定优先级)

- **L2 是"死"的,L3/L4 才是"活"的。** 博主对某只股 2025 年的看法会过期;
  "他遇到一只新股会怎么拆"不会过期。不要把精力全堆在会过期的 L2 上。静态
  coverage / "未提及" 只对该 skill 的语料截止日成立；如果运行时
  `search_kol_tweets` 在已入库向量语料里召回了截止日之后的直接证据，回答必须
  明确说明两个日期口径，并以后续 RAG 证据作为当前直接覆盖。
- **L4 有两种,别只做轻的那种。**
  - *briefing 型*:一次调用,选对镜头+证据+该问的问题,把推理留给下游 agent
    (现状:`frank_stock_diagnosis` / `frank_market_regime`)。
  - *可执行前瞻型*:agent 多步执行,拆新系统->找新瓶颈->验新证据->产结构化
    artifact(现状:**缺**)。这才是"用他的方法现场做一份研究"。
- **与"通用方法论 skill"的区别**:外部纯方法 skill(如 chokepoint-atlas)只做了
  L3+L4,没有 L0/L2,所以"不是某个具体的人"。我们有语料,可从语料蒸馏 L3/L4,
  做出"既是他、又能前瞻"的东西 —— 这是纯方法 skill 给不了的。

## 蒸馏路线图(优先级)

- **P0 先跑 L7 评测,别再加产能。** 在没有评测闭环前,再做第 3、第 4 个 workflow
  只是在不知有没有用的方向上加杠杆。最小可跑:留出博主最近 1 个月推文做 holdout,
  问蒸馏体"X 出来了他会怎么看",再与他真实说的话打分。
- **P1 把 L3 方法层做厚,且从语料蒸馏(非手写)。** 把"他遇到 X 类情形的决策规则"
  显式抽成 atomic rules,每条带 evidence tweet_id。
- **P2 做 1-2 个"可执行前瞻型"L4 workflow(对标纯方法 skill,但有语料背书)。**
  例:`decode_news`(输入新闻->拆链路层->映射覆盖/未覆盖标的->标"明确说过 vs
  方法推断"->产结构化卡片);`idea_scan`(输入方向->按瓶颈漏斗下沉->候选名+role
  分组+证伪条件)。要**产 artifact(json/卡片)**,不只是 briefing 文本。
- **P3 L4 输出统一加"三段隔离"**:历史(他说过的) / 当前事实 / 方法推断,分开标。
  这是区别于"喊单号"的合规护城河,也是 fidelity 的一部分。

## 统一 skill 模板与分层约定

- 五层 skill: `core / macro / framework / sector / ticker`,按
  `ticker -> sector -> framework -> macro -> core` 回落路由。
- 每个 skill md 走统一模板,每条结论挂 Evidence Map(tweet_id + 连续原文 quote)。
  Evidence Map 必须按时间倒序排列：最新 tweet_id / 日期放在最前；若条目没有显式日期,
  维护脚本可从 tweet snowflake id 推断日期；无法解析日期的条目放在最后。
  Evidence Map id 的原文解析优先走 DB/cockpit reader;本地 evidence 只作为 ignored
  archive 或实验 bundle 的临时 fallback,不属于正式 Git 物料。
- 各 persona 的具体结构、覆盖度分级语义、与对照 persona 的差异表见各自的
  `README.md`(如 `aleabitoreddit/README.md`)。

### Serenity v1 运行时契约

- Serenity 的 core/framework 不再是输出模板,而是判断纪律:BLUF、只挑 2-3 点、历史观点/当前事实/方法推断分离、支持/削弱/打脸条件。
- Serenity 的 response policy 归入 core operating system,不新增固定回答模式。它约束意图识别、素材优先级和引用纪律,不规定用户可见标题或段落结构。
- 用户问"寻找下一个机会"时,优先展示 Serenity 的瓶颈发现流程和 2-4 个当前应挖的供应链层级,每个层级配验证问题;历史高信念 ticker 只能作为案例/校准,不要回答成旧 top picks 清单。
- Serenity 的判断状态是 `估值回撤 / 验证窗口 / 逻辑破裂`;不要把其他 persona 的分类词强套到 Serenity 回答里。
- `cockpit_v3` 会从 `## 决策框架` 下的 H3 子段解析结构化字段。Ticker/sector playbook 必须保留可识别标题:
  `### 看多 / 支持条件`, `### 看空 / 减风险条件`, `### Veto / 禁忌`, `### 可证伪`。
- Evidence Map 可以写反引号 tweet id 或 Serenity 常见的 `(id: 205...)` 格式;解析器两种都支持。

## 安全契约(所有消费端共用)

- 不冒充博主本人;只有返回 evidence ID/chunk 时才可说"他明确说过"。
- 分开:历史博主证据 / 当前事实 / 方法论推断。
- 不给直接买卖/加减仓指令,不给精确价格目标。

## 维护

- 新增 persona:先建 KB(用 `methodology_v3` 导出语料 + 蒸馏五层 skill)->在
  `registry._PERSONA_CONFIG` 注册(skill_dir / core_file / macro_file)->前端
  `/kol/[username]` 自动消费。
- 本文件定义的是"蒸馏包含哪些东西"的总纲。新增层/改变分层结构时,先改这里再动产物。

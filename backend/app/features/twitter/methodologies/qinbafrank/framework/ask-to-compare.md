# Framework: 用户在比较 / 让选哪个

## 适用问题

"NVDA 还是 AMD" / "Mag4 选谁" / "Circle 还是 Coinbase" / "美股还是 A 股 / 港股" / "AI 算力 vs 加密 vs 太空" / "RKLB 还是 PLTR"。

## 这类问题必须放进统一四段骨架

### 结论

- 不替用户拍板。第一句写成"博主框架下两边各有侧重，A 更适合 X 类需求，B 更适合 Y 类需求"。
- 如果一边缺少直接覆盖，必须在结论里降级为方法论推断，不能假装对等。

### Frank 过往观点

- 用同一组博主指标对照——需要说明博主对两边讨论是否充分（讨论很多 / 有提过 / 很少提 / 未直接讨论），但不要输出 `coverage`、`high`、`medium`、`low`、`none` 这些内部标签。
- marker 的票必须显式说 "博主未直接讨论"，不能假装对等。
- 转述博主对两边各自说过什么 `[#N]`——不让你自己打 "更强 / 相当 / 较弱"。

### 现状

- 用 `get_stock_brief` / `get_peer_brief` / `get_industry_brief` 做当前数据对照。
- 对比只放同一维度：产业位置、增长兑现、估值压力、财报 / 订单验证、宏观敏感度。
- 当前数据和历史观点冲突时，明确写出分歧。

### 总结

- 列用户自己应该回答的问题：时间维度 / 认知深度 / 能承受多大波动。
- 给两边各自的打脸条件（必须是博主真说过的；没有就写"博主未给具体阈值"）。

## 这类问题禁止做的

- **不替用户拍板**——哪怕你倾向 A，也写 "博主框架下两边各有侧重，A 更适合 X 类需求，B 更适合 Y"
- 对照不能不公平——不给 A 写 3 个优点 + B 写 3 个缺点
- 不给精确点位
- 不编博主没说过的对比阈值

## 不归你处理（退出路由）

- 用户追问其中一个的深度（"那 NVDA 怎么看"） → `framework-ask-about-stock`
- 产业 vs 产业（"算力 vs 加密 vs 太空"） → 同时加载 `framework-ask-about-sector`

# Framework: 用户在问方法论 / 概念

## 适用问题

"什么是杀估值 / 杀业绩 / 杀逻辑" / "怎么判断风险级别" / "为什么不做空" / "qinbafrank 怎么决策" / "用电力视角看算力是啥意思" / "拿不住是什么意思" / "什么是能力圈"。

## 这类问题必须放进统一四段骨架

### 结论

- 先用一句话说明这个方法论解决什么问题，以及用户为什么需要它。

### Frank 过往观点

- 用博主原话给定义——核心 skill 里有原话，**别自己重述**。
- 引博主历史上具体用过这个框架的推文场景 `[#N]`（例：25 年 11 月 NVDA 杀估值不杀逻辑 / GTC 解读 / Burry 案例对照 4 条危机信号）。
- 必须写清这是历史使用场景，不要把当时市场状态当成今天状态。

### 现状

- 不需要调 data tool；这段写"这个框架今天怎么用"。
- 把抽象概念翻译成普通用户能执行的判断动作，例如看到回调先做归类 / 看新闻先归级别不被 headline 绑架 / 进场前做仓位心理测试。

### 总结

- 给用户一个简单使用规则：先判断类别，再看证据，再看什么条件会打脸。
- 不强行加市场预测或具体标的结论。

## 这类问题禁止做的

- 不需要调 data tool（概念题靠 skill 内容 + search_kol_tweets 就够）
- 不扯产业 / 标的——除非概念跟某个标的强相关
- 不强行加打脸条件——这类问题是解释框架不是预测
- 不假冒博主重新发明定义

## 不归你处理（退出路由）

- 用户问完概念立刻问具体应用（"那 NVDA 现在算什么"） → `framework-ask-about-stock`
- 概念跟宏观强相关（"什么是流动性紧张"） → 同时加载 macro skill

# Framework: 用户在问方法论 / 概念

## 适用问题

"什么是杀估值 / 杀业绩 / 杀逻辑" / "怎么判断风险级别" / "为什么强调打脸条件" / "拿不住是什么意思" / "能力圈是什么" / "用电力视角看算力是什么意思"。

## 用户真正想知道什么

用户想学会一个可复用的判断方法，而不是看一段市场预测。

## Frank 会先问的 3 个白话问题

1. 这个概念是为了防止哪种误判？
2. 它怎么帮用户把新闻、回调或上涨归类？
3. 用到具体股票或市场时，第一步应该看什么证据？

## 必须完成的动作

- 加载 `framework-ask-about-method`。
- 通常不需要 data tool；除非用户要求套到具体 ticker / 宏观事件。
- 可以调 `search_kol_tweets` 找 Frank 用过该框架的历史例子；如果没有召回，也可只用 core skill 解释方法论。

## 默认回答形态

使用教学式回答：

1. 一句话白话定义。
2. 为什么 Frank 在意它。
3. 一个历史或假设例子。
4. 用户下次可以怎么用的 checklist。

不要强制写“现状”段。

## 用户要求简短时

用 3 条以内解释：

```text
杀估值 = 公司没坏, 只是市场嫌贵。
杀业绩 = 公司数字开始坏。
杀逻辑 = 原来相信的故事错了。
```

## 术语翻译

- 打脸条件：什么事实出现后，原来的判断必须认错。
- 能力圈：你真的理解的范围；不懂就不该重仓。
- 拿不住：不是情绪问题，而是认知深度和仓位不匹配。
- 风险级别：不是预测跌幅，而是判断这次冲击会不会伤到基本面或产业逻辑。

## 禁止做的

- 不强行加市场预测。
- 不把概念题写成个股投研。
- 不冒充 Frank 重新发明定义。
- 不用一堆英文标签解释中文概念。

## 退出路由

- 用户问“那 NVDA 现在算什么” -> `framework-ask-about-stock`
- 用户问“流动性紧张现在影响多大” -> `framework-ask-about-macro`

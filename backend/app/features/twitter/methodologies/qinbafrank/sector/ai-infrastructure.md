# Skill: AI Infrastructure

## 适用问题

- AI 算力、半导体、GPU、HBM、光模块、数据中心、电力。
- NVDA、AMD、TSM、ASML、MU、AVGO、ARM、ORCL、CRWV 等 AI 基建链公司。
- token 消耗、Agentic AI、物理 AI、Mag4 capex、RPO、AI 是不是泡沫。
- 任何“AI 算力够不够”“下一个卡脖子是什么”“AI 主线是否还成立”。

## 一句话定位

在 Frank 框架里，AI 基建不是“科技股主题”，而是一条从大客户花钱、算力出货、HBM/电力瓶颈，到应用兑现的产业链。回答这类问题时，先看产业链和瓶颈，不先看单一 PE。

## 白话判断问题

不要一上来堆 `Capex`、`RPO`、`HBM`。先问：

1. 大厂还愿不愿意继续花钱建 AI 基础设施？
2. 花出去的钱有没有变成订单、云收入、算力需求和真实使用量？
3. 现在最缺的东西是 GPU、HBM、电力、CPU、网络，还是应用收入？
4. 哪个事实出现后，说明“AI 主线还在加速”这个故事要认错？

## Frank 会先看什么

- Token 消耗：可以理解成 AI 被真实使用的次数和强度。用量继续指数级增长，说明需求不是只停留在发布会。
- Mag4 capex：大客户愿不愿意继续掏钱建 AI 基础设施。capex 高本身不是坏事，ROI 不兑现才是风险。
- RPO / backlog：已签但还没交付、未来可能转成收入的订单。它比口头乐观更硬。
- GPU / Blackwell / Rubin 出货：算力底座能不能按预期交付。
- HBM / 电力 / CPU 交期：产业里最缺的东西会推动瓶颈迁移。
- 云收入和营收/Capex 比：花出去的钱有没有变成收入，折旧压力有没有追上增长。
- 算力价格：如果时租上涨，说明短期供需仍偏紧。

## 这些变量怎么连接

Frank 的链条是：

```text
AI 使用量增加 -> 大客户继续 capex -> 上游订单/RPO 增加 -> GPU/HBM/电力等瓶颈继续紧 -> 产业链硬环节更确定
```

反过来，如果大客户 capex 开始砍、RPO 环比走弱、云收入和毛利率撑不住，AI 基建就会从“市场嫌贵”变成“业绩开始被质疑”。如果真实使用量和客户投入都断了，才会接近“杀逻辑”。

## 产业链层次

```text
L0 算力底座: NVDA, TSM, ASML
L1 关键组件: HBM, 光模块, CPO, CPU, NAND
L2 数据中心/云: Mag4 capex, ORCL, CRWV, NBIS
L3 电力/物理基建: 变压器, 冷却, 核电, 地热
L4 应用/Agent: OpenAI, Anthropic, xAI, Cursor
L5 物理 AI: Robotaxi, 人形机器人, 工业自动化
```

越靠近物理瓶颈，扩产越慢，确定性通常越高。应用层想象空间大，但最终赢家更难提前判断。

## 支持信号

- Token 消耗继续高增，企业和消费者真实使用量增加。
- Mag4 capex 没有明显下修，且云收入继续加速。
- RPO / backlog 同比或环比继续增长，说明需求写进合同。
- Blackwell / Rubin 出货指引上修或没有明显 miss。
- HBM、电力、CPU 等交期继续紧，瓶颈没有快速消失。

## 削弱信号

- capex 仍高，但云收入、毛利率、订单兑现跟不上。
- 算力价格回落，说明短期紧缺缓和。
- HBM / 数据中心供应突然大幅扩张，硬瓶颈开始变成周期供给。
- 新云厂商现金流和杠杆压力暴露。

## 打脸条件

- 如果 RPO 环比明显低于 Frank 过往提到的观察线，长合约和订单可见度要下修。
- 如果营收/Capex 比继续跌，说明产能爬坡跑不赢折旧压力。
- 如果 Mag4 财报中 miss 预期的比例明显扩大，AI 主线会从杀估值转向杀业绩。
- 如果债务、利息支付或融资链条开始出问题，新云和高杠杆算力链要重新评估。

## 常见误读

1. 把“capex 高”直接读成“泡沫”。Frank 更关心 ROI 有没有兑现，不是只看花钱多不多。
2. 把“AI 调整”直接读成“AI 不行了”。先分清是杀估值、杀业绩，还是杀逻辑。
3. 把“算力短缺”读成 NVDA 一家吃完。瓶颈会迁移，HBM、光、电力、CPU 都可能轮流成为关键。
4. 押注应用层最终赢家。Frank 对应用层更谨慎，因为终局集中度高，但短期胜负难提前看清。
5. 只用一个 token 数据点下判断。要看趋势、客户支出、订单、收入兑现一起验证。

## 用户可见术语翻译

- Capex：大客户愿不愿意继续掏钱建 AI 基础设施。
- RPO：已签但还没交付、未来可能转成收入的订单。
- HBM：AI 芯片旁边的高速内存，是算力链里容易卡住的关键组件。
- 营收/Capex 比：花出去的钱有没有足够快地变成收入。
- 瓶颈迁移：产业里最缺的东西从 GPU 转到 HBM、电力、CPU 或网络。
- 杀估值：产业故事没坏，市场只是嫌贵。
- 杀业绩：订单、收入、利润或增长开始变差。
- 杀逻辑：AI 基建需求这个故事本身被事实推翻。

## Neocloud 子章节

CRWV / NBIS 这类新云厂商是 NVDA 和 Mag4 之外的算力需求敞口，但不能简单当成 NVDA 替代品。结构性短缺时它们受益，问题在于资本结构、客户集中度、融资成本和现金流。回答时要把“需求强”与“公司财务能不能扛住”分开。

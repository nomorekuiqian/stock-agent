# Twitter KOL Module

KOL (Key Opinion Leader) 推文采集与存储模块，是 KOL 观点日报的数据底座（Phase 1：数据管道）。

## 用途

设计为定时采集配置好的可信金融博主 timeline，增量入库到 Insforge。后续日报生成和股票观点查询都从数据库读，不在用户请求时直接调用 TwitterAPI.io。GitHub Actions workflow `.github/workflows/kol-tweets-fetch.yml` 每小时触发 `fetch-configured-kols`。

## 数据流

```
TWITTER_KOL_ACCOUNTS (app/shared/twitter_kol_config.py, 当前 31 个 KOL)
  -> POST /api/twitter/fetch-configured-kols (cron endpoint; schedule configured externally)
  -> service.fetch_configured_kols()
       -> per KOL: start_fetch_run -> fetch_and_store_tweets -> finish_fetch_run
  -> Insforge tables: kol_tweets, twitter_fetch_runs
```

每个 KOL 独立 try/catch，单个失败不影响整批；同一批共享 `run_id` 便于排查。

## 关键文件

- `app/shared/twitter_kol_config.py` — 金融博主目录（`username` + `display_name`，当前 31 个 KOL）。位于 shared 是因为 `twitter_digest` 也要读
- `service.py` — TwitterAPI.io 客户端 + `fetch_configured_kols` 批量编排
- `db.py` — 调用 `kol-tweets` Edge Function（推文 + 运行记录）
- `router.py` — API 端点
- `models.py` — Pydantic 请求模型
- `../../edge_functions/kol-tweets.js` — Insforge Edge Function

## API 端点

| 端点 | 方法 | 认证 | 用途 |
|------|------|------|------|
| `/api/twitter/fetch-configured-kols` | POST | cron_secret | **批量采集**整个 KOL 目录（cron 主链路） |
| `/api/twitter/fetch-tweets` | POST | cron_secret | 单 KOL 时间线采集 |
| `/api/twitter/search-tweets` | POST | cron_secret | 单 KOL `advanced_search` 历史回填 |
| `/api/twitter/fetch-articles` | POST | cron_secret | 单 KOL 抓取文章全文 |
| `/api/twitter/fetch-runs` | GET | cron_secret | 列出最近 fetch 运行记录 |
| `/api/twitter/kol-accounts` | GET | user_token | 返回当前 KOL 目录 |
| `/api/twitter/tweets` | GET | user_token | 查询已存储推文 |
| `/api/twitter/stats` | GET | user_token | 推文统计信息（受 PostgREST 1000 行限制，为采样分布） |

## Insforge 数据表

`kol-tweets` Edge Function 操作三张相关表：

### `kol_tweets`（15 列）

| 字段 | 类型 | 说明 |
|------|------|------|
| `id` | TEXT PK | 推文 ID |
| `author_username` | TEXT NOT NULL | 博主 username |
| `text` | TEXT | 推文全文 |
| `tweet_type` | TEXT | original / quote / reply / article |
| `conversation_id` | TEXT | thread 归属会话 ID |
| `quoted_tweet_text` | TEXT | 被引用推文文本 |
| `in_reply_to_username` | TEXT | 回复对象 |
| `created_at` | TIMESTAMPTZ | 推文发布时间 |
| `like_count` | INT | 点赞数 |
| `retweet_count` | INT | 转推数 |
| `reply_count` | INT | 回复数 |
| `view_count` | INT | 浏览数 |
| `url` | TEXT | 推文链接 |
| `category` | TEXT | 蒸馏分类（阶段 2 回填） |
| `symbols` | JSONB | 股票 ticker 列表（如 `["NVDA"]`），未标注为 null |

索引：`(author_username, created_at DESC)`、`(conversation_id)`、`(category)`、`GIN (symbols)`

### `twitter_fetch_runs`

每次 cron 内每 KOL 一行：`run_id` / `status` / `pages_fetched` / `tweets_fetched` / `tweets_stored` / `tweets_skipped` / `reached_safety_window` / `error` / `started_at` / `finished_at`

### `kol_daily_digests`

由下游 `twitter_digest` 模块读写。当前 edge function 复用 `kol-tweets`:

- `upsert_digest`
- `get_digest`
- `get_latest_digest`

应用层和表列名一致: `macro_picks` / `industry_picks` / `stock_picks`。早期 V1.5 命名 (`bullish_picks` / `bearish_picks` / `neutral_analyses`) 已迁移。

## Edge Function actions

`POST`: `upsert_batch`、`update_category`、`update_categories_batch`、`list_batch`、`start_run`、`finish_run`、`upsert_digest`

`GET`: `list`、`stats`、`get`、`list_runs`、`get_digest`、`get_latest_digest`

## 配置

### KOL 目录 (`app/shared/twitter_kol_config.py`)

`KolAccount` TypedDict 只有两个字段：`username` + `display_name`。目前 31 个 KOL。

`enabled_kols()` 返回全部目录；`validate_catalog()` 校验重复和缺失 username。

### 环境变量

- `TWITTER_API_KEY` — TwitterAPI.io
- `CRON_SECRET` — cron 端点认证

## 采集策略

- **批量采集** (`fetch-configured-kols`): 默认 `max_pages_per_kol=1`、`safety_window_hours=3`、`include_articles=false`
- **去重**: tweet id 作为主键 upsert
- **过滤**: 纯转推被丢弃，原创 / 引用 / 回复保留
- **失败隔离**: 单 KOL 抛错不阻断其他 KOL

# Twitter KOL Module

KOL (Key Opinion Leader) 推文采集与存储模块,是 KOL 观点日报的数据底座(数据管道)。

## 用途

定时从 Twitter list 采集金融博主推文,增量入库到 Insforge。日报生成、股票观点查询、KOL 方法论蒸馏都从 DB 读,不在用户请求时直接调 TwitterAPI.io。Insforge `Cron - KOL Tweets Ingestion` 每小时经 `cron-trigger` 触发 `fetch-configured-kols`,随后同一 proxy job 调 `twitter-digest/enrich?window_hours=6`。旧 GitHub cron workflow 已删除。

**仅 list 路径**:旧的逐 KOL `user/last_tweets` 抓取已下线(每 KOL/小时强制计费 20 条历史推文,即使博主当时没发推)。所有 KOL 都从 Twitter list 同步到 `kol_accounts`,`source` 形如 `list:<list_id>`。

## 数据流

```
kol_accounts (Insforge, source=list:<id>)
  -> POST /api/twitter/fetch-configured-kols (hourly cron)
  -> service.fetch_configured_kols()
       -> per list: start_fetch_run -> fetch_list_timeline -> finish_fetch_run
  -> Insforge tables: kol_tweets, twitter_fetch_runs
```

每个 list 独立 try/catch,单个失败不影响其他 list;同一批共享 `run_id` 便于排查。

`fetch_list_timeline` 按时间窗口停(`page_oldest < now - lookback_hours`),不按页数。
默认 `lookback_hours=1.5h` 给小时级 cron 留 30min cron drift 余量。

### 方法论蒸馏

`POST /api/twitter/extract-methodology` 请求体：

```json
{
  "username": "qinbafrank",
  "category": "stock_analysis",
  "methodology_version": "current",
  "limit": 2000
}
```

流程：

1. `db.list_tweets_by_category()` 按 `category` 分页读取该 KOL 的推文（Edge Function `list` 单页最多 100 条）。
2. `methodology_extractor.py` 使用 `gemini-3.1-pro-preview` 和 `CategoryMethodology` schema 提取结构化方法论。
3. 每条 evidence 必须包含 `tweet_id` 和源推文连续原文 quote；保存前会自动尝试修复省略号/轻微改写，并再次校验 quote 是否存在于源语料。
4. 输出到 `methodologies/<username>/<category>.yaml`，审阅材料写入 `methodologies/<username>/extraction_log/`。旧 qinbafrank 抽取产物已清理；当前 Frank 对话产品使用 `kol_research` + skill 资产，不再走 `/api/twitter/methodology-chat*`。

## Insforge 数据表

`kol-tweets` Edge Function 操作四张表:

### `kol_accounts`

| 字段 | 说明 |
|---|---|
| `username` (PK) | Twitter handle (lowercase) |
| `display_name` | 人类可读名字 |
| `source` | `list:<list_id>`,标识来自哪个 Twitter list |
| `enabled` | 软删除标志 |
| `followers` / `bio` | 同步时回填 |
| `added_at` / `last_synced_at` | 时间戳 |

`sync_kol_list` 同步时:list 新成员 upsert,移出 list 的成员 `enabled=false`。

### `kol_tweets`

| 字段 | 说明 |
|---|---|
| `id` (PK) | 推文 ID |
| `author_username` | 博主 username |
| `text` | 推文全文 |
| `tweet_type` | original / quote / reply |
| `conversation_id` | thread 归属会话 ID |
| `quoted_tweet_text` | 被引用推文文本 |
| `in_reply_to_username` | 回复对象 |
| `created_at` | 推文发布时间 |
| `like_count` / `retweet_count` / `reply_count` / `view_count` | 互动数 |
| `url` | 推文链接 |
| `media` | JSONB 数组；保存 TwitterAPI.io `extendedEntities.media` 提取出的图片/视频 metadata（type/source_url/expanded_url/width/height 等）。图片文件本身如需归档应放 Storage，表内只保存 metadata |
| `content_parts` | JSONB 数组；按顺序保存完整正文组成部分：tweet_text、quoted_tweet_text、image_text。图片 OCR/vision 文本在这里作为正文扩展参与后续分析 |
| `canonical_text` / `canonical_status` / `canonical_hash` | canonical enrichment 输出的完整推文正文、状态和内容 hash。`fetch_for_enrich` 与 vector indexing 优先使用该字段 |
| `canonical_extracted_at` / `canonical_extracted_model` | canonical 正文构建时间与 vision/OCR 模型标识 |
| `category` | 蒸馏分类(阶段 2 回填) |
| `symbols` | JSONB,enrichment 写入 `{quality, ticker_stances, sectors, ...}` |

索引:`(author_username, created_at DESC)`、`(conversation_id)`、`(category)`、`GIN (symbols)`

采访 reference 这类非本人账号发布的 X Article 会作为 persona corpus
入库: `author_username` 可设为 persona 以复用现有 cockpit/RAG 查询,
但必须在 `symbols.source_author_username` 保留原始发布者,避免用户界面误
归因。脚本默认写入 `content_type=sector_framework`、`quality=keep`,所以
不会被 enrichment 队列反复捞起。

### `twitter_fetch_runs`

每次 cron 内每 list 一行(synthetic username `_list:<list_id>`):
`run_id` / `status` / `pages_fetched` / `tweets_fetched` / `tweets_stored` / `tweets_skipped` / `reached_safety_window` / `error` / `started_at` / `finished_at`

### `kol_daily_digests`

由下游 `twitter_digest` 模块读写,详见 `../twitter_digest/.context.md`。

## 采集策略

- **list-only**:旧 manual 路径已下线(2026-05 cost cleanup),省 ~$75/月
- **时间窗口停**:`list_lookback_hours=1.5h`,翻到 oldest_tweet < now-1.5h 停;`list_safety_max_pages=50` 兜底
- **去重**:tweet id 作为主键 upsert
- **过滤**:纯转推被丢弃;`enabled_usernames` 白名单过滤,DB 软删除的成员即使还在 list 也会被丢
- **失败隔离**:单 list 抛错不阻断其他 list
- **catalog 缓存**:`get_enabled_kols` 5 分钟进程内缓存;`sync_kol_list` 调用后清缓存

## 添加新博主流程

1. 在 x.com 把博主加进任意 Twitter list
2. 调 `POST /api/twitter/sync-kol-list?list_id=<id>`(cron_secret),`kol_accounts` 自动 upsert
3. 下次整点 cron 自动抓取

# features/agent_runtime — Shared Agent Runtime

## Purpose

Owns the runtime substrate for chat-style agents: durable sessions, the
events timeline, context assembly with a central budget, and the HTTP
endpoint that lets the frontend restore a conversation from the durable
store rather than from `picker_conversations`.

The module is intentionally infrastructural — it does not host an LLM
agent of its own, and the architecture test
(`tests/test_architecture.py`) lists it under `SHARED_INFRA_FEATURES` so
the absence of router/agent/service is expected.

## Files

- `models.py` — dataclasses for `AgentRunRequest`, `SessionSnapshot`,
  `TranscriptEntry`, `RuntimeEvent`, `AgentRuntimeTurn`
- `db.py` — Python helpers around the `agent-sessions` Edge Function
  (`get_session`, `list_user_sessions`, `get_user_conversation_stats`,
  `append_entries`, `append_events`, `update_message_feedback`). Cursor
  pagination honors `(after_created_at, after_id)` only when BOTH are supplied;
  passing one alone is treated as no-cursor. Admin callers can pass
  `all_events=True` through `get_session` to retrieve the complete session
  timeline.
- `session_store.py` — `SessionStore` protocol + `InMemorySessionStore`
  (LRU-bounded), `AgentSessionsSessionStore`, `PickerConversationSessionStore`,
  `HybridSessionStore` (primary → picker only when no row exists →
  in-memory fallback only on primary write failure)
- `context.py` — `DefaultContextEngine`, `BudgetPlan`, `default_budget_plan()`,
  `ContextAssemblyRequest`
- `events.py` — payload builders (`context_snapshot_event`,
  `context_budget_truncated_event`, `tool_call_events`, `error_event`,
  `sync_ui_state`) + `append_turn_events` write helper
- `runtime.py` — `AgentRuntimeService` orchestration entrypoint
- `router.py` — `GET /api/agent-runtime/sessions/{session_id}` HTTP API
- `backend/app/edge_functions/agent-sessions.js` — Edge Function backing
  durable reads/writes; idempotency via three upsert lanes on
  `(client_event_id)`, `(turn_id, event_type, role)`, and plain insert.
  Batch appends assign server-side `created_at` offsets per event so restore
  order remains deterministic even when multiple rows are written in the same
  millisecond and UUID ids are random.
  It also exposes internal-only Admin read actions:
  `list_user_sessions` (all sessions with visible messages for one user),
  `stats_by_user` (per-user runtime conversation/message aggregate), and
  `get&all=true` (complete event timeline for one session). `update_feedback`
  updates thumbs feedback columns on a single `assistant_message` row.
- `backend/migrations/u4a_agent_runtime_schema.sql` — additive schema for
  `agent_sessions` and `agent_session_events` (turn_id, client_event_id,
  client_ts columns + unique indexes + cursor index)
- `backend/migrations/u4b_agent_runtime_feedback.sql` — additive feedback
  columns on `agent_session_events`: `feedback_sentiment`,
  `feedback_reason`, `feedback_at`, `feedback_payload`

## Phase 1 status

Completed (the user-facing contract from
`docs/plans/active/agent-runtime-next-3-phases.md`):

- `turn_id` / `client_event_id` / `client_ts` propagated end-to-end. The
  Edge Function dedupes via three lanes; retrying the same `turn_id`
  cannot double-write user / assistant messages.
- `assistant_message` rows carry the current per-answer feedback state in
  `feedback_sentiment` (`1` / `-1` / `null`), `feedback_reason`, `feedback_at`,
  and `feedback_payload`. Research/KOL UI submits thumbs feedback through
  `POST /api/feedback`, which routes to `agent-sessions?action=update_feedback`.
  A submitted `sentiment: 0` clears the current row back to `null`, enabling
  users to cancel or overwrite accidental thumbs choices.
- `SessionSnapshot` exposes `transcript`, `metadata`, `ui_state`,
  `summary`, and a `source` tag (`agent_sessions`, `agent_sessions_empty`,
  `agent_sessions_missing`, `picker_conversations`, `request_history`,
  `memory`). `metadata.session_exists` short-circuits the picker fallback
  so a brand-new runtime session never imports a legacy conversation's
  messages.
- `ContextAssemblyRequest` accepts an optional `SessionSnapshot`,
  `BudgetPlan`, `prefix_sections`, and `content_renderer`. Engine reads
  history from `session.transcript` when available and only falls back to
  `request.history` if no transcript was loaded.
- `BudgetPlan` is wired through both feature agents
  (`default_budget_plan()` is called inside
  `screener.research_agent.ResearchAgent.assemble_prompt_context` and
  `kol_research.agent._prepare_runtime_context`). Per-section
  truncations land in `assembled.metadata.truncated_sections`; if any
  section was reduced, both agents emit a `context_budget_truncated`
  event alongside the usual `context_snapshot`.
- `AgentRuntimeService.prepare_turn()` preserves feature-provided
  `prefix_sections` and `content_renderer` when assembling context, so
  callers can inject rich right-panel content and stable prompt prefaces
  without losing them at the runtime boundary.
- Edge Function cursor uses `(created_at, id)` as a two-tuple,
  over-fetches by 20 rows, then post-filters so the boundary event is
  never re-delivered. Response carries two cursors: `cursor` advances on
  any event and `messages_cursor` advances only on
  `user_message` / `assistant_message`.
- `GET /api/agent-runtime/sessions/{session_id}` exposes the durable
  store to the frontend. `agent_id` is constrained to
  `{research_agent, kol_research_agent}`. Missing sessions return 200 +
  empty shape so callers can cleanly fall through to
  `api.screener.conversations.get(...)`.
- Admin user detail reads Agent conversation lists and expanded details from
  `agent_sessions` / `agent_session_events`. `picker_conversations` is no
  longer used for the Admin user-detail conversation drawer.
- Frontend (`frontend/src/app/research/page.tsx::handleLoadConversation`)
  calls picker_conversations first to read the research-specific extras,
  infers `agent_id` from `picker.data.persona_username`, then queries the
  runtime endpoint. If the picker row is unavailable, it first tries
  `research_agent`, then the alternate `kol_research_agent`; runtime metadata
  can restore `persona_username` and flip the loaded conversation back into
  KOL mode. Runtime owns the message list and `ui_state`; picker keeps
  `accumulated_filters` / `candidates` / `recommendations` /
  `funnel_steps` / `kol_chunks` / `persona_username` (none of which the
  runtime tracks yet).
- Feature flags are now distinguishable:
  - `AGENT_RUNTIME_REQUEST_HISTORY=primary` — agent sees `[]` when the
    runtime session has no transcript. Use to A/B test "frontend stops
    sending history".
  - `AGENT_RUNTIME_REQUEST_HISTORY=fallback` (default) — agent falls
    back to `req.history` when the runtime session has no transcript.
  - `AGENT_RUNTIME_REQUEST_HISTORY=disabled` — `req.history` is dropped
    at the runtime boundary regardless of session state.
  - `NEXT_PUBLIC_AGENT_RUNTIME_SEND_HISTORY=false` — frontend stops
    attaching the compact history to chat requests.

## Data Flow

```text
frontend turn
  -> POST /api/research/chat/stream  (session_id, turn_id, [history?])
       -> AgentRuntimeService.load_session()
            -> agent_sessions (Edge Function)
            -> picker_conversations fallback (only if no agent_sessions row)
            -> InMemorySessionStore (last resort, primary write failure only)
       -> ResearchAgent.assemble_prompt_context()
            -> ContextEngine.assemble(BudgetPlan, session, content_renderer)
       -> ADK runner
       -> AgentRuntimeService.complete_turn()
            -> append_events(user_message, assistant_message)
       -> events.append_turn_events([context_snapshot, tool_calls,
                                     context_budget_truncated?])
  -> picker save (legacy compatibility for accumulated_filters etc.)

frontend reload
  -> handleLoadConversation()
       -> api.research.conversations.get()   (picker; rich state, may fail)
       -> api.agentRuntime.getSession()      (durable; message list + ui_state)
       -> if picker missing, try alternate agent_id before falling back
       -> merge: runtime wins on messages + ui_state, picker fills the rest
```

## Database Boundary

Migration is additive-only:

- Creates `agent_sessions`, `agent_session_events`.
- Adds `turn_id`, `client_event_id`, `client_ts` columns + unique indexes
  on `(user, agent, session, client_event_id)` and
  `(user, agent, session, turn_id, event_type, role)` for the message /
  context_snapshot / error event types.
- Adds per-answer feedback columns to `agent_session_events` via
  `u4b_agent_runtime_feedback.sql`; these columns are only meaningful for
  `event_type = 'assistant_message'`.
- Adds cursor index `(user, agent, session, created_at, id)`.
- Never `ALTER` / `DROP` / writes existing production tables.
- Does not touch `picker_conversations`; that store remains owned by
  the existing UI save flow.

## Gotchas

- `InMemorySessionStore` is the third-tier fallback. `HybridSessionStore`
  only writes there when the primary `append_entries` returns falsy or
  raises — the happy path leaves it empty.
- A primary row that exists but has zero events signals "new runtime
  session, do not import legacy history" via `metadata.session_exists`.
  `HybridSessionStore.load_session` honors that; any new alternative
  store implementation must keep the contract.
- `PickerConversationSessionStore` is read-only by design — the existing
  `/research` UI still owns picker writes. Don't make the runtime write
  picker rows.
- `agent_id` allowlist on the restore endpoint is intentional. Adding a
  new chat-style agent requires updating
  `_ALLOWED_AGENT_IDS` in `router.py` (and the corresponding frontend
  `inferredAgentId` branch in `research/page.tsx`).
- BudgetPlan caps land in `assembled.metadata.truncated_sections`. If
  you add a new prompt section, also add an allocation key in
  `default_budget_plan()` — otherwise `section_limit()` falls back to
  the global soft limit, which is usually too generous.
- Durable restore ordering depends on `(created_at, id)`. Because event ids are
  UUIDs, Edge Function batch writes must not stamp every event with the exact
  same `created_at`; otherwise same-turn user / assistant messages can restore
  in arbitrary order.
- Cursor pagination requires both `after_created_at` and `after_id`. A
  half-cursor is intentionally rejected (HTTP 400 in `router.py`, no-op
  in `db.get_session`).
- Do not import from `backend/app/services` or `backend/app/models`;
  this feature uses the active `app/features` / `app/shared` layout.

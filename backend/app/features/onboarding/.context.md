# onboarding

Tracks whether each user has finished the post-signup 3-step flow + exposes the
daily lifecycle cron entry point.

## Routes (`/api/...`)

- `GET  /user/onboarding-status` — returns `{completed: bool}`. Used by the
  auth callback to decide whether to redirect a fresh sign-in to `/onboarding`.
- `POST /user/onboarding/complete` — marks `subscriptions.onboarding_completed_at = NOW()`
  for the authenticated user. Idempotent (returns existing timestamp if already set).
- `POST /cron/lifecycle/onboarding-pass` — `verify_cron_secret`-gated. Dispatches the
  14-day lifecycle email sequence by delegating to
  `app.features.subscription.lifecycle_scheduler.run_onboarding_pass`.

## Storage

All three new columns live on `public.subscriptions` (added in
`backend/migrations/subscriptions_lifecycle_state.sql`):

- `lifecycle_state` (JSONB, default `{}`) — `{onboarding_sent: {day_int: iso}, intro_sent_count, triggered_at}`
- `reactivation_state` (TEXT) — cohort_a / cohort_b / cohort_c / cold (Phase 3)
- `onboarding_completed_at` (TIMESTAMPTZ) — NULL means not done

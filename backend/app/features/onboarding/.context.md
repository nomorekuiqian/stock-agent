# onboarding

Tracks whether each user has finished the post-signup homepage Guided Tour.
The current flow is a 4-step spotlight tour over the real navigation
(`AI 研究助手 / 每日简报 / 投研 / 我的`) and prompts the user to add watchlist stocks
from the "我的" area.

Onboarding drip emails have been removed. `features/notification/onboarding.py`
is now a legacy no-op used only so old cron calls return disabled counters.

## Routes (`/api/...`)

- `GET  /user/onboarding-status` — returns `{completed: bool}`. Used by the
  auth callback and homepage tour to decide whether a fresh user should see
  `/?tour=1`.
- `POST /user/onboarding/complete` — marks `subscriptions.onboarding_completed_at = NOW()`
  for the authenticated user. Idempotent (returns existing timestamp if already set).

## Storage

Three columns on `public.subscriptions` (added in
`backend/migrations/subscriptions_lifecycle_state.sql`):

- `onboarding_completed_at` (TIMESTAMPTZ) — NULL means the in-app gate is not done
- `lifecycle_state` (JSONB, default `{}`) — legacy `onboarding_sent` values may
  exist from old drip sends, but current onboarding email cron no longer writes
  or sends anything
- `reactivation_state` (TEXT) — reserved for future re-engagement cohorts

## Related modules

- Legacy drip no-op: `app/features/notification/onboarding.py`
- Legacy cron endpoint: `POST /api/cron/onboarding-emails` (notification/router.py),
  returns `disabled=true` and sends no email
- Schedule: Insforge `Cron - Onboarding Drip`
  (`29f09615-aacd-4d3b-a31c-8d8bbae2df07`, `0 23 * * *`, via
  `cron-trigger` job `onboarding_drip`) may still trigger the no-op endpoint.
  The old GitHub cron workflow was deleted after migration.
- Contract: `docs/constraints/subscription-model.md`

# onboarding

Tracks whether each user has finished the post-signup 3-step in-app onboarding
gate (watchlist / preferences / etc.).

The actual onboarding **emails** (Day 1/3/7/11/14 drip) live in
`features/notification/onboarding.py` — see that module for the cron + templates.

## Routes (`/api/...`)

- `GET  /user/onboarding-status` — returns `{completed: bool}`. Used by the
  auth callback to decide whether to redirect a fresh sign-in to `/onboarding`.
- `POST /user/onboarding/complete` — marks `subscriptions.onboarding_completed_at = NOW()`
  for the authenticated user. Idempotent (returns existing timestamp if already set).

## Storage

Three columns on `public.subscriptions` (added in
`backend/migrations/subscriptions_lifecycle_state.sql`):

- `onboarding_completed_at` (TIMESTAMPTZ) — NULL means the in-app gate is not done
- `lifecycle_state` (JSONB, default `{}`) — `{onboarding_sent: {day_int: iso}}`
  used by `notification/onboarding.py::process_onboarding_emails` for idempotent
  drip sends
- `reactivation_state` (TEXT) — reserved for future re-engagement cohorts

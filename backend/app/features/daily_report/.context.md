# Market - 市场日报

## 功能概述

每日生成一份 AI 驱动的市场分析报告，面向美股散户投资者（偏重科技股）。使用 Gemini 3.1 Pro 分析当日市场数据、新闻、经济日历，输出结构化中文报告。按日缓存，同一天重复请求直接返回缓存。

## API 端点

| 端点 | 方法 | 描述 | 认证 |
|------|------|------|------|
| `/api/market` | POST | 生成/获取当日市场报告 | 无 |
| `/api/market/latest` | GET | 只读获取当日缓存日报，无缓存返回 404 | 无 |
| `/api/market/reports` | GET | 历史日报列表 (分页: limit + offset) | 无 |
| `/api/market/reports/latest` | GET | 获取最新一篇日报 (不限日期) | 无 |
| `/api/market/reports/date/{date}` | GET | 按日期获取日报 (YYYY-MM-DD) | 无 |
| `/api/market/reports/{report_id}` | GET | 按 UUID 获取日报 | 无 |

**POST 请求参数**: `{ "force": false }` — `force=true` 强制重新生成

**GET /api/market/latest**: 无参数，纯读取当天缓存。适用于外部 agent 或服务拉取日报，不会触发 AI 生成。

**GET /api/market/reports**: 分页参数 `limit` (1-100, 默认 20) + `offset` (默认 0)。返回 `{ data, total, limit, offset }`。

**GET /api/market/reports/latest**: 与 `/api/market/latest` 不同，此端点返回数据库中最新一篇日报，不限于当天。

**响应结构**:
```json
{
  "indices": [{"name", "value", "change_percent", "change_unit?"}],
  "title": "15-30字中文标题",
  "summary": "2-3句摘要",
  "intro": "2-3段开场白",
  "news": {
    "headlines": [{"title", "fact_summary", "deep_analysis", "url"}],
    "briefs": [{"title", "summary", "analysis", "url"}]
  },
  "report_summary": [{"title", "content"}],
  "calendar": [{"date", "event", "analysis"}],
  "market_data": {},
  "from_cache": true,
  "report_id": "uuid",
  "timestamp": "ISO-8601"
}
```

## 数据流

```
POST /api/market
  |
  +-- 检查缓存 (DB 按日期查询, Pacific 时区)
  |   +-- 命中且当天 -> 直接返回
  |   +-- 未命中/force=true -> 生成新报告
  |
  +-- MarketAgent.analyze()
  |   +-- 并行获取: 市场数据 + 新闻 + 经济日历 + 财报日历
  |   +-- 加载最近 5 篇历史报告 (叙事连续性)
  |   +-- 数据清洗 (减少 45% token)
  |   +-- Gemini Flash 生成结构化报告
  |   +-- 后处理: article_id -> 真实 URL
  |
  +-- transform_market_data_to_indices() 转换前端格式
  +-- 保存到 DB (按日期 upsert)
  +-- 返回响应
```

| 文件 | 职责 |
|------|------|

## 关键业务逻辑

### Agent 指令核心规则
- **叙事连续性**: 如果有 previous_reports，需将今日分析放入过去一周的叙事脉络中
- **情绪校准**: 大涨时也要说明上涨何时可能停止；大跌时提供背景（如"距年内高点仅 3%"）
- **标题风格**: 像经济学人，不像小报。15-30 字，有观点但克制
- **新闻筛选**: headlines 2-4 条（必须是 CNBC/Bloomberg 级别大事件），briefs 8-12 条
- **输出语言**: 全中文

### URL 解析机制
Agent 输出的 `url` 字段可能是三种情况:
1. article_id（如 "5"）-> 映射回原始新闻 URL
2. 真实 URL -> 保留
3. 伪造 URL -> 清空，避免死链

### 缓存策略
- 按 Pacific 时区判断"今天"
- 同一天内只生成一次（除非 force=true）
- 缓存键: report_date (YYYY-MM-DD)

### 数据清洗 (_prepare_data_for_analyst)
- 新闻: 只保留 article_id, title, text, source, url, publishedDate
- 过滤垃圾新闻 (集体诉讼广告等)
- 过滤回顾性新闻 (`_is_retrospective_news`): 检测今天发布但报道过去事件的文章（如"亚马逊上月跌12%"），防止误导读者。通过正则匹配价格变动+过去时间框架、月度/周度总结等模式
- 日历: 删除冗余数字字段
- 市场数据: 删除 month_change 字段
- 效果: 减少约 45% token 消耗

### 新闻时效性双重防御
1. **预处理层** (`_is_retrospective_news`): 正则过滤明显的回顾性文章（标题/正文前300字）
2. **Agent 指令层**: ANALYST_INSTRUCTION 中的"时效性验证"规则，要求 AI 判断每条新闻的事件是否发生在今天/昨天

## 注意事项

- indices 转换中，国债利率变动用 bps 而非百分比
- 响应中的换行符需要做 double-escaped newline 修复
- Agent 是单例模式，模块生命周期内复用同一个 MarketAgent 实例
- DB 操作全部走 Edge Function HTTP 调用，不是直接 SQL

# Screener - Stock Screener 数据层

## 模块概述

专业级 Stock Screener，覆盖全美市场 ~3,680 只可交易股票（市值 > $100M 的普通股，已过滤 OTC），提供 65+ 维度数据（基本面 + 技术面 + 增长 + 分红 + 分析师），支持 8 种预筛选策略 + 自然语言 Agent。

## 产品愿景

为用户提供快速、专业的股票筛选工具，通过预定义策略（热门板块、资金异动、价值发现、高股息、动量、超跌优质）快速定位候选股票，未来支持自然语言自定义筛选。

## 架构

```
Cron (每日收盘后, ~5秒完成)
    |
    v
refresher.py -- tvscreener 一次调用获取 ~5,800 股票 x 65 字段, 过滤 OTC 后 ~3,680 只
    |
    v
db.py -- 写入 Insforge screener-universe-cache Edge Function
    |                    (3 个 cache key)
    v
filters.py -- 纯 Python 预筛选 (读缓存, 无 API 调用)
    |
    v
router.py -- POST /api/screener/filter -> 返回 20-30 只候选股
```

## 数据来源

- **tvscreener**: TradingView Screener API，一次调用获取全部数据
- 65 个原始字段 + 6 个派生字段 = 71 个维度
- 数据每日收盘后刷新，TTL 26 小时

## 缓存 Key

| Key | 内容 | 大小 |
|-----|------|------|
| `screener:universe` | 全部股票数据 list[dict] | ~4MB |
| `screener:sector_stats` | 板块聚合统计 | ~2KB |
| `screener:meta` | 元信息 (数量/刷新时间) | ~200B |

## 筛选策略

| 策略 | 逻辑 | 典型结果 |
|------|------|----------|
| `hot_sectors` | 板块均涨幅 top3 -> 板块内个股涨幅 | ~30 只 |
| `volume_surge` | 相对成交量 >= 2x + 放量上涨 | ~30 只 |
| `value_discovery` | PE 低于行业中位 + 52w低位 + ROE>10% | ~30 只 |
| `high_dividend` | 股息率 > 2% + 连续派息 + 派息率 < 80% | ~30 只 |
| `momentum` | 3月涨幅 top + RSI 50-70 + 上SMA50 | ~30 只 |
| `oversold_quality` | RSI < 35 + ROE > 15% + 分析师买入 | ~30 只 |
| `by_sector` | 指定板块内排序 | ~30 只 |
| `custom` | 结构化条件筛选 (预留 LLM) | 可变 |

## 数据字段 (65 原始 + 6 派生)

### 原始字段分类
- **Identity (4)**: name, sector, industry, beta_1y
- **Price & Performance (10)**: price, daily_change, weekly/monthly/3m/6m/ytd/yearly_change, high/low_52w
- **Valuation (7)**: market_cap, pe_ttm, pb_mrq, ps_fy, ev_ebitda_ttm, ev_mrq, peg_ttm
- **Profitability (6)**: gross/operating/net_margin, roe, roa, roic
- **Growth (8)**: revenue/eps/ebitda/fcf growth (TTM + quarterly + 5y)
- **Dividends (4)**: yield, payout_ratio, growth_years, payout_years
- **Earnings & Cash Flow (4)**: eps_ttm, net_income_fy, gross_profit_fy, fcf_margin
- **Balance Sheet (3)**: debt_to_equity, current_ratio, cash_equivalents
- **Volume (3)**: volume, avg_volume_30d, relative_volume
- **Shares (3)**: shares_outstanding, shares_float, float_pct
- **Analyst (5)**: target_price (avg/median/high/low), analyst_rating
- **Technical (14)**: rsi, macd/signal, sma20/50/200, ema20/50, atr, bb_upper/lower, adx, cmf, stoch_k

### 派生字段 (computed)
- `pct_from_52w_high`: 距52周高点百分比
- `position_52w`: 52周区间位置 (0=低点, 1=高点)
- `above_sma200` / `above_sma50`: 是否在均线上方
- `analyst_upside`: 分析师目标价上行空间 %
- `market_cap_tier`: small/mid/large/mega

## Agent 架构 (agent.py)

自然语言选股 Agent，基于 Google ADK LlmAgent，配备 3 个 FunctionTool：

| Tool | 功能 | 用途 |
|------|------|------|
| `execute_screener` | 执行筛选条件并返回匹配结果 | Agent 测试条件、查看结果数量和预览 |
| `get_field_distribution` | 获取字段分布统计 | Agent 了解数据分布以设置合理阈值 |
| `list_available_sectors` | 列出可用板块和计数 | Agent 探索板块选项 |

**工作流**: 用户自然语言 -> Agent 调用工具探索数据 -> 迭代调整条件 -> 输出 ScreenerQueryOutput (filters + summary)

**关键设计**:
- `_current_universe` 使用 `contextvars.ContextVar` 实现协程级隔离，每次 `parse()` 调用前 `.set()`，工具函数通过 `.get()` 读取数据
- Agent 是项目中第一个使用 FunctionTool 的 ADK Agent
- `output_schema=ScreenerQueryOutput` 确保最终输出结构化
- Router 拿到 Agent 输出后再执行一次 `filter_custom` 生成最终结果
- `execute_screener` 工具的 preview 中 `ticker` 字段从 universe `symbol` 字段提取（格式 `"NASDAQ:AAPL"` → `"AAPL"`）

## Research Agent 架构 (research_agent.py)

对话引导式投研 Agent，复用 agent.py 的工具和 ContextVar，面向新手用户友好对话。

**工作流**: 用户对话 -> Agent 理解偏好 -> 逐步缩小范围 -> 3-8 只推荐 + 理由

**关键设计**:
- 复用 `agent.py` 的 `execute_screener` / `get_field_distribution` / `list_available_sectors` 工具
- `RESEARCH_MODEL` 使用项目默认 `gemini-3.5-flash`。若前端再次出现
  `model_schema_error` / “AI 助手输出格式异常”，优先检查 ADK
  `output_schema=ResearchAgentOutput` 与模型结构化输出兼容性。
- 默认 Research chat 的 Gemini thinking level 固定为 `MINIMAL`，仍允许
  ADK 在流式响应中返回 thought summary 供前端展示。
- `recommendations` 输出经 `router.py` 三层符号校验：直接 ticker 匹配 → 带 exchange prefix 的 strip → 公司名称反查 → 模糊名称匹配
- Agent 指令明确要求 `recommendations.symbol` 使用 ticker 而非公司名称
- Agent 每轮输出 `title` 字段 (5-10 中文字)，用于对话持久化标题
- **Research Desk 集成**: 支持 `content_context` 参数注入当前查看的内容数据，Agent 可基于此回答问题。当前支持的 context type:
  - `stock`: 个股数据（行情/基本面/财报/技术面/近期新闻）。旧 `analyst_summary` 已移除，Agent 不能假设上下文里有分析师评级。
  - `daily_report`: 日报数据（标题/摘要/新闻/事件日历），Agent 切换为市场解读助手模式
  - `morning_report`: 盘前早报数据（市场脉搏/期货/全球市场/隔夜新闻/今日关注）
  - `twitter_digest`: 推特日报数据（headline/hot_tickers/ticker_theses/macro_threads/watchpoints）
  - `macro`: 宏观风险仪表盘数据（verdict/signal_lights/landscape/narrative/takeaway），Agent 切换为宏观分析助手模式
  - `brew`: 用户专属日报数据（持仓、事件、新闻和 summary content）
- **统一上下文预算**: 普通 Research Agent 的实际 LLM prompt 由
  `ResearchAgent.assemble_prompt_context()` 通过共享
  `features.agent_runtime.ContextEngine` 生成，而不是在 router 里另拼一份。
  当前日期、自选股、筛选条件、universe size 作为 `prefix_sections` 注入；
  对话历史优先来自 runtime session transcript，必要时才 fallback 到
  request history；右侧 Research Desk 内容通过富文本 `content_renderer`
  进入 `content_context` 预算分区。`router.py` 写入的
  `context_snapshot` 与传给 ADK runner 的 prompt 来自同一个
  `AssembledContext`，避免「记录的上下文」和「模型实际看到的上下文」漂移。
- **Agent 导航**: Agent 输出 `navigate` 字段可驱动前端右侧面板切换到个股研究视图、日报视图或宏观仪表盘
- `ResearchAgentOutput` 新增 `navigate` 字段 (type: stock|daily_report|macro + params + reason)
- **`update_results` 安全默认**: `ResearchAgentOutput.update_results` 默认是 `false`，避免纯聊天或个股追问漏填字段时误清空筛选结果。`router.py::_postprocess_agent_output()` 在字段缺失时按 `bool(filters)` 推断：有 filters 就执行筛选，无 filters 就保留现有结果；只有显式 `filters=[] + update_results=true` 才表示清空筛选。
- **工具→导航回填**: `research_agent.py::_TOOL_NAVIGATE` 是工具名→navigate payload 的映射表（quote/news/fundamentals/technical 等 → stock；execute_screener/filter_by_tickers → screener；liquidity/sentiment/macro_risk → 各 macro 子页）。当 LLM 调用工具但未显式给出 `navigate` 时，`_select_auto_navigate()` 会按本轮主意图选一个最终目标：筛选更新（有 filters / screener 工具）优先回到 screener，纯个股/宏观/报告轮次才使用最后一个对应工具。`router.py::_postprocess_agent_output()` 还会在 `filters + update_results` 场景强制返回 `navigate.type=screener`，防止筛选轮次被后续 AMD/NVDA 之类的个股工具误切走。
- **SSE 错误分类**: `/api/research/chat/stream` 的 error event 会带 `code`（`context_too_long` / `model_schema_error` / `agent_timeout` / `agent_error`），前端据此显示更准确的失败提示。
- **Agent Runtime 记录**: `ResearchRequest.conversation_id` 会作为 durable runtime `session_id`。当已登录用户且请求带 `conversation_id` 时，`router.py` 会把普通 Research 回合写入 `agent_sessions` / `agent_session_events`，其中 `agent_id=research_agent`、`agent_sessions.metadata.agent_kind=research`。消息会写 `user_message` / `assistant_message`；上下文写 `context_snapshot`；SSE tool 事件汇总后写 `tool_call_completed`；错误写 `error`。runtime 现在是历史列表、可见消息、反馈和置顶状态的权威来源；`picker_conversations` 只保留 Research Desk 尚未迁移的 UI 业务状态。
- **日报讨论模式**: 当 `content_context.type == "daily_report"` 时，Agent 从选股助手切换为市场解读助手，解读新闻影响、分析市场动态，可通过 navigate 跳转到新闻中提到的个股
- **宏观讨论模式**: 当 `content_context.type == "macro"` 时，Agent 切换为宏观分析助手，解读信号灯（流动性/经济/通胀/情绪）含义、核心判断逻辑、对用户持仓的影响，默认 `update_results=false`

## 对话持久化 (research conversations)

- **Runtime 表**: `agent_sessions` / `agent_session_events`。非搜索历史列表默认从 `agent-sessions?action=list_user_sessions` 聚合，置顶状态保存在 `agent_sessions.metadata.is_pinned/pinned_at`。
- **Picker 兼容表**: `picker_conversations` (id, user_id, title, data JSONB, message_count, created_at, updated_at)，用于完整 Research Desk UI 状态保存/恢复和正文搜索兼容。
- **Edge Functions**: `agent-sessions` (runtime list/pin/events) + `picker-conversations` (UI state CRUD/search)
- **DB 层**: `conversation_db.py` (list 聚合 runtime + picker legacy fallback / get / create / update / delete)
- **认证契约**: `/api/research/conversations*` 全部使用 `verify_user_token`。匿名或 token 验证失败必须返回 401，不能返回空列表或静默 skip；否则前端会把临时 auth 失败误缓存成“没有历史对话”。
- **列表搜索**: `/api/research/conversations?search=` 仍依赖 `picker_conversations.data.messages` 扫描当前用户最近最多 1000 条 conversation，按 title 和正文做多词包含匹配，再按 `offset/limit` 切页；返回会带 `search_matches`（最多 3 条 title/user/assistant 命中片段）。搜索结果会合并 runtime pin metadata，确保同一对话的置顶状态一致。
- **置顶排序**: 非搜索历史列表按 runtime 聚合结果排序：`is_pinned DESC, pinned_at DESC, updated_at DESC`；picker-only 旧对话只作为 legacy fallback 追加。置顶状态通过 `PATCH /api/research/conversations/{id}/pin` 更新到 `agent_sessions.metadata`，请求可带 `agent_id` 精确定位 `research_agent` 或 `kol_research_agent`，不会写 picker，也不会把置顶/取消置顶误算作最近聊天更新。若旧 picker-only 对话还没有 runtime session，首次置顶会在 `agent_sessions` 创建最小 metadata row（保留原 title/message_count/created_at/updated_at），让后续列表排序仍由 runtime metadata 驱动；取消置顶后该无事件 session 不再进入 runtime list，旧 picker row 会以未置顶状态回到 legacy fallback。
- **保存时机**: 前端在每轮 `/api/research/chat/stream` 响应后异步调 POST/PUT，第一轮创建、后续更新；`/api/screener/pick` 仅保留兼容旧调用。
- **data JSONB**: 完整对话状态 (messages, accumulated_filters, candidates, recommendations, funnel_steps)
- **title**: Agent 每轮生成，反映当前投研方向
- **Runtime sidecar**: `/api/research/chat/stream` 仍由前端保存完整 JSON 状态到
  `picker_conversations`。新对话第一轮会先由前端预分配 UUID 作为
  `conversation_id` 传给后端，保存 conversation 时也使用同一个 id。后端只在有
  稳定 `conversation_id` 时写 `agent_sessions` / `agent_session_events`，避免创建
  无法关联 UI 对话的随机 runtime session。conversation create/update 会把
  `active_content` / `content_stack` 同步到 `agent_sessions.metadata.ui_state`，
  并写一条 `ui_navigation` event。

## 注意事项

- tvscreener 是同步库，需要 `asyncio.to_thread()` 包装
- universe 数据 ~4MB，单次 DB 写入需要足够超时 (30s)
- filter 端点应 < 200ms (纯内存操作)
- `screener_universe_cache` 表需要在 Insforge 中手动创建

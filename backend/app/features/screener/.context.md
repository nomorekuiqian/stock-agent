# Screener - Stock Screener 数据层

## 模块概述

专业级 Stock Screener，覆盖全美市场 ~5,800 只股票（市值 > $100M 的普通股），提供 65+ 维度数据（基本面 + 技术面 + 增长 + 分红 + 分析师），支持 6 种预筛选策略。

## 产品愿景

为用户提供快速、专业的股票筛选工具，通过预定义策略（热门板块、资金异动、价值发现、高股息、动量、超跌优质）快速定位候选股票，未来支持自然语言自定义筛选。

## 架构

```
Cron (每日收盘后, ~5秒完成)
    |
    v
refresher.py -- tvscreener 一次调用获取 5,800+ 股票 x 65 字段
    |
    v
db.py -- 写入 Insforge screener-universe-cache Edge Function
    |                    (3 个 cache key)
    v
filters.py -- 纯 Python 预筛选 (读缓存, 无 API 调用)
    |
    v
router.py -- POST /api/screener/filter -> 返回 20-30 只候选股
```

## 文件说明

| 文件 | 职责 |
|------|------|
| `refresher.py` | tvscreener 数据获取 + 派生字段计算 + 缓存写入 |
| `filters.py` | 6 个预筛选策略 + 自定义筛选 (纯 Python, 无 API) |
| `models.py` | Pydantic 模型 (FilterRequest, FilterResult) |
| `db.py` | 缓存 CRUD (复制自 macro/cache/db.py) |
| `router.py` | 3 个 API 端点 |

## API 端点

| 方法 | 路径 | 认证 | 说明 |
|------|------|------|------|
| POST | `/api/screener/refresh` | Cron | 刷新全市场数据 (~5s) |
| GET | `/api/screener/status` | 无 | 缓存状态监控 |
| POST | `/api/screener/filter` | 无 | 执行筛选策略 |

## 数据来源

- **tvscreener**: TradingView Screener API，一次调用获取全部数据
- 65 个原始字段 + 6 个派生字段 = 71 个维度
- 数据每日收盘后刷新，TTL 26 小时

## 缓存 Key

| Key | 内容 | 大小 |
|-----|------|------|
| `screener:universe` | 全部股票数据 list[dict] | ~4MB |
| `screener:sector_stats` | 板块聚合统计 | ~2KB |
| `screener:meta` | 元信息 (数量/刷新时间) | ~200B |

## 筛选策略

| 策略 | 逻辑 | 典型结果 |
|------|------|----------|
| `hot_sectors` | 板块均涨幅 top3 -> 板块内个股涨幅 | ~30 只 |
| `volume_surge` | 相对成交量 >= 2x + 放量上涨 | ~30 只 |
| `value_discovery` | PE 低于行业中位 + 52w低位 + ROE>10% | ~30 只 |
| `high_dividend` | 股息率 > 2% + 连续派息 + 派息率 < 80% | ~30 只 |
| `momentum` | 3月涨幅 top + RSI 50-70 + 上SMA50 | ~30 只 |
| `oversold_quality` | RSI < 35 + ROE > 15% + 分析师买入 | ~30 只 |
| `by_sector` | 指定板块内排序 | ~30 只 |
| `custom` | 结构化条件筛选 (预留 LLM) | 可变 |

## 数据字段 (65 原始 + 6 派生)

### 原始字段分类
- **Identity (4)**: name, sector, industry, beta_1y
- **Price & Performance (10)**: price, daily_change, weekly/monthly/3m/6m/ytd/yearly_change, high/low_52w
- **Valuation (7)**: market_cap, pe_ttm, pb_mrq, ps_fy, ev_ebitda_ttm, ev_mrq, peg_ttm
- **Profitability (6)**: gross/operating/net_margin, roe, roa, roic
- **Growth (8)**: revenue/eps/ebitda/fcf growth (TTM + quarterly + 5y)
- **Dividends (4)**: yield, payout_ratio, growth_years, payout_years
- **Earnings & Cash Flow (4)**: eps_ttm, net_income_fy, gross_profit_fy, fcf_margin
- **Balance Sheet (3)**: debt_to_equity, current_ratio, cash_equivalents
- **Volume (3)**: volume, avg_volume_30d, relative_volume
- **Shares (3)**: shares_outstanding, shares_float, float_pct
- **Analyst (5)**: target_price (avg/median/high/low), analyst_rating
- **Technical (14)**: rsi, macd/signal, sma20/50/200, ema20/50, atr, bb_upper/lower, adx, cmf, stoch_k

### 派生字段 (computed)
- `pct_from_52w_high`: 距52周高点百分比
- `position_52w`: 52周区间位置 (0=低点, 1=高点)
- `above_sma200` / `above_sma50`: 是否在均线上方
- `analyst_upside`: 分析师目标价上行空间 %
- `market_cap_tier`: small/mid/large/mega

## Edge Function

- **名称**: `screener-universe-cache`
- **表**: `screener_universe_cache` (schema 同 `macro_data_cache`)
- **JS 备份**: `backend/app/edge_functions/screener-universe-cache.js`

## 依赖

- `tvscreener` - TradingView Screener Python 库
- `pandas` - DataFrame 处理
- `app.features.screener.db` -> Insforge Edge Function
- `app.core.deps.verify_cron_secret` - Cron 认证

## Cron 调度

- GitHub Actions: `0 23 * * 1-5` (UTC 23:00 = 美东 18:00, 收盘后)
- 调用: `POST /api/screener/refresh` + `X-Cron-Secret`

## 注意事项

- tvscreener 是同步库，需要 `asyncio.to_thread()` 包装
- universe 数据 ~4MB，单次 DB 写入需要足够超时 (30s)
- filter 端点应 < 200ms (纯内存操作)
- `screener_universe_cache` 表需要在 Insforge 中手动创建

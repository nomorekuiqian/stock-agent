# Memory / Feedback Module

## Purpose

Stores thumbs up/down feedback on non-runtime AI content and tracks suggestion
outcomes over T+7 windows. Provides `get_user_memory()` to aggregate thesis +
feedback + tracking into a compact memory block for agent injection.

## Architecture

- **router.py** — `POST /api/feedback`, `GET /api/suggestion-tracking/recent`
- **service.py** — `get_user_memory()` aggregation (<=1050 tokens)
- **db.py** — Insforge Edge Function wrapper (`memory` EF)
- **outcome.py** — Pure function `compute_outcome()` for T+7 evaluation
- **models.py** — Pydantic schemas

## Tables

- `ai_feedback` — user reactions on AI content
- `suggestion_tracking` — health check suggestion follow-ups

## Feedback Targets

`POST /api/feedback` accepts thumbs up/down for digest, health/action-bar content,
top events, and `research_agent_answer` (per-message feedback from `/research`
assistant and KOL assistant answers). `sentiment` uses `1` for thumbs up,
`-1` for thumbs down, and `0` to clear the user's previous choice.
Non-runtime targets are inserted into
`ai_feedback`. `research_agent_answer` is routed to the Agent Runtime store and
updates the matching `agent_session_events` `assistant_message` row using
`session_id` + `agent_id` + `turn_id` / `client_event_id` / `message_event_id`.
For runtime feedback, `sentiment: 0` sets `feedback_sentiment` and
`feedback_reason` back to `null`. The answer preview and UI metadata are stored in that row's `feedback_payload`.
Feedback failures remain non-blocking.

## Cross-feature Dependencies

- Reads `portfolio.db.list_portfolio()` for thesis data
- Memory block is consumed by health check and action bar agents

## Key Constraints

- All DB failures degrade gracefully (return empty, never crash)
- `get_user_memory()` total <= 1050 tokens (~2100 chars)
- Feedback POST always returns 200 (even if DB not deployed)
- All user-facing text in Chinese

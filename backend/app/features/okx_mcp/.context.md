# features/okx_mcp — OKX Context MCP Adapter

## Purpose

Isolated OKX-facing context/data adapter for TheMarketBrew. It lets OKX
Onchain OS / Agent Marketplace call TheMarketBrew capabilities through a small
paid HTTP surface without changing the production web app experience.

This module returns context and data only. It does **not** call the website chat
agents, does **not** generate final investment answers, and does **not** spend
TheMarketBrew LLM tokens. The external OKX/user agent is responsible for final
synthesis.

## Entry Point

Run the OKX service with:

```bash
uvicorn app.okx_main:app --host 0.0.0.0 --port 8000
```

`app.okx_main` is separate from `app.main`, so OKX x402 middleware and routes do
not affect the current production TheMarketBrew app unless this entry point is
deployed.

## Routes

```
GET  /api/okx-mcp/discovery        free capability/persona/data discovery
POST /api/okx-mcp/persona-context  paid persona methodology + evidence context
POST /api/okx-mcp/market-data      paid stock/market/news data envelope
```

Discovery stays public so OKX and external agents can inspect capabilities.
The paid routes can be protected either by the in-app OKX SDK middleware or by
an OKX reverse proxy. In both modes, access is authorized by OKX x402 payment,
not by TheMarketBrew account login.

## Files

- `models.py` — Pydantic schemas for the three-tool OKX surface.
- `service.py` — Persona selection, lens aggregation, optional Evidence Map and
  vector evidence hydration, and market data routing.
- `router.py` — FastAPI routes under `/api/okx-mcp`.
- `payment.py` — Optional OKX x402 SDK middleware registration. SDK imports are
  lazy and only run when `OKX_MCP_PAYMENT_ENABLED=true`.

## Reused Internal Capabilities

The module deliberately reuses the existing Market Lens data/material plane:

- `features.kol_research.mcp_materials` for promoted persona methodology roots
  and lens search.
- `features.kol_research.mcp_data` for stock, macro, calendar, report, and news
  data envelopes.
- `features.kol_research.cockpit` for Evidence Map tweet hydration.
- `features.vector.service.search` for optional vector corpus evidence.

`mcp_data` normally marks account auth as required. OKX responses rewrite the
transport auth metadata to `provider=okx_x402` and `account_required=false`;
the underlying data fetching logic is unchanged.

## Payment Env

Defaults keep payment disabled for local tests:

```text
OKX_MCP_PAYMENT_ENABLED=false
OKX_MCP_PAYMENT_MODE=sdk
OKX_MCP_NETWORK=eip155:196
OKX_MCP_PAY_TO_ADDRESS=0x...
OKX_MCP_PERSONA_CONTEXT_PRICE=$0.05
OKX_MCP_MARKET_DATA_PRICE=$0.03
OKX_MCP_MAX_TIMEOUT_SECONDS=300
OKX_API_KEY=...
OKX_SECRET_KEY=...
OKX_PASSPHRASE=...
OKX_BASE_URL=https://web3.okx.com
```

When `OKX_MCP_PAYMENT_ENABLED=true` and `OKX_MCP_PAYMENT_MODE=sdk`,
`payment.py` imports the OKX x402 SDK and protects only:

- `POST /api/okx-mcp/persona-context`
- `POST /api/okx-mcp/market-data`

Unpaid requests should receive HTTP 402 before business logic runs.

## Safety Contract

- Do not expose TheMarketBrew account/device auth through this module.
- Do not call `answer_kol_research` or `stream_kol_research`.
- Do not fabricate final advice fields; return context/data envelopes and
  section-level errors.
- Keep discovery public and cheap; keep paid endpoints idempotent/read-only.
- No direct buy/sell/add/reduce instructions or exact price targets in adapter
  authored text.

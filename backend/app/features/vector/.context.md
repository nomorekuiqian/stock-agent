# Vector - Generic Embedding and Retrieval

## Purpose

Generic infrastructure for document indexing, embeddings, vector storage, and semantic retrieval. It is intentionally not tied to KOL, stock, macro, or user-note use cases.

Business features should normalize their content into:

```text
source_type + source_id + content + metadata
```

Then call `features.vector.service.index_document()` or `POST /api/vector/index`.

## Flow

```text
normalized document
  -> chunk_document()
  -> embed_texts() via OpenRouter
  -> vector-store Edge Function
  -> vector_documents / vector_chunks in Insforge Postgres pgvector

query
  -> embed_query()
  -> vector-store?action=search
  -> match_vector_chunks RPC
  -> ranked chunks
  -> optional context assembly

exact/hybrid query
  -> vector-store?action=search_text
  -> search_vector_chunks_text RPC
  -> title/content/metadata keyword hits using the same source/user/metadata filters
```

## File Structure

| File | Purpose |
|---|---|
| `models.py` | Pydantic request/response models for indexing, search, and context assembly |
| `chunking.py` | Deterministic document chunking |
| `embeddings.py` | Embedding client and model selection |
| `db.py` | Insforge `vector-store` Edge Function access |
| `service.py` | Index/search/context orchestration |
| `kol_tweets.py` | KOL tweet document normalization and backfill helpers |
| `router.py` | FastAPI endpoints |

## API

| Endpoint | Auth | Purpose |
|---|---|---|
| `POST /api/vector/index` | cron/admin/nonprod | Index one document |
| `POST /api/vector/index-kol-tweets` | cron/admin/nonprod | Index recent KOL tweets |
| `POST /api/vector/search` | user token | Return top-k chunks |
| `POST /api/vector/context` | user token | Return top-k chunks plus LLM-ready context |
| `DELETE /api/vector/source/{source_type}/{source_id}` | cron/admin/nonprod | Delete indexed source |

## Storage Contract

The Edge Function expects:

- `vector_documents`
- `vector_chunks`
- RPC `match_vector_chunks`
- RPC `search_vector_chunks_text`

Current pgvector dimension is 1536, matching `openai/text-embedding-3-small`.

## Notes

- Rule filters should narrow the candidate set before vector similarity.
- `search_text` is an internal Edge Function action used by KOL hybrid
  retrieval. It is not exposed as a public router endpoint. Deploy
  `vector-store.sql` and `vector-store.js` together because the JS action calls
  the `search_vector_chunks_text` RPC.
- Keep source-specific facts in structured metadata whenever possible.
- LLM answers must cite retrieved chunks by source metadata; the vector layer only retrieves evidence.
- KOL tweets are indexed by `scripts/index_kol_tweets.py` as `source_type=kol_tweet`.
  Use `--authors` / `--author-usernames` and `--tweet-types` to scope backfills;
  the default tweet types are `original`, `quote`, `thread`, and `article`.
- KOL tweet embedding content prefers `kol_tweets.canonical_text` when present.
  `canonical_text` is built from ordered `content_parts`, so image OCR / vision
  extraction text is embedded as part of the tweet body instead of only being
  kept as media metadata. Vector metadata preserves `media_count`,
  `content_part_types`, `canonical_status`, `canonical_hash`,
  `canonical_extracted_at`, and `canonical_extracted_model` for auditability.
- zsxq (知识星球) exports are indexed by `scripts/index_zsxq_threads.py` as
  `source_type=zsxq_thread` for the `pandacircle` persona. One thread = one
  document (`source_id=topic_id`); the multi-author circle is pinned to one
  persona via `metadata.author_username="pandacircle"` with the real sub-author
  in `metadata.source_author_username`. Tier-0 deterministic enrichment
  (`content_type`, reused `tags`, dictionary-extracted `tickers`) is baked into
  the embedded text. Re-run with `--force` after re-export; `--dry-run` prints
  the selection/ticker distribution. The persona retrieves it because its
  `corpus_source_types=["zsxq_thread"]` (see `shared/kol_persona`).
- KOL reference articles may carry provenance fields inside `kol_tweets.symbols`:
  `persona_username`, `source_author_username`, `source_kind`,
  `source_tweet_id`, `source_url`, `article_id`, and `article_title`.
  `features.vector.kol_tweets` and `scripts/index_kol_tweets.py` preserve these
  fields in vector metadata and include `key_claim` as the fallback summary.
- When re-indexing one corrected KOL reference, delete the old
  `(source_type, source_id)` first or use `scripts/backfill_x_article_reference.py
  --force-index`; otherwise older chunks with a different content hash can
  remain alongside the new document.

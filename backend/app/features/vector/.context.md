# Vector - Generic Embedding and Retrieval

## Purpose

Generic infrastructure for document indexing, embeddings, vector storage, and semantic retrieval. It is intentionally not tied to KOL, stock, macro, or user-note use cases.

Business features should normalize their content into:

```text
source_type + source_id + content + metadata
```

Then call `features.vector.service.index_document()` or `POST /api/vector/index`.

## Flow

```text
normalized document
  -> chunk_document()
  -> embed_texts() via OpenRouter
  -> vector-store Edge Function
  -> vector_documents / vector_chunks in Insforge Postgres pgvector

query
  -> embed_query()
  -> vector-store?action=search
  -> match_vector_chunks RPC
  -> ranked chunks
  -> optional context assembly
```

## API

| Endpoint | Auth | Purpose |
|---|---|---|
| `POST /api/vector/index` | cron/admin/nonprod | Index one document |
| `POST /api/vector/search` | user token | Return top-k chunks |
| `POST /api/vector/context` | user token | Return top-k chunks plus LLM-ready context |
| `DELETE /api/vector/source/{source_type}/{source_id}` | cron/admin/nonprod | Delete indexed source |

## Storage Contract

The Edge Function expects:

- `vector_documents`
- `vector_chunks`
- RPC `match_vector_chunks`

Current pgvector dimension is 1536, matching `openai/text-embedding-3-small`.

## Notes

- Rule filters should narrow the candidate set before vector similarity.
- Keep source-specific facts in structured metadata whenever possible.
- LLM answers must cite retrieved chunks by source metadata; the vector layer only retrieves evidence.
- KOL tweets are indexed by `scripts/index_kol_tweets.py` as `source_type=kol_tweet`.
  Use `--authors` / `--author-usernames` and `--tweet-types` to scope backfills;
  the default tweet types are `original`, `quote`, `thread`, and `article`.
- KOL reference articles may carry provenance fields inside `kol_tweets.symbols`:
  `persona_username`, `source_author_username`, `source_kind`,
  `source_tweet_id`, `source_url`, `article_id`, and `article_title`.
  `features.vector.kol_tweets` and `scripts/index_kol_tweets.py` preserve these
  fields in vector metadata and include `key_claim` as the fallback summary.
- When re-indexing one corrected KOL reference, delete the old
  `(source_type, source_id)` first or use `scripts/backfill_x_article_reference.py
  --force-index`; otherwise older chunks with a different content hash can
  remain alongside the new document.

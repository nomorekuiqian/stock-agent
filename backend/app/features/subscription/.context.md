# Subscription - 邮件订阅与推送

## 功能概述

多频道邮件订阅系统，管理日报、周报和个性化摘要的邮件推送。集成 Resend API 处理受众管理、联系人 CRUD 和广播发送。包含 HTML 邮件模板渲染、欢迎邮件、AI Newsletter 生成等功能。邮件发送/广播/预览端点已拆分到 `notification/` 模块。

## API 端点

> 邮件发送/广播/预览端点已迁移到 `notification/` 模块，本模块只保留订阅状态管理端点。

| 端点 | 方法 | 描述 | 认证 |
|------|------|------|------|
| `/api/subscriptions/{channel}/subscribe` | POST | 订阅频道 | 无 |
| `/api/subscriptions/{channel}/unsubscribe` | POST | 取消订阅 | 无 |
| `/api/subscriptions/{channel}/status` | GET | 查询订阅状态 | 无 |
| `/api/subscriptions/{channel}/update` | PUT | 更新元数据 (symbols等) | 无 |
| `/api/subscriptions/{channel}/subscribers` | GET | 列出全部订阅者 | X-Cron-Secret |
| `/api/subscriptions/{channel}/broadcast` | POST | 广播推送到全部订阅者 | X-Cron-Secret |
| `/api/subscriptions/sync-user` | POST | 同步网站用户到 Resend | 无 |

## 数据流

### 订阅流程 (含欢迎邮件)
```
POST /api/subscriptions/{channel}/subscribe
  |
  +-- subscribe_with_welcome(channel, email, metadata)
  |   +-- Contacts.create() 尝试创建
  |   |   +-- 成功 -> is_new=true
  |   |   +-- "already exists" -> Contacts.update(), is_new=false
  |
  +-- if channel==daily_report AND is_new:
      +-- send_welcome_email() 发送欢迎邮件
```

### 频道广播流程 (subscription router)
```
POST /api/subscriptions/{channel}/broadcast (X-Cron-Secret)
  |
  +-- daily_report: 生成/缓存日报 -> email_service.broadcast_daily_report()
  +-- personal_digest: email_service.broadcast_personal_digests(max_concurrent=5)
  |   Phase 1: 并发生成 (5路) -> Phase 2: batch 发送 -> Phase 3: 失败用户自动重试
  +-- weekly_report: weekly_db.get_latest_report() -> email_service.broadcast_weekly_report()
```

> 早报广播已迁移到 `POST /api/morning/broadcast`（morning_report/router.py），使用 daily_report 受众。

> 日报/周报的独立发送、预览、测试端点在 `notification/` 模块。

## 依赖关系

**外部服务**:
- `resend` — 邮件发送 (Audiences/Contacts/Broadcasts API)
- Resend API Key: `RESEND_API_KEY`

**内部依赖**:
- `features/daily_report/` — MarketAgent (日报生成, lazy import)、market db (报告查询)
- `features/macro/weekly/` — weekly db (周报查询, lazy import, broadcast 端点用)
- `features/morning_report/` — MorningReportAgent (早报生成, lazy import)、morning db (报告查询)
- `features/brew/` — DigestAgent (个性化摘要生成, 通过 email_service 间接依赖)

**环境变量**: RESEND_API_KEY, GOOGLE_API_KEY, FRONTEND_URL, ENVIRONMENT, CRON_SECRET

## 关键业务逻辑

### 三个订阅频道
| 频道 | 受众名 | 需要认证 | 额外元数据 |
|------|--------|----------|-----------|
| `daily_report` | MarketBrew Daily | 否 | first_name |
| `personal_digest` | Personal Digest Daily | 是 | first_name, user_id |
| `weekly_report` | MarketBrew Weekly | 否 | first_name |

### Resend 元数据存储
- Resend Contacts 没有自定义字段
- 使用 `last_name` 字段存储 JSON 编码的元数据 (user_id, symbols 等)
- 读取时解析 JSON，写入时序列化

### 限流
- Resend API: 2 请求/秒
- `_rate_limit_wait()` 强制 550ms 间隔
- 应用于所有 Resend 操作

### 6 种邮件模板
1. **日报邮件** — 市场指数 + 新闻 + 日历 + 总结 + 反馈按钮
2. **早报邮件** — 期货 grid + 全球市场 + 隔夜新闻 + 今日焦点 + 总结
3. **个性化摘要** — 持仓股票 + 过滤新闻 + 日历 + 总结
4. **欢迎邮件** — 创始人故事 + 功能介绍卡片
5. **验证邮件预览模板** — 账号激活 / 6 位验证码 / 深色头图 + emerald CTA
6. **Newsletter** — 纯文本格式，Markdown 支持

### 反馈链接
邮件底部嵌入反馈链接: `{frontend_url}/feedback?report_date=X&email=X&rating=satisfied`

## 注意事项

- email_service.py 已拆分为三文件：`email_styles.py`（样式常量）→ `email_templates.py`（渲染纯函数）→ `email_service.py`（发送编排）
- verification email 模板目前只作为预览模板存在，便于对齐品牌视觉；实际 auth 验证邮件仍由 Insforge 发送链路控制
- `EmailService` 保留一行代理方法（如 `_format_html_report`）以兼容测试中的 `svc._format_xxx()` 调用
- `email_templates.py` 的 `_FRONTEND_URL` / `_LOGO_URL` 通过 `EmailService` 的 property setter 同步
- router.py 在 broadcast 端点内使用 lazy import (MarketAgent, weekly_db) 避免启动时加载重依赖
- 个性化摘要广播使用 asyncio.Semaphore(5) 控制并发，避免压垮 API
- 欢迎邮件只在首次订阅 daily_report 时发送，已存在的联系人更新不触发
- Newsletter Agent 以 "Golden" 身份写作，温暖个人化的创始人风格
- 所有 Resend 操作都有限流保护 (550ms 间隔)

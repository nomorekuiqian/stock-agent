# Subscription - 邮件订阅与推送

## 功能概述

多频道邮件订阅系统，管理日报、周报和个性化摘要的邮件推送。集成 Resend API 处理受众管理、联系人 CRUD 和广播发送。包含 HTML 邮件模板渲染、欢迎邮件、AI Newsletter 生成等功能。邮件发送/广播/预览端点已拆分到 `notification/` 模块。

## API 端点

> 邮件发送/广播/预览端点已迁移到 `notification/` 模块，本模块只保留订阅状态管理端点。

| 端点                                       | 方法 | 描述                   | 认证                                          |
| ------------------------------------------ | ---- | ---------------------- | --------------------------------------------- |
| `/api/subscriptions/{channel}/subscribe`   | POST | 订阅频道               | 无                                            |
| `/api/subscriptions/{channel}/unsubscribe` | POST | 取消订阅               | 无                                            |
| `/api/subscriptions/{channel}/status`      | GET  | 查询订阅状态           | 无                                            |
| `/api/subscriptions/{channel}/update`      | PUT  | 更新元数据 (symbols等) | 无                                            |
| `/api/subscriptions/{channel}/subscribers` | GET  | 列出全部订阅者         | X-Cron-Secret                                 |
| `/api/subscriptions/{channel}/broadcast`   | POST | 广播推送到全部订阅者   | X-Cron-Secret                                 |
| `/api/subscriptions/sync-user`             | POST | 同步网站用户到 Resend  | 无                                            |
| `/api/subscriptions/preferences`           | GET  | 获取邮件订阅偏好       | Bearer Token (`verify_user_token_with_email`) |
| `/api/subscriptions/preferences`           | POST | 更新邮件订阅偏好       | Bearer Token (`verify_user_token_with_email`) |
| `/api/subscriptions/backfill-resend-names` | POST | 回填 Resend 联系人姓名 (one-time migration，`?dry_run=true`) | X-Cron-Secret |

## 数据流

### 订阅流程 (含欢迎邮件)

```
POST /api/subscriptions/{channel}/subscribe
  |
  +-- subscribe_with_welcome(channel, email, metadata)
  |   +-- Contacts.create() 尝试创建
  |   |   +-- 成功 -> is_new=true
  |   |   +-- "already exists" -> Contacts.update(), is_new=false
  |
  +-- if channel==daily_report AND is_new:
      +-- send_welcome_email() 发送欢迎邮件
```

### 频道广播流程 (subscription router)

```
POST /api/subscriptions/{channel}/broadcast (X-Cron-Secret)
  |
  +-- daily_report: 生成/缓存日报 -> email_service.broadcast_daily_report()
  +-- personal_digest: email_service.broadcast_personal_digests(max_concurrent=5)
  |   Phase 1: 并发生成 (5路) -> Phase 2: batch 发送 -> Phase 3: 失败用户自动重试
  +-- weekly_report: weekly_db.get_latest_report() -> email_service.broadcast_weekly_report()
```

> 早报广播已迁移到 `POST /api/morning/broadcast`（morning_report/router.py），使用 daily_report 受众。

> 日报/周报的独立发送、预览、测试端点在 `notification/` 模块。

## 关键业务逻辑

### Resend Segments (邮件偏好)

使用 Resend Segments (实为独立 Audiences) 过滤邮件投递:

- Morning Report (`RESEND_SEGMENT_MORNING`) — 早报 (Pro entitlement gated)
- Evening Report (`RESEND_SEGMENT_EVENING`) — 晚报 (免费，用户可自行开关)
- Weekly Report (`RESEND_SEGMENT_WEEKLY`) — 周报 (Pro entitlement gated)
- Daily Free CTA (`RESEND_SEGMENT_DAILY_FREE_CTA`) — 日报发送名单，收到升级 CTA（免费用户 + 试用用户）
- Daily Paid CTA (`RESEND_SEGMENT_DAILY_PAID_CTA`) — 日报发送名单，收到感谢 CTA（真付费用户）

**Segment 写入规则**: Morning/Weekly 的成员资格由 Stripe entitlements webhook 通过 `sync_resend_segments(email, sub)` 统一管理。Evening 是用户偏好，由 `update_email_preferences` 管理。日报 CTA 发送名单跟随 Evening 偏好：订阅日报时按 `cta_tier.is_real_paid_sub(sub)` 自动判定加入 Free CTA 或 Paid CTA；取消日报时从两个 CTA 发送名单移除。试用用户（`access_expires_at` 非空）即使有 entitlements，也进入 Free CTA。

**真付费判定** (`cta_tier.is_real_paid_sub`):
1. `is_lifetime=true` → paid（lifetime 用户始终看感谢 CTA）
2. `entitlements` 为空 → free（免费用户或试用过期）
3. `access_expires_at` 非空 → free（试用窗口内）
4. 否则（有 entitlements 且 `access_expires_at` 已被 `customer.subscription.created` webhook 清空）→ paid

**Resend 分组同步触发点**:
- Stripe `entitlements.active_entitlement_summary.updated` webhook（升级/降级）
- Stripe `customer.subscription.deleted` webhook（取消，作为冗余兜底）
- `payment.db.set_lifetime()`（lifetime 授予/撤销）
- `update_email_preferences()`（用户在 /preferences 页面切换偏好）
- `audit_cta_segments.py --apply`（drift audit 兜底，覆盖任何未通过上述路径的状态）

**运维脚本**:
- `scripts/backfill_cta_segments.py` — 一次性迁移现有订阅者到正确 CTA 分组（`--apply` 实际执行）
- `scripts/audit_cta_segments.py` — 每日 drift 审计 + 自动修（建议接入 cron）

**日报广播规则**: 生产环境 `broadcast_daily_report()` 发两次 Resend Broadcast：Free CTA 发送升级版 HTML，Paid CTA 发送感谢版 HTML。非生产环境和显式传入 `audience_id` 的测试发送保持单次 broadcast，避免测试收件人收到重复邮件。

`_is_pro_user()` 检查 `subscriptions.entitlements` 列是否包含 Pro feature，无 plan-based fallback。

### 三个订阅频道

| 频道              | 受众名                | 需要认证 | 额外元数据          |
| ----------------- | --------------------- | -------- | ------------------- |
| `daily_report`    | TheMarketBrew Daily   | 否       | first_name          |
| `personal_digest` | Personal Digest Daily | 是       | first_name, user_id |
| `weekly_report`   | TheMarketBrew Weekly  | 否       | first_name          |

### Resend 元数据存储

- Resend Contacts 没有自定义字段
- 使用 `last_name` 字段存储 JSON 编码的元数据 (user_id, symbols 等)
- 读取时解析 JSON，写入时序列化

### 限流

- Resend API: 2 请求/秒
- `_rate_limit_wait()` 强制 550ms 间隔
- 应用于所有 Resend 操作

### 6 种邮件模板

1. **日报邮件** — 市场指数 + 新闻 + 日历 + 总结 + 反馈按钮
2. **早报邮件** — 期货 grid + 全球市场 + 隔夜新闻 + 今日焦点 + 总结
3. **个性化摘要** — 持仓股票 + 过滤新闻 + 日历 + 总结
4. **欢迎邮件** — 创始人故事 + 功能介绍卡片
5. **验证邮件预览模板** — 账号激活 / 6 位验证码 / 深色头图 + emerald CTA
6. **Newsletter** — 纯文本格式，Markdown 支持

**推特日报邮件**: header 右上角优先显示 `digest_date`（`YYYY-MM-DD`），不显示生成时间或时区，避免 `generated_at` 的 UTC/Pacific 换算让业务日期看起来错位。

### 反馈链接

邮件底部嵌入反馈链接: `{frontend_url}/feedback?report_date=X&email=X&rating=satisfied`

## 注意事项

- email_service.py 已拆分为三文件：`email_styles.py`（样式常量）→ `email_templates.py`（渲染纯函数）→ `email_service.py`（发送编排）
- verification email 模板目前只作为预览模板存在，便于对齐品牌视觉；实际 auth 验证邮件仍由 Insforge 发送链路控制
- `EmailService` 保留一行代理方法（如 `_format_html_report`）以兼容测试中的 `svc._format_xxx()` 调用
- `email_templates.py` 的 `_FRONTEND_URL` / `_LOGO_URL` 通过 `EmailService` 的 property setter 同步
- router.py 在 broadcast 端点内使用 lazy import (MarketAgent, weekly_db) 避免启动时加载重依赖
- 个性化摘要广播使用 asyncio.Semaphore(5) 控制并发，避免压垮 API
- 欢迎邮件只在首次订阅 daily_report 时发送，已存在的联系人更新不触发
- Newsletter Agent 以 "Golden" 身份写作，温暖个人化的创始人风格
- 所有 Resend 操作都有限流保护 (550ms 间隔)

# Payment 模块

## 功能

Stripe 订阅支付 + Entitlements 权限管理。Stripe 是账单与新订阅真相源，Insforge `subscriptions.entitlements` 列是应用权限缓存。例外：老 Max 用户迁移为 Ultra 后，Stripe 仍按原 Max price 收费，但 app DB 的 `plan=ultra` + `ULTRA_FEATURES` 是应用内权限真相；active/trialing Stripe 同步不能把这类本地 Ultra 降级回 Max。

## 架构 (四层数据流)

```
Layer 1: Stripe (真相源)
  Customer → Subscription → Active Entitlements (Pro 7 / Max 11 / Ultra 12 个 feature)
       |
       | webhook + compensation sync
       v
Layer 2: Insforge subscriptions 表 (快速读缓存)
  entitlements JSONB 列 + 5 分钟内存 TTL
       |
       | 同一 webhook handler 顺序写
       v
Layer 3: Resend Segments (发送缓存)
  sync_resend_segments(email, entitlements) — 唯一写入点
       |
       v
Layer 4: Frontend EntitlementsContext
  has(feature) 判断，PaywallGuard requiredFeature
```

## API 端点

| 端点 | 方法 | 认证 | 描述 |
|------|------|------|------|
| `/api/payment/checkout-session` | POST | Bearer | 为新订阅创建 Stripe Checkout Session |
| `/api/payment/checkout-session/complete` | POST | Bearer | Checkout 回跳后校验 session_id 并同步 subscription/entitlements |
| `/api/payment/subscription-status` | GET | Bearer | 查询用户订阅状态 (`?fresh=true` 旁路 5 分钟缓存) |
| `/api/payment/me/entitlements` | GET | Bearer | 查询用户 feature entitlements (`?fresh=true` 旁路缓存并补偿同步 Stripe Subscription) |
| `/api/payment/portal-session` | POST | Bearer | 创建 Stripe 管理 Portal；传 `product` 时用于已有订阅升级确认 |
| `/api/payment/reconcile-expired-grants` | POST | Cron | 清理过期的非 Stripe grant (`access_expires_at`) |
| `/api/payment/webhook` | POST | Stripe Signature | Webhook 回调 |

## 文件结构

- `router.py` — 路由 + Webhook (checkout.session.completed / subscription.updated / subscription.deleted / entitlements.active_entitlement_summary.updated)
- `entitlements.py` — Entitlements Gateway (`has_entitlement` / `get_user_entitlements`，普通用户查 entitlements 列；lifetime 用户返回 MAX_FEATURES ∪ 存储 entitlements)
- `service.py` — Stripe API 封装 (checkout / portal / customer 管理 / entitlement reconciliation / expired grant reconciliation)
- `models.py` — Pydantic 模型
- `db.py` — subscriptions Edge Function 操作 + 缓存 + `get_subscription_by_customer`

## 依赖

- `stripe` SDK (同步调用通过 `asyncio.to_thread` 包装)
- Edge Function: `subscriptions` (get / get_by_customer / upsert)
- 环境变量: `STRIPE_SECRET_KEY`, `STRIPE_WEBHOOK_SECRET`, `STRIPE_PRO_PRICE_ID`, `STRIPE_MAX_PRICE_ID`, `STRIPE_ULTRA_PRICE_ID`

## 上线 Readiness

Qinbafrank Ultra 上线前需要用目标 Stripe 环境执行只读检查:

```bash
cd backend
source venv/bin/activate
python scripts/check_qinbafrank_stripe_readiness.py \
  --require-live \
  --webhook-url https://stock-agent-production.up.railway.app/api/payment/webhook
```

检查项包括:
- Ultra price 能通过 `STRIPE_ULTRA_PRICE_ID` 或 lookup key `themarketbrew_ultra_monthly` 找到 active price
- Stripe webhook endpoint 启用，并包含 `checkout.session.completed`、`customer.subscription.updated`、`customer.subscription.deleted`、`entitlements.active_entitlement_summary.updated`
- Billing Portal active configuration 允许 `subscription_update` 到 Ultra product/price，并且 `features.subscription_update.proration_behavior=always_invoice`，已有 Pro/Max 用户升级时依赖该配置避免并行订阅并立即按比例补差价

## 注意事项

- `entitlements.active_entitlement_summary.updated` 是权限变更的权威触发源；`checkout.session.completed`、`customer.subscription.updated`、`customer.subscription.deleted` 也会调用同一个 `sync_entitlements_from_stripe()` 作为补偿路径，避免 webhook 顺序/投递导致本地 entitlements 漂移
- entitlements webhook 检测档位后**补全为代码定义的完整 tier 集合**（Pro=`PRO_FEATURES` 7 项 / Max=`MAX_FEATURES` 11 项 / Ultra=`ULTRA_FEATURES` 12 项）再写入，不逐项照搬 Stripe：Stripe 不会把订阅创建后才挂到 product 的 feature 追溯给老订阅（`portfolio_management`/`twitter_digest` 后加，约 42 个老 Max 订阅曾缺失），故 tier 内容以代码 catalog 为权威（与 lifetime 一致），档位判定仍以 Stripe 为准
- `has_entitlement()` 对普通用户无 fallback — entitlements 列为空则无权限。Lifetime 用户例外：固定拥有 MAX_FEATURES，并 union row 上存储的 Ultra-only entitlements。
- Checkout success_url 指向 `/pricing/success?checkout=success&tier={pro|max|ultra}&product=...&next=...&session_id={CHECKOUT_SESSION_ID}`；成功页先调用 `/checkout-session/complete` 主动同步，再轮询 `subscription-status?fresh=true` + `me/entitlements?fresh=true`，确认目标 entitlement（Max=`ai_research_engine`，Ultra=`kol_pack_qinbafrank`）落库后才跳回 `next`
- Checkout/Portal return URL 优先使用发起请求的合法 `Origin`（`ALLOWED_ORIGINS` 或 `CORS_ALLOWED_ORIGIN_REGEX` 匹配），否则回退 `FRONTEND_URL`。这是为了 Vercel preview 多域名测试时回到同一个 origin，避免 localStorage/cookie 登录态在跨 preview 域名回跳后丢失；不能接受任意 origin，避免开放跳转。
- `POST /api/payment/checkout-session` 兼容 `tier=pro|max|ultra`；旧 `product=creator_max_qinbafrank` 仅作为兼容 alias 归一化为 `ultra`。当前只支持 `billing_interval=monthly`。
- 新付费用户走 Checkout；已有 Pro/Max 订阅用户升级更高 tier 时前端通过 `/portal-session` 打开 Stripe Billing Portal `subscription_update_confirm` flow，避免创建第二个订阅。升级 Portal session 会确保使用 `proration_behavior=always_invoice` 的 Billing Portal configuration，让 Stripe 立即按剩余周期补差价（例如 Max -> Ultra 只收剩余周期的 $10 差额比例，不重新收完整 $30）。后端 `/checkout-session` 也会兜底检查真实 paid subscription：同级/降级请求返回 409，升级请求返回 Portal URL（沿用 `checkout_url` 响应字段）而不是创建新的 Checkout Session。Portal flow 完成后回 `/pricing/success`，由 `subscription-status?fresh=true` 从 Stripe Subscription 刷新本地状态。
- `STRIPE_ULTRA_PRICE_ID` 仍应在生产环境显式配置；代码在该变量缺失时会尝试使用 Stripe Price lookup key `themarketbrew_ultra_monthly` 兜底解析 Ultra Price。
- `checkout.session.completed`、`customer.subscription.updated` 和 `subscription-status?fresh=true` 都会把 Stripe subscription price/metadata 解析成 app tier，并写入代码 catalog 定义的完整 entitlements；随后再尝试用 Stripe Active Entitlements 对齐，避免 entitlement webhook 延迟导致购买后长时间不可用。
- Stripe Portal 周期末取消时 Stripe 仍可能保持 `status=active`，但返回 `cancel_at`（部分 API 版本下 `cancel_at_period_end` 可能为 false）。`sync_subscription_from_stripe()` 会把 `cancel_at_period_end`、`cancel_at`、`canceled_at` 写入 `subscriptions` 并由 `/subscription-status` 返回，前端据此展示“已取消 / 权益有效至”。
- `kol_pack_qinbafrank` 出现在 Stripe Active Entitlements 时，后端归一化为 `plan=ultra` + `ULTRA_FEATURES`，即 Max 全部能力加 Qinbafrank 资料包权限。
- 老 Max 用户 DB 迁移为 Ultra 后，`sync_subscription_from_stripe()` 和 `sync_entitlements_from_stripe()` 都会在本地 row 已是 active/trialing Ultra 且 Stripe subscription 仍 active/trialing 时保留 `plan=ultra` + `ULTRA_FEATURES`。这允许用户继续按原 Max Stripe price 付费，但在 app 内拥有 Ultra benefits。Stripe 非 active / 空 active entitlement / subscription.deleted 仍会正常清空权限。
- Stripe entitlement reconciliation 写入 `plan/status/entitlements` 时会同时清理旧的 `access_expires_at`，避免历史 trial/admin grant 的过期字段拦住已付费用户
- 过期的非 Stripe grant 由读时 `access_expires_at` 判断兜底；`POST /api/payment/reconcile-expired-grants` 负责把已过期 grant 的 `plan/status/entitlements` 清理成 Free/expired，并同步 Resend；edge function 查询失败必须向 cron 暴露失败，不能当作空结果
- 新试用建议优先通过 Stripe Trial Subscription 实现，到期自动 cancel + webhook 清权限；旧的 `access_expires_at` grant 保留 reconciliation 兜底

## Lifetime 终身用户

`subscriptions.is_lifetime: true` 的用户绕开整条 Stripe 链路：
- webhook / reconciliation 进入函数后会跳过 `is_lifetime=true` 用户，不写库
- `has_entitlement()` / `get_user_entitlements()` 检测 is_lifetime=true 时返回完整 MAX_FEATURES，并 union row 上的 `entitlements`。因此 lifetime Max 迁移为 Ultra 时，只要 row 里有 `kol_pack_qinbafrank`，后端 gate 会放行。
- 开通工具：`python -m scripts.grant_lifetime <email>`（`--revoke` 取消）。撤销会清空 `plan/status/access_expires_at/entitlements`，避免旧 Max entitlements 残留。
- DB 字段：`is_lifetime BOOLEAN DEFAULT FALSE`
- 设计文档：`docs/plans/active/lifetime-max-system.md`

# Payment 模块

## 功能

Stripe 订阅支付系统。处理 Checkout Session 创建、订阅状态查询、Customer Portal、Webhook 事件。

## 数据流

```
前端 → POST /api/payment/checkout-session → Stripe Checkout → Webhook 回调 → upsert_subscription
前端 → GET /api/payment/subscription-status → db.get_subscription (带 5 分钟内存缓存)
前端 → POST /api/payment/portal-session → Stripe Customer Portal URL
```

## API 端点

| 端点 | 方法 | 认证 | 描述 |
|------|------|------|------|
| `/api/payment/checkout-session` | POST | Bearer | 创建 Stripe Checkout Session |
| `/api/payment/subscription-status` | GET | Bearer | 查询用户订阅状态 |
| `/api/payment/portal-session` | POST | Bearer | 创建 Stripe 管理 Portal |
| `/api/payment/sync` | POST | Cron | 手动同步 Stripe 订阅 (管理员恢复工具) |
| `/api/payment/webhook` | POST | Stripe Signature | Stripe Webhook 回调 |

## 文件结构

- `router.py` — 路由 + Webhook 事件处理 (checkout.session.completed / subscription.updated / subscription.deleted)
- `service.py` — Stripe API 封装 (get_or_create_stripe_customer / create_checkout_session / create_portal_session)
- `models.py` — Pydantic 模型 (CreateCheckoutRequest / CheckoutSessionResponse / SubscriptionStatusResponse / PortalSessionResponse)
- `db.py` — `subscriptions` Edge Function 操作 + 5 分钟内存缓存

## 依赖

- `stripe` SDK (同步调用通过 `asyncio.to_thread` 包装)
- Edge Function: `subscriptions` (GET action=get / POST action=upsert)
- 环境变量: `STRIPE_SECRET_KEY`, `STRIPE_WEBHOOK_SECRET`, `STRIPE_PRO_PRICE_ID`

## 注意事项

- Stripe API 2026+ 版本将 `current_period_start/end` 从 subscription 顶层移到 `items.data[*]`，`_get_period()` 已兼容两种格式
- `checkout.session.completed` Webhook 无 try/except，失败会让 Stripe 重试
- `subscription.deleted` 会检查用户是否有其他 active subscription，防止误降级
- `upsert_subscription` 成功后自动失效缓存

# invites feature context

## 功能概述

邀请码 + 自动试用系统。支持两种试用激活方式：

1. **邀请码兑换**：DM 驱动模型，小红书发内容 → 用户私信要码 → 创始人分享通用码 → 14 天 Max 试用
2. **注册即试用**：新用户注册后前端自动调用 auto-trial，无需邀请码即获得 14 天 Max 试用

- **通用共享码**：环境变量 `INVITE_CODES`（逗号分隔），如 `BREW2024`，用于小红书等渠道
- **无专属推荐码**：不存在每用户的 BREW-XXXXXX 码，简化实现

## 数据流

```
方式 A（已有码）：
  用户输入邀请码
    → POST /api/invites/redeem (Bearer)
    → 校验：是否在 INVITE_CODES 列表中
    → create_trial_subscription(source="invite_redemption")
    → 更新 invite_code 为实际码
    → 返回 { access_expires_at }

方式 B（申请码）：
  用户填写申请表（姓名、邮箱、原因）
    → POST /api/invites/request (public)
    → 发送邮件：INVITE_CODES 中第一个码
    → 返回 { success, message }

方式 C（注册即试用）：
  新用户注册完成后
    → POST /api/invites/auto-trial (Bearer)
    → create_trial_subscription(source="auto_registration")
    → 幂等：已有活跃订阅则跳过
    → Stripe 失败时 fallback 直写 DB（stripe_pending=true）
    → 返回 { success, access_expires_at, already_active }
```

## 核心函数

### create_trial_subscription(user_id, user_email, source, days=14)
共享试用创建逻辑，被 redeem_code() 和 auto-trial 端点调用：
- **幂等检查**：已有 active pro/max 订阅 → 直接返回成功
- **Stripe 创建**：Max Trial Subscription, missing_payment_method=cancel
- **Stripe 失败 fallback**：直写 DB, invite_code="AUTO_TRIAL", stripe_pending=true
- **DB 写入**：upsert_subscription 确保立即可用

## API 端点

| 路由 | 方法 | 认证 | 说明 |
|------|------|------|------|
| `/api/invites/redeem` | POST | Bearer | 兑换邀请码，返回 14天 Max 访问 |
| `/api/invites/auto-trial` | POST | Bearer | 注册即试用，自动创建 14天 Max 试用 |
| `/api/invites/request` | POST | Public | 申请访问表单，自动发邮件含邀请码 |

## 数据库字段（subscriptions 表）

```sql
invite_code TEXT           -- 兑换时使用的码，自动试用为 "AUTO_TRIAL"
access_expires_at TIMESTAMPTZ  -- 访问过期时间（试用 14 天）
```

## isPro 判断逻辑

```
isPro = plan in ('pro', 'max') AND status === 'active'
        AND (access_expires_at IS NULL OR access_expires_at > NOW())
```

付费订阅 `access_expires_at` 为 null，试用用户有具体日期。

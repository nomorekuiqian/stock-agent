# invites feature context

## 功能概述

邀请码系统，用于内测分发。DM 驱动模型：小红书发内容 → 用户私信要码 → 创始人分享通用码 → 14 天 Pro 访问。

- **通用共享码**：环境变量 `INVITE_CODES`（逗号分隔），如 `BREW2024`，用于小红书等渠道
- **无专属推荐码**：不存在每用户的 BREW-XXXXXX 码，简化实现

## 数据流

```
方式 A（已有码）：
  用户输入邀请码
    → POST /api/invites/redeem (Bearer)
    → 校验：是否在 INVITE_CODES 列表中
    → upsert subscriptions: plan=pro, status=active, access_expires_at=+14天
    → 返回 { access_expires_at }

方式 B（申请码）：
  用户填写申请表（姓名、邮箱、原因）
    → POST /api/invites/request (public)
    → 发送邮件：INVITE_CODES 中第一个码
    → 返回 { success, message }
```

## API 端点

| 路由 | 方法 | 认证 | 说明 |
|------|------|------|------|
| `/api/invites/redeem` | POST | Bearer | 兑换邀请码，返回 14天 Pro 访问 |
| `/api/invites/request` | POST | Public | 申请访问表单，自动发邮件含邀请码 |

## 数据库字段（subscriptions 表）

```sql
invite_code TEXT           -- 兑换时使用的码
access_expires_at TIMESTAMPTZ  -- Pro 访问过期时间（邀请码 14 天）
```

## isPro 判断逻辑

```
isPro = plan === 'pro' AND status === 'active'
        AND (access_expires_at IS NULL OR access_expires_at > NOW())
```

付费订阅 `access_expires_at` 为 null，邀请码用户有具体日期。

## 相关文件

- `models.py` — Pydantic 模型（RedeemInviteRequest/Response, AccessRequestInput/Response）
- `db.py` — 数据库操作（redeem_code，调用 payment.db.upsert_subscription）
- `router.py` — FastAPI 路由，`/request` 端点用 resend 发邮件
- `../payment/db.py` — upsert_subscription() 支持 invite_code + access_expires_at 字段

## 模块职责

**这是 `/for-you` 专属体系的"数据地基"。** 所有下游 Unit（Action Bar、体检、What-If、连线、月度复盘）都假设：
- 用户的持仓向量可读 → 这里
- 用户的画像可读 → 这里
- "持仓还新鲜" 戳可读 → `user_profiles.portfolio_confirmed_at`

**不属于这里的逻辑**（防误添加）：
- 体检 / scoring / drag 计算 → `features/brew/` 或未来 `features/health/`
- ETF 行业穿透 / `$CASH` 业务消费 → `features/portfolio/exposure_parser.py`（M4 才建）
- 数据网关 `$CASH` 防护 → `shared/data_tools/_cash_guard.py`

## 数据契约

### 端点（全部 `Depends(verify_user_token)`，user_id 从 token 取，**绝不**信任 query string）

| Method | Path | 用途 |
|---|---|---|
| GET    | `/api/portfolio`              | 当前用户持仓 + `effective_weight_pct` |
| PUT    | `/api/portfolio/bulk`         | 整组替换（onboarding / 录入页） |
| PATCH  | `/api/portfolio/{symbol}`     | 单行 upsert（thesis/target/conviction 追加） |
| DELETE | `/api/portfolio/{symbol}`     | 删一行 |
| PATCH  | `/api/portfolio/touch`        | 仅刷新 `portfolio_confirmed_at`（R-2） |
| GET    | `/api/profile`                | 画像（缺省返回默认值） |
| PUT    | `/api/profile`                | 更新画像 |

### `effective_weight_pct` 推断（service.py 纯函数）

```
if shares 非空 and price 可得:  weight = shares*price / Σ
elif weight_pct 非空:           weight = weight_pct / Σ(weight_pct_i)
else:                           weight = 1 / n_holdings
```

**单调性保证**：调用方传入的 rows 顺序与返回的 HoldingView 顺序一致。

### `HoldingView.price` / `market_value`（service.enrich_market_values）

`GET /api/portfolio` 在算完 weights 后会再跑 `enrich_market_values(holdings, prices_map)`，把当次 batch_quote 拿到的当前价回填进每行 `price` 字段；有 `shares > 0` 时同步算 `market_value = shares × price`。前端依赖 `price` 直接渲染"X 股 × $Y = $Z"，**不要让前端自己除 `market_value / shares`**（fractional shares + 现金行会踩坑）。

- `$CASH`：`price` 永远 `None`，`market_value` 取 `shares` 或 `cost_basis`。
- 报价 API 失败：`price` 留 `None`，`market_value` 保持 `None`（不崩，前端 fallback 到"成本 $X"）。

### 默认画像

`get_profile()` 遇空行不抛错，返回 `Profile(style="passive", horizon="long", risk_tolerance="moderate", notify_mode="events_only")`，这与 `inject_profile()`（M2）的兜底一致。

## 与下游的契约

- **U0-B Action Bar** 消费 `user_profiles.version`（cache key）和 `portfolio_confirmed_at`（staleness signal）
- **U0-C** 仅消费 `user_profiles.notify_mode`

- **U1-C** 写入 `user_portfolios.thesis/target/stop_loss/conviction`（这些列已建好）
- **Track M（`features/holdings_sync/`，手动/导入持仓同步）** 经 `portfolio.db.reconcile_portfolio()` 写外部源行，**从不**直接 ALTER `user_portfolios`、**从不**自开打 `user_portfolios` 的 EF 连接（geba 遵守，规则 4&5）。

任何下游 Unit 想加新列前，先回这里加。**禁止**在下游 feature 自己 ALTER `user_portfolios`。

### Track M 新增列与 `reconcile` action（geba 第 2/3/4 步）

`u0a_portfolio_schema.sql` 幂等加三列（无 `source` CHECK，枚举由应用层守）：

| 列 | 含义 | 默认 |
|---|---|---|
| `source` | 行来源 `manual\|paste\|csv\|screenshot\|pdf\|snaptrade` | `'manual'`（旧行已回填） |
| `source_synced_at` | 该 source 最近一次 reconcile 时间 | NULL |
| `external_account_id` | 外部账户标识（Track M v1 透传位，多账户合并用） | NULL |

索引 `idx_user_portfolios_user_source(user_id, source)` 服务源作用域删除。

`portfolio.js` 新增 `action=reconcile`（replace-by-source）契约：

- **P1 保护**：`thesis/target/stop_loss/conviction` 在 reconcile 中**永远 COALESCE 自既有行、绝不取自入参**。`reconcile_portfolio()` 也不发送 P1。结构上让 import 无法携带/清零 P1。
- **源作用域删除**：只删 `source` 相同且不在本次完整集内的行；手敲行与其它源不受影响。**入参必须是该 source 的完整目标集**（非增量）——续修/部分提交时调用方须发「已落库该 source 行 ∪ 本轮接受行」，否则 replace-by-source 会反删先存行。
- **`$CASH` 源无关单例**：`$CASH` 始终在 keep 集内（永不被源作用域删除），跨 source 单条 last-write-wins，杜绝多源现金双计。
- **空入参保护**：`rows=[]` 仅在 `clear_source=true` 时执行（清空该 source 全部，仍不动 `$CASH`/manual/其它源），否则 400。
- **touch 折叠**：`portfolio_confirmed_at=now()` 在 reconcile 内原子刷新，holdings_sync 不再单独 touch。
- **原子性（Codex 评审 [high] 修复）**：`action=reconcile` 不再做「读→逐条 upsert→源作用域删除→touch」多步 PostgREST 序列，而是**一次性调用 Postgres 函数 `reconcile_user_portfolio_source`**（定义见 `u0a_portfolio_schema.sql`）。该函数 = 单事务原子提交，并用 `(user_id, source)` 级 `pg_advisory_xact_lock` 串行化并发的同源完整集提交：两次并发提交**不会**再交错互删对方结果。任一步报错 → 函数抛异常 → 整个事务（含 touch）回滚，EF 返回 5xx。空入参保护与 P1 保留在 SQL 函数内同样强制（防御纵深）。`bulk` 仍沿用旧的 upsert-first-then-delete（非本次修复范围）。
- **RPC 暴露面（Codex M1 复评 [high] 修复 — 决策：与既有 `bulk` 平价）**：reconcile 是租户写 RPC，迁移**显式 `REVOKE ALL … FROM PUBLIC`**（Postgres 默认 PUBLIC 可执行必须主动收回），EXECUTE 仅绑定 EF anon 客户端实际所用标准角色（anon/authenticated）——与已上线 `bulk` 的表 DML 暴露面**严格平价**，不引入新越权类。信任边界仍是 EF（后端 verify JWT → X-Internal-Secret → EF anon 客户端），平台约定“PostgREST 不外部直连、只经 EF”（规则 5；RLS 后续接）。残留暴露 = bulk 既有、已接受；部署冒烟须验证 anon-key 直连 `/rpc` 行为与 bulk 平价并记录。回归守卫 `test_holdings_sync_ef_hardening.py::test_reconcile_rpc_not_granted_to_public`。
- **manual→csv 接管行为（已记录、可接受）**：手敲行被某 source 导入接管后 `source` 变为该 source、thesis 仍保留；此后该 source 再导入若不含它会按源作用域删除它（用户已显式导入过，可接受）。Review 文案需提示"导入会接管同名持仓的数量字段"。

## 维护守则

1. **Edge Function 单点职责**：`backend/app/edge_functions/portfolio.js` 只做 CRUD，不做业务逻辑。
2. **DEAD 区** (`backend/app/services/`, `backend/app/models/`) 禁止 import。
3. **日志**：`get_logger(__name__)`，禁止 `print`，`%s` lazy 格式化。
4. **改 schema**：先改 `backend/migrations/u0a_portfolio_schema.sql`（保持幂等），再改 Edge Function 和 Python `db.py`，**最后**更新本文件。
5. **不要**直连 Insforge PostgREST 绕过 Edge Function（平台惯例 + 后续接 RLS 时不会断裂）。

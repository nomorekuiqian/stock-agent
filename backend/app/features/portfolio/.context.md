## 模块职责

**这是 `/for-you` 专属体系的"数据地基"。** 所有下游 Unit（Action Bar、体检、What-If、连线、月度复盘）都假设：
- 用户的持仓向量可读 → 这里
- 用户的画像可读 → 这里
- "持仓还新鲜" 戳可读 → `user_profiles.portfolio_confirmed_at`

**不属于这里的逻辑**（防误添加）：
- 体检 / scoring / drag 计算 → `features/brew/` 或未来 `features/health/`
- ETF 行业穿透 / `$CASH` 业务消费 → `features/portfolio/exposure_parser.py`（M4 才建）
- 数据网关 `$CASH` 防护 → `shared/data_tools/_cash_guard.py`

## Schema 来源

`backend/migrations/u0a_portfolio_schema.sql`（Insforge Postgres，幂等 DDL）。

| 表 | 行级粒度 | 索引 |
|---|---|---|
| `user_portfolios` | (user_id, symbol) UNIQUE | `idx_user_portfolios_user(user_id)` |
| `user_profiles` | user_id PRIMARY KEY | — |

`updated_at` 由数据库 trigger `u0a_set_updated_at()` 自动维护。

## 数据契约

### 端点（全部 `Depends(verify_user_token)`，user_id 从 token 取，**绝不**信任 query string）

| Method | Path | 用途 |
|---|---|---|
| GET    | `/api/portfolio`              | 当前用户持仓 + `effective_weight_pct` |
| PUT    | `/api/portfolio/bulk`         | 整组替换（onboarding / 录入页） |
| PATCH  | `/api/portfolio/{symbol}`     | 单行 upsert（thesis/target/conviction 追加） |
| DELETE | `/api/portfolio/{symbol}`     | 删一行 |
| PATCH  | `/api/portfolio/touch`        | 仅刷新 `portfolio_confirmed_at`（R-2） |
| GET    | `/api/profile`                | 画像（缺省返回默认值） |
| PUT    | `/api/profile`                | 更新画像 |

### `effective_weight_pct` 推断（service.py 纯函数）

```
if shares 非空 and price 可得:  weight = shares*price / Σ
elif weight_pct 非空:           weight = weight_pct / Σ(weight_pct_i)
else:                           weight = 1 / n_holdings
```

**单调性保证**：调用方传入的 rows 顺序与返回的 HoldingView 顺序一致。

### 默认画像

`get_profile()` 遇空行不抛错，返回 `Profile(style="passive", horizon="long", risk_tolerance="moderate", notify_mode="events_only")`，这与 `inject_profile()`（M2）的兜底一致。

## 与下游的契约

- **U0-B Action Bar** 消费 `user_profiles.version`（cache key）和 `portfolio_confirmed_at`（staleness signal）
- **U0-C** 仅消费 `user_profiles.notify_mode`
- **U1-A/U1-B** 消费 `user_portfolios` 的 `effective_weight_pct`
- **U1-C** 写入 `user_portfolios.thesis/target/stop_loss/conviction`（这些列已建好）

任何下游 Unit 想加新列前，先回这里加。**禁止**在下游 feature 自己 ALTER `user_portfolios`。

## 维护守则

1. **Edge Function 单点职责**：`backend/app/edge_functions/portfolio.js` 只做 CRUD，不做业务逻辑。
2. **DEAD 区** (`backend/app/services/`, `backend/app/models/`) 禁止 import。
3. **日志**：`get_logger(__name__)`，禁止 `print`，`%s` lazy 格式化。
4. **改 schema**：先改 `backend/migrations/u0a_portfolio_schema.sql`（保持幂等），再改 Edge Function 和 Python `db.py`，**最后**更新本文件。
5. **不要**直连 Insforge PostgREST 绕过 Edge Function（平台惯例 + 后续接 RLS 时不会断裂）。

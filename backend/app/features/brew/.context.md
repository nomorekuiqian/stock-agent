# Digest - 个性化摘要

## 功能概述

根据用户自选股列表（watchlist）生成个性化每日摘要。与通用市场日报不同，digest 只关注用户关心的股票，新闻和事件都围绕用户持仓筛选。当前免费/付费都使用 Gemini Flash，靠 prompt 和结构化输入控制分析深度。按 user_id + 日期缓存，同一天同一用户重复请求返回缓存。

## API 端点

| 端点 | 方法 | 描述 | 认证 |
|------|------|------|------|
| `/api/digest` | POST | 生成/获取个性化摘要 | Bearer Token (`verify_user_token`) + 速率限制 5/min |
| `/api/watchlist` | GET | 获取用户自选股 | Bearer Token (`verify_user_token`) |
| `/api/watchlist` | PUT | 保存用户自选股 | Bearer Token (`verify_user_token_with_email`) |
| `/api/digests` | GET | 列出用户摘要历史 | Bearer Token (`verify_user_token`) |
| `/api/digests/{id}` | GET | 获取特定摘要 | Bearer Token (`verify_user_token`) |

**POST /api/digest 请求参数**:
```json
{
  "symbols": ["AAPL", "MSFT", "NVDA"]
}
```

**响应结构**:
```json
{
  "success": true,
  "timestamp": "ISO-8601",
  "symbols_used": ["AAPL", "MSFT", "NVDA"],
  "greeting": "2026年2月14日 | [钩子]",
  "one_line_summary": "关键洞察",
  "stocks": [{"symbol", "name", "price", "daily_change", "week_change", "status", "quick_take"}],
  "news": {
    "headlines": [{"title", "related_symbols", "fact_summary", "deep_analysis", "url"}],
    "briefs": [{"title", "related_symbols", "summary", "analysis", "url"}]
  },
  "events": [{"date", "event", "related_symbols", "why_important"}],
  "summary": {"content": "3段私人分析师总结"},
  "top_event": {"type": "earnings|macro", "symbol": "NVDA", "title": "NVDA 财报", "days_until": 2, "why_for_you": "仓位 30%", "severity": "urgent|watch|info", "link": "/stock/NVDA?tab=earnings", "source_id": "earnings:NVDA:2026-05-03"},
  "from_cache": false
}
```

## 数据流

```
POST /api/digest
  |
  +-- verify_user_token -> 可信 user_id
  +-- 校验 symbols (400)
  +-- 检查缓存: get_user_digest(user_id, today)
  |   +-- 命中且 symbols 匹配 -> from_cache=true
  |   +-- 未命中/symbols 变化 -> 重新生成
  |
  +-- PersonalDigest.generate(symbols)
  |   +-- 并行获取:
  |   |   +-- get_stock_quotes(symbols) — 用户个股报价
  |   |   +-- get_combined_market_news(symbols + 宏观) — 过滤新闻
  |   |   +-- get_economic_calendar(14天)
  |   |   +-- get_earnings_calendar(14天) — 智能过滤
  |   |   +-- get_all_market_data() — 宏观背景
  |   |   +-- portfolio/profile/previous_digests/action_context — 个性化上下文
  |   |
  |   +-- 数据清洗 (新闻50条上限, 财报25条, 日历25条)
  |   +-- Gemini Flash Agent 生成个性化分析
  |
  +-- save_user_digest() 保存到 DB
  +-- 返回响应
```

## 关键业务逻辑

### 缓存策略
- 缓存键: user_id + digest_date (YYYY-MM-DD)
- 如果缓存存在但 symbols 列表变了 -> 重新生成
- symbols 上限 25 个（去重）
- 路由层不再信任前端传入 `user_id`，统一以后端 token 身份为准

### 智能财报过滤 (_filter_earnings)
- 始终包含科技巨头: NVDA, AAPL, MSFT, GOOGL, META, AMZN, TSLA, AMD
- 如果用户关注芯片股 -> 额外加入半导体生态链
- 最多返回 25 条财报

### 与 Market 模块的区别
| 维度 | Market (日报) | Digest (个性化) |
|------|--------------|----------------|
| 视角 | 全市场 | 用户持仓 |
| 模型 | Gemini 3.1 Pro | Gemini Flash |
| 新闻 | 通用市场新闻 | 按用户 symbols 过滤 |
| 缓存 | 按日期（全局） | 按 user_id + 日期 |
| 成本 | ~$0.018/次 | ~$0.018/次 |

### Agent 输出要点
- `stocks` 中每只股票有 `status`（12-18 字判断）和 `quick_take`（120-160 字、3-4 句因果链）
- `news.headlines` 3-4 条深度分析，`briefs` 8-10 条简评
- `summary.content` 3 段: 核心判断 + 波动归因 + 未来 1-2 周场景
- prompt 明确使用 `user_profile`、`portfolio_symbols`、`watchlist_only_symbols`、`previous_digests`、`action_context`；不要把这些字段名直接写进正文。

## 注意事项

- 使用单例模式，全局只有一个 PersonalDigest 实例
- models.py 中 Agent 输出模型和 API 响应模型字段名不同（如 StockSummary vs StockAnalysis），router.py 做了映射
- DB 中 `bottom_line` 和 `analysis` 是遗留字段，新数据存在 `digest_data` (JSONB)
- 新闻清洗: 正文截断 500 字、过滤无标题文章
- `PUT /api/watchlist` 在 Pydantic 层会做 symbols 规范化（trim + upper + 去重）与格式校验，且限制最多 25 个。
- `GET /api/watchlist` 现在会区分“无持仓”和“上游失败”：无持仓返回空列表；上游不可用返回 502，避免前端误判为空并覆盖数据。
- `PUT /api/watchlist` 支持可选 `base_updated_at`。后端会把它透传给 `user-watchlists` Edge Function 做版本检查；如果 watchlist 已被其他入口更新，返回 409 Conflict，避免旧快照整表覆盖新改动。
- `user-watchlists` Edge Function 现在需要鉴权：外部调用必须带 Bearer token 且 `user_id` 必须与 token 用户一致；后端内部调用可使用 `X-Internal-Secret`（`EDGE_FUNCTION_SECRET` 或 `CRON_SECRET`）。

## 产品愿景

> 对应产品模块：持仓日报（详见 Obsidian 产品策略.md）

**当前阶段**：基础版已上线——按用户自选股筛新闻，生成个性化摘要。

**下一步升级**：
- **判断层**：quick_take 从描述升级为判断（这条新闻是噪音还是信号？）
- **连线层**：跨持仓关联分析（集中度、板块联动、对冲盲区）
- **宏观翻译**：把通用宏观事件翻译为"对你的持仓意味着什么"

**长期定位**：每日核心触点，串联持仓体检、个股深研、机会发现、风险预警的枢纽。

## 「我的持仓」UI 数据源（2026-05, V2）

`/for-you` 专属日报上的「我的持仓」区块**不能**用 `digest.stocks ∩ portfolioSymbols` 来组装——digest.stocks 是 LLM 当日产物，可能因为模型遗漏、25 上限截断、或缓存命中后 portfolio 又被改过，导致清单残缺（线上曾出现"模拟持仓 5 只、日报只显示 1 只"）。

**正确实现**：`ForYouContentV2.tsx` 把 `portfolioData.holdings`（过滤掉 ghost）作为 `holdings` 透传给 `DigestInlineReport` → `StockOverviewPanel`；面板按 `holdings` 渲染每行的 symbol / 名称 / 权重 / `shares × price = market_value`，只有右侧详情面板和当日涨跌幅是从 `digest.stocks[symbol]` 叠加上来的（缺时显示"今日日报暂未包含该持仓的分析"）。

观察列表区块继续用 `digest.stocks - portfolioSymbols` 渲染（仅显示 LLM 当日分析），因为观察列表本身就是"我想看 LLM 怎么讲它"的语义。

后续优化：当 watchlist/portfolio symbols 变更时主动让 digest 缓存失效，让 `digest.stocks` 也包含新加入的 symbol——单独 PR，与本次 UI 解耦无关。

## Action Items (V2 round 2, 2026-04-25)

`PersonalDigestOutput.action_items` carries 0-3 in-site action items produced
jointly with the narrative summary. Each item has `{label, target, reason, priority}`.

Targets follow a whitelist enforced in `features/for_you/action_items.py`. The
agent receives `action_context` (missing_thesis_symbols, days_since_*,
symbols_with_today_events, previous_digest_dates) to guide decisions. No hard-coded
rule engine in for_you/service.py anymore — that logic was moved to the agent.

Date→uuid rewrite for `digest:<YYYY-MM-DD>` happens in for_you/service before the
bar reaches the frontend; the frontend only sees `digest:<uuid>`.

# Webhooks

Owns inbound third-party webhook ingestion endpoints.

Current responsibilities:
- Verify Resend webhook signatures.
- Normalize email engagement events into the `email_events` storage flow.
- Preserve explicit Resend channel tags and leave unknown attribution as `unknown`.

The feature keeps provider-specific parsing in `resend_router.py`. `router.py`
re-exports the feature router so architecture checks and app composition can use
the standard feature entry-point convention.
# features/webhooks

## Purpose

Receives third-party webhook callbacks and normalizes them into internal
records. The active endpoint is the Resend engagement webhook used for email
event ingestion.

## Files

- `resend_router.py` — verifies Svix-signed Resend webhook payloads, filters to
  `email.*` events, shapes the event row, and writes through the `email-events`
  Edge Function.
- `router.py` — feature-level router aggregation so the module follows the
  standard feature structure.

## Endpoint

```
POST /api/webhooks/resend
```

Requires `RESEND_WEBHOOK_SECRET` for signature verification. When
`EDGE_FUNCTION_SECRET` is configured, it is forwarded as `X-Internal-Secret`
to the Edge Function.

# features/community_access — Community Agent Access

## Purpose

Owns partner/community-scoped Agent access that is independent from Stripe
subscriptions. MVP supports Panda Agent access for 潘大的科技交流圈 members via
manual email grants collected from a knowledge-planet signup thread.

## Files

- `models.py` — grant/access DTOs and Panda constants
- `service.py` — email normalization/extraction and access helper
- `db.py` — `community-access` Edge Function wrapper
- `router.py` — `/api/community/panda/*` user facade and
  `/api/admin/community/panda/*` admin grant endpoints
- `backend/app/edge_functions/community-access.js` — CRUD over
  `community_access_grants`
- `backend/migrations/community_access_grants.sql` — grant table schema

## Data Model

`community_access_grants` stores one row per `(partner_id, email_normalized)`.
For Panda MVP:

```text
partner_id = panda
email_normalized = user's TheMarketBrew login email
status = active | revoked
grant_source = zsxq_comment
```

The grant can be created before a user registers. When a matching user logs in
and calls `/api/community/panda/me`, the backend marks the grant as seen with
`user_id`, but access remains email-based.

## Access Rules

Panda Agent access is:

```text
verify_user_token_with_email
  -> normalize user.email
  -> active community_access_grants row for partner_id=panda
```

This must not write to `subscriptions.entitlements`, must not imply Max, and
must not unlock main-site features.

## API

User endpoints:

- `GET /api/community/panda/me`
- `POST /api/community/panda/chat/stream`
- `GET/POST/PUT/PATCH/DELETE /api/community/panda/conversations*`
  (`GET` accepts `limit`, `offset`, and optional `search`; the facade filters to
  Panda-owned conversations after the base conversation layer returns rows;
  `PATCH /{conversation_id}/pin` checks Panda ownership before pinning the
  runtime session)

Admin endpoints:

- `POST /api/admin/community/panda/grants/dry-run`
- `POST /api/admin/community/panda/grants/apply`
- `GET /api/admin/community/panda/grants`
- `DELETE /api/admin/community/panda/grants/{grant_id}`

The Panda chat facade ignores any requested persona and always calls
`stream_kol_research(persona_username="pandacircle")` after access passes.

## Gotchas

- Generic `/api/kol_research/chat*` rejects `pandacircle`; only this module's
  facade may run Panda chat.
- This feature is a narrow facade and intentionally delegates to
  `kol_research`, `screener.conversation_db`, and `agent_runtime.events` after
  its own access gate passes. Do not duplicate KOL agent/session logic here.
- Admin grant apply supports pre-authorizing emails that have not registered.
- No public access-code or self-serve bind endpoint exists in MVP.
- Tests must mock write helpers by default to avoid writing production grants.

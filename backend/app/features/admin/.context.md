# Admin 模块

## 功能

管理后台端点，提供 CRM 和运营数据查询。

## 文件结构

- `router.py` — 管理端点
  - `GET /api/admin/whoami` — 当前登录用户是否为 admin（前端用于 gate admin UI），认证依赖 `verify_user_token_with_email`，**不**走 admin 白名单
  - `GET /api/admin/dashboard` — 用户列表，含每用户聚合：订阅 + 互动 + ops 标签 + personal_digest 30 天聚合
  - `GET /api/admin/llm-usage?days=N` — 按天 × feature 的 LLM token 用量 + USD 估值（调 `llm-usage` edge function，附 `X-Internal-Secret`）
- `crm_router.py` — CRM 相关端点（详情页、profile 增删改、interactions、grant subscription、conversations）
- `dashboard.activity` — 30-day DAU summary sourced from `user_activities` via the `admin-activity` edge function.
- `GET /api/admin/activity?days=60` — daily activity series for admin WoW/MoM comparisons.

## 认证

除 `/whoami` 外，所有端点 `Depends(verify_admin_user)`，基于 `ADMIN_EMAILS` 白名单。`/whoami` 仅校验登录态，由响应中的 `is_admin` 字段告诉前端身份。

## 详情页端点 `/api/admin/crm/users/{user_id}` 返回字段

- `subscription` — 来自 `subscriptions list_all` 行（含 plan/status/entitlements/is_lifetime/personal_digest_count_30d/personal_digest_last_date）
- `profile` — CRM 运营档案（user_profiles 表）
- `interactions` — 人工录入交互（interactions 表）
- `contact_feedbacks` / `questionnaires` — 用户反馈
- `email_subscriptions` — Resend Segments 实时查询：`{morning_report, daily_report, weekly_report, personal_digest}`，每次详情加载消耗一次 Resend API（~550ms）
- `personal_digest` — `{count_30d, last_date}`，由 list_all 已聚合，无额外查询
- `conversations` — 最近 10 条 `picker_conversations` 元信息（不含 messages）
- `conversations_total` — 总条数
- `watchlist` — `user_watchlists` 单行：`{symbols, preferences, email, updated_at}`，无则 null
- `portfolio` — `user_portfolios` 全部行：每行含 `{symbol, shares, cost_basis, entry_price, target, stop_loss, conviction, thesis, updated_at}`，无则 []

数据从新 edge function `user-holdings`（`?action=get_watchlist|get_portfolio`）拉取。该函数无 RLS，admin 后端可跨 user_id 读。

## Agent 对话子端点

- `GET /api/admin/crm/users/{user_id}/conversations` — 全部（edge function 上限 20 条）
- `GET /api/admin/crm/users/{user_id}/conversations/{conv_id}` — 单条详情含完整 messages

注：`picker_conversations` 表无 RLS，admin 后端用 anon key + 任意 user_id 即可查任何用户对话。

## 列表端点 `/api/admin/dashboard` 增量字段

每个用户额外字段：
- `personal_digest_count_30d` / `personal_digest_last_date` — 来自 `list_all` edge function（Insforge 聚合，零 Resend 调用）
- `personal_digest_subscribed` — 来自 `entitlements` 列是否包含 `personal_digest_email`，**这是真实广播路径**（`broadcast_personal_digests` 调 `list_entitled_users("personal_digest_email")` 决定发给谁）。Resend Audience「Personal Digest Daily」是历史遗留概念，实际广播不依赖它。

表格「邮件」列：早/周/专全部用 `entitlements` 推导，零 Resend 调用，性能纯前端 O(N)。

筛选 chip 组「邮件」：`订阅专属日报` / `未订阅专属` / `Pro 早报权限` / `Pro 周报权限`，每个 chip 后显示当前匹配人数（基于全用户计算，不受其他筛选影响）。

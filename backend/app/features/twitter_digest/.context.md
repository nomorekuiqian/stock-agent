# Twitter KOL Digest Module

KOL 观点日报生成与读取模块。V3 设计:**入库阶段 enrichment + 日报阶段聚类综合**。读取 `kol_tweets`,先用 flash-lite 给每条推文打质量 + 摘要 + ticker / sector / event 标签;然后用 pro 一次 LLM 调用聚类成话题 + 快讯 + 独家声音;通过 `kol_daily_digests` 持久化给前端读取。

## 用途

为登录用户提供一份标准化的 KOL 观点日报。V3 产品结构按"事件"组织,不再以单条推文为最小单元:

- `headline`: 主线一句,15-25 字
- `intro`: 导言段,20-50 字
- `takeaway`: 3-5 条今日要点(挂锚点 `#topic-N`)
- `topics`: 完整话题卡(多 KOL 综合,带立场分布 + 论据)
- `briefs`: 快讯条(单条值得知道 + 原推链接)
- `solo_voices`: 独家声音(单 KOL 深度 thread/article)
- `crosscut`: 跨话题观察(可空)
- `watch_next`: 明日观察(可空)

V2 schema (`macro_picks` / `industry_picks` / `stock_picks`) 仍存在于 `DailyDigest` 模型上,用于读取 V3 cutover 前写入的旧行。`schema_version` 选择渲染路径。

## 数据流

```
kol_tweets (hourly fetch, symbols IS NULL)
  ↓ daily enrichment cron (北京 05:30, flash-lite)
    enrich_unenriched_tweets()
      - batched (25/批) flash-lite 调用
      - 5 特征质量门:high (≥2) / medium (=1) / low (=0)
      - 抽 tickers / sectors / events,带词典反查 + 文本出现校验
      - 写回 kol_tweets.symbols JSONB:
        {quality, quality_features, content_summary_zh,
         tickers, sectors, events, enriched_at, enriched_model}
kol_tweets (last 24h, enriched)
  ↓ pull_candidate_tweets()
    - 过滤 quality="low"
    - 过滤 unenriched (symbols IS NULL)
    - 过滤低互动 reply
  ↓ curate_tweets() (1 pro LLM call)
    - 聚类:topics (multi-KOL) + briefs (single high/medium) + solo_voices (single high thread/article)
    - 编辑性输出:headline / intro / takeaway / crosscut / watch_next
    - 后处理:
      * _enforce_no_overlap (topics > solo_voices > briefs)
      * _refresh_topic_post_processing (stance_distribution, participating_kols)
      * _fill_brief_one_liners (one_liner_zh ← content_summary_zh)
      * _enforce_brief_validity (must have ticker or sector)
      * _enforce_caps (15/25/5/5/3)
  ↓ generate_daily_digest()
    - 构建 DailyDigest schema_version="v3"
    - model_version = "v3:enrich={ENRICH_MODEL}/digest={CURATE_MODEL}"
  ↓ db.save_digest()
    - edge function `kol-tweets?action=upsert_digest`
    - 写入完整 V2+V3 列(V2 列对 v3 行而言是 [])
  ↓ GET /api/twitter-digest/latest 或 /{date}
  ↓ 前端 /twitter-digest 和 /twitter-digest/[date]
    - DigestView 按 schema_version 分流 v2 vs v3 渲染
```

模型: 在 `agents.py` 中
- `ENRICH_MODEL = "gemini-3.1-flash-lite-preview"` (V3 Step 1)
- `CURATE_MODEL = "gemini-3.1-pro-preview"` (V2 + V3 Step 2 复用)

## V3 Schema 详述

### `EnrichmentOutput`(写入 `kol_tweets.symbols`)

```python
quality: "high" | "medium" | "low"
quality_features: list[str]    # ["data", "reasoning", "catalyst", "comparison", "risk"]
content_summary_zh: str        # 一句中文梗概,15-40 字(schema 软约束 80 char)
tickers: list[str]             # 大写 2-5 字符或 6 位 A-share,经词典 + 文本反查校验
sectors: list[str]             # 中文短词组(如"加密资产", "AI 算力")
events: list[str]              # 短词组(如"Clarity Act", "Q2 财报前瞻")
```

### `Topic`(完整话题卡)

```python
title: str                     # "$CRCL · Clarity Act 通过推涨"
layer: "macro" | "industry" | "stock"
primary_ticker: str            # 必填 if layer="stock"
sector: str                    # 必填 if layer="industry"
event: str                     # 可空,canonical event 名
participating_kols: list[str]  # 后端从 key_arguments 重算
stance_distribution: str       # 后端计算:"5 位博主 · 4 看多 / 1 谨慎"
synthesis_zh: str              # 综述,3-5 句,带分歧点
key_arguments: list[KeyArgument]  # 2-5 条 KOL 论据,每条带 stance
```

### `Brief`(快讯条)

```python
layer: "macro" | "industry" | "stock"
label: str                     # "$TSLA" / "半导体" / "Fed 5月会议"
one_liner_zh: str              # 后端从 content_summary_zh 回填
username, display_name, tweet_id, tweet_url
```

### `SoloVoice`(独家声音)

```python
title: str                     # 编辑标题,~15-30 字
username, display_name
primary_ticker: str            # 可空
tweet_type: "thread" | "article"
tldr_zh: str                   # 3-5 句中文摘要
interpretation_zh: str         # 一句话,为什么值得读
tweet_id, tweet_url
```

## 数量约束

- topics: 5-15 (防御性 cap=15)
- briefs: 10-25 (防御性 cap=25)
- solo_voices: 0-5
- takeaway: 3-5 (cap=5)
- watch_next: 0-3 (cap=3)
- 典型日原推覆盖 ~50 条(topics × args ≈ 30 + briefs ≈ 15 + solo ≈ 3)

## 持久化

`kol_daily_digests` (Insforge) V3 列扩展(V2 列保留):

- V2: `macro_picks`, `industry_picks`, `stock_picks`, `takeaway` (JSONB)
- V3: `headline` TEXT, `intro` TEXT, `topics` JSONB, `briefs` JSONB, `solo_voices` JSONB, `crosscut` TEXT, `watch_next` JSONB
- meta: `schema_version` TEXT (`v2` | `v3`), `tracked_kols`, `generated_at`, `model_version`, `input_tweet_count`, `updated_at`

`save_digest` 同时写所有列(V2 行 V3 列为空,V3 行 V2 列为空)。`get_digest_by_date` 读 V3 行解析所有列;V2 行(无 V3 列)`schema_version` 默认 `v2`,V3 字段用空默认值。

`upsert_digest` edge function 比较 `generated_at`:已有更新结果时拒绝覆盖,避免重叠 cron last-writer-wins。

`generate_daily_digest()` 空结果保护:如果 V3 输出三类全空,先读已有 digest,非空就不覆盖,只返回给调用方。

## 筛选 / 质量门

V3 设计把 5 特征质量门**前移到 enrichment 阶段**(flash-lite,per-tweet),digest 阶段(pro)只做聚类 + 综合。门槛标准:

1. **data**: 具体数据 / 数字
2. **reasoning**: 明确推理链
3. **catalyst**: 可证伪 claim 或具体催化剂
4. **comparison**: 横向 / 历史对比
5. **risk**: 自我承认风险 / 反方论点

→ 命中 ≥2 = `high`,=1 = `medium`,=0 = `low`(永不进 digest)

## V3 Pipeline 后处理规则

- 低互动 reply 预过滤:`like_count + retweet_count < 5` 的 reply 丢弃
- 不喂 unenriched 给 pro 模型(symbols IS NULL)
- 三类不重叠:topics > solo_voices > briefs(后两者按出现优先级 strip)
- `Topic.stance_distribution` 由后端从 `key_arguments[].stance` 计数生成
- `Topic.participating_kols` 由后端从 `key_arguments[].username` 重算去重
- `Brief.one_liner_zh` 由后端从源推 `content_summary_zh` 回填
- Brief 必须有 ticker 或 sector(label 维度),否则丢弃
- 防御性 caps:topics 15 / briefs 25 / solos 5 / takeaway 5 / watch_next 3

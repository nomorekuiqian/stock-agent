# Twitter KOL Digest Module

KOL 观点日报生成与读取模块。它读取 `kol_tweets`, 用单次 LLM 调用筛选高信号推文, 生成结构化 `DailyDigest`, 并通过 `kol_daily_digests` 持久化给前端读取。

## 用途

为登录用户提供一份标准化的 KOL 观点日报。当前产品结构按内容类型组织, 不是按情绪标签组织:

- `takeaway`: 3-5 条今日要点
- `macro_picks`: 大盘 / 指数 / 利率 / 跨资产 / 宏观政策观点
- `industry_picks`: 行业 / 赛道观点, 包括 BTC / ETH 等加密资产类别
- `stock_picks`: 单一 ticker 观点

每条 curated tweet 都保留原推链接、英文原文或中文原文、中文翻译 / 复刻、AI headline、TLDR、KOL 和互动数。

## 数据流

```
enabled_kols (app/shared/twitter_kol_config.py)
  -> pull_candidate_tweets(36h) via kol-tweets edge function `list_batch`
       - filters very-low-engagement replies
  -> curate_tweets() (1 LLM call)
       - quality gate: data / reasoning chain / falsifiable claim / comparison / risk
       - output: CuratedDigestOutput {takeaway, macro_picks, industry_picks, stock_picks}
       - post-process: engagement backfill, Chinese-source cleanup, same-KOL same-subject dedup, caps
  -> generate_daily_digest()
       - builds DailyDigest
       - persist=True by default
  -> db.save_digest()
       - edge function `kol-tweets?action=upsert_digest`
       - table: kol_daily_digests
  -> GET /api/twitter-digest/latest or /api/twitter-digest/{date}
  -> frontend /twitter-digest and /twitter-digest/[date]
```

模型: `gemini-3.1-pro-preview` in `agents.py`.

## 关键文件

- `models.py` - Pydantic schemas: `CuratedTweet`, `CuratedDigestOutput`, `DailyDigest`
- `prompts.py` - 单阶段 `CURATE_INSTRUCTION`
- `agents.py` - `LlmAgent` + lazy-singleton `InMemoryRunner`
- `service.py` - `pull_candidate_tweets()`, `curate_tweets()`, `generate_daily_digest()`
- `db.py` - `kol_daily_digests` 读写封装
- `router.py` - FastAPI endpoints
- `app/shared/twitter_kol_config.py` - KOL 目录
- `../../edge_functions/kol-tweets.js` - Insforge edge function, 同时服务推文和日报表

## API 端点

| 端点 | 方法 | 认证 | 用途 |
|------|------|------|------|
| `/api/twitter-digest/generate` | POST | cron / admin / nonprod | 触发 LLM pipeline, 默认落库并返回 `DailyDigest` |
| `/api/twitter-digest/latest` | GET | user_token | 返回最近一份已持久化日报 |
| `/api/twitter-digest/{date}` | GET | user_token | 返回指定 ISO 日期日报 |

`/generate` 使用 `verify_admin_or_nonprod_or_cron`, 防止普通生产用户触发高成本生成和写入。读取端点当前只要求登录, 代码中 TODO 保留: V2.5 应替换为 Pro entitlement 校验。

## 数据模型

### `CuratedTweet`

主要字段:

- `tweet_id`, `username`, `display_name`, `created_at`, `tweet_type`, `url`
- `category`: `macro` / `industry` / `stock`
- `primary_ticker`: `stock` 类必填, 其他为空字符串
- `sector`: `industry` 类必填, 其他为空字符串
- `text_en`: 英文原文 verbatim; 中文源推文为空字符串
- `text_zh`: 英文源推文的忠实中文翻译; 中文源推文则复制原文
- `interpretation_zh`: <=2 句 headline, 强调非显而易见的角度
- `tldr_zh`: 3-5 句中文 TLDR, 保留论证结构和关键数字
- `like_count`, `retweet_count`, `view_count`: LLM 不填, 后端从源推文回填

### `DailyDigest`

```
generated_at: str
window_hours: int
input_tweet_count: int
tracked_kols: list[str]
takeaway: list[str]
macro_picks: list[CuratedTweet]
industry_picks: list[CuratedTweet]
stock_picks: list[CuratedTweet]
model_version: str
```

## 持久化

日报存在 Insforge `kol_daily_digests` 表。应用层使用新字段名:

- `macro_picks`
- `industry_picks`
- `stock_picks`

数据库列仍沿用早期命名:

- `bullish_picks` -> stores `macro_picks`
- `bearish_picks` -> stores `industry_picks`
- `neutral_analyses` -> stores `stock_picks`

`kol-tweets` edge function 在 `upsert_digest`, `get_digest`, `get_latest_digest` actions 中做 alias mapping。未来如果迁移表列名, 可以删除这个兼容 shim。

`save_digest()` 以 `date` upsert。edge function 读取已有行的 `generated_at`, 如果已有结果更新, 会跳过旧结果写入, 避免重叠 cron / 手工重跑造成 last-writer-wins。

## 筛选策略

Prompt 默认 drop。保留推文必须至少命中一个结构化信号:

- 具体数据 / 数字
- 明确推理链
- 可证伪 claim 或明确 catalyst
- 横向 / 历史对比
- 自我承认风险或反方论点

纯观点、价格反应、无论证的加减仓、闲聊、政治、哲学化周期感想、上下文不清的推文会被丢弃。

## 后处理规则

- 低互动 reply 预过滤: `like_count + retweet_count < 5` 会丢弃
- Engagement 从源推文回填, 不信任 LLM 复制值
- 中文源推文不会被反译成英文, `text_en` 强制清空
- 同一 KOL 同一 subject 去重:
  - macro: 每 KOL 最多 1 条
  - industry: `(username, sector)`
  - stock: `(username, primary_ticker)`
- 防御性 cap:
  - macro max 4
  - industry max 8
  - stock max 10
  - takeaway max 5

## 当前缺口

- 没有 GitHub Actions workflow 自动触发 KOL 采集或日报生成
- Web 读取端点还未接 Pro / Max 付费墙, 当前仅要求登录
- 邮件模板和 Resend batch send 尚未实现
- 没有历史归档列表页, 只有 `/twitter-digest` latest 和 `/twitter-digest/[date]`
- `twitter-kol-opinion-platform.md` 仍保留部分后续计划项, 实现状态以本文件和代码为准

# Twitter KOL Digest Module

KOL 观点日报生成与读取模块。两阶段设计:**入库阶段 enrichment + 日报阶段聚类综合**。
读取 `kol_tweets`,先用 flash-lite 给每条推文打 `quality=keep|drop` + 每个 ticker 的
`stance=bull|bear|neutral` + sectors;然后用 pro 一次 LLM 调用聚成 ticker_theses +
macro_threads + watchpoints;通过 `kol_daily_digests` 持久化给前端 + 邮件读取。

## 输出形态

- `headline`: 主线一句,15-25 字
- `intro`: 导览段落,80-150 字编辑话术(今天主要 ticker / 事件 / 分歧 + 引导深读)
- `ticker_theses`: 个股讨论卡片(同 ticker ≥2 KOL 聚合,buy / sell / observation 三类论据)
- `macro_threads`: 宏观 / 行业讨论(Fed / CPI / 监管 / 地缘 / 行业级别)
- `watchpoints`: 短期未来注意点(具体事件 + date_hint + KOL evidence)
- `hot_sectors` / `hot_tickers` / `hot_events`: 后端 frequency tallies(基于 enrichment tags)
- `other_tickers`: transparency tail(被讨论但没上 thesis 的 ticker)

## 数据流

```
kol_tweets (hourly fetch, symbols IS NULL)
  ↓ hourly Insforge cron-trigger enrichment step (flash-lite)
    enrich_unenriched_tweets()
      - batched (25/批) flash-lite 调用
      - 二值质量门 quality = keep / drop (面向散户, keep 门槛刻意放宽):
        keep 触发任一项即可:
          1. 数据 / 推理链 / 催化剂 / 对比 / 风险揭示(thesis 级)
          2. narrative 叙事(讲市场故事, 无需数字)
          3. 行为信号(加仓 / 减仓 / 清仓 / 翻多翻空)
          4. 事件提及(财报日 / FOMC / 评级变动 / 产品发布,无需作者 take)
          5. 明确方向 + ticker(即使只一句"$NVDA 看到 250")
        drop 收紧到只剩:
          纯价格播报、纯炫战绩、无 ticker 的哲学、纯转推、与投资无关
      - 每个 ticker 直接打 stance = bull / bear / neutral
        (同推文可对不同 ticker 给不同 stance)
      - 抽 sectors,ticker 带词典反查 + 文本出现校验
      - 写回 kol_tweets.symbols JSONB:
        {quality, ticker_stances: [{ticker, stance}], sectors,
         enriched_at, enriched_model}

kol_tweets (last 24-36h, enriched, quality = keep)
  ↓ pull_candidate_tweets()
      - 按 1h 半开时间片 [since, until) 调 `list_batch`, 再按 tweet id 去重合并
      - 单片 ≥ 900 行 (`_LIST_BATCH_SPLIT_THRESHOLD`) 时递归二分,避免 Insforge/PostgREST 默认 1000 行截断
      - 过滤 drop + 低互动 reply + unenriched
  ↓ (向后兼容:老 schema 的 high/medium → keep, low → drop;
     老 tickers list → ticker_stances 全部 stance=neutral)
  ↓ curate_tweets() — single pro LLM call
      ticker_theses + macro_threads + watchpoints + intro/headline
      - macro_threads.key_points 用于网页 topic 折叠区: 同一话题下 filtered
        tweets <=12 时尽量全收, >12 时保留最多 12 条不同 KOL/观点摘要
  ↓ generate_daily_digest()
      - _compute_hot_lists() 算 frequency
      - _compute_other_tickers() 算 tail
      - 写入完整 DailyDigest
  → kol_daily_digests
```

## 模型 & Agent

- `ENRICH_MODEL = "gemini-3.1-flash-lite-preview"` (Step 1 enrichment)
- `CURATE_MODEL = "gemini-3.5-flash"` (Step 2 curation)
- 两个 LlmAgent 各自 InMemoryRunner(`agents.py`,跨调用 singleton)

## 文件

- `models.py` - Pydantic schemas:
  - `EnrichmentOutput` (Step 1 输出: quality + ticker_stances + sectors)
  - `TickerStance` (单 ticker 立场对)
  - `Argument`, `TickerThesis`, `MacroThread`, `WatchpointItem` (LLM 输出零件)
  - `OtherTickerMention`, `HotItem` (transparency tail + hot list)
  - `CuratedDigestOutput` (Step 2 LLM 输出整体)
  - `DailyDigest` (持久化模型,前端 + 邮件 read)
  - `DailyDigestListItem` / `DailyDigestArchiveResponse` / `TwitterDigestTeaser`
    (归档列表 + 公开转化预览)
- `prompts.py` - 综合 prompt(聚类规则、论据 direction 分类、intro 写法、watchpoints)
- `enrichment_prompts.py` - flash-lite 每条推文打标签的 prompt
- `agents.py` - LlmAgent + Runner singletons
- `enrichment.py` - Step 1 流水线(batched flash-lite 调用 + 写回 symbols JSONB)
- `service.py` - Step 2 流水线(pull → curate → 后处理 → 持久化)
- `db.py` - `kol_daily_digests` 读写
- `router.py` - HTTP endpoints
- `../../edge_functions/kol-tweets.js` - `kol_tweets` + `kol_daily_digests` 两表的 CRUD edge function

## 端点

| 路径 | 方法 | 鉴权 | 用途 |
|------|------|------|------|
| `/api/twitter-digest/enrich` | POST | cron / admin / nonprod | 扫 unenriched 推文打 flash-lite 标签 |
| `/api/twitter-digest/generate` | POST | cron / admin / nonprod | 触发 pro pipeline 聚合,默认落库并返回 DailyDigest |
| `/api/twitter-digest/latest` | GET | user_token + `twitter_digest` entitlement(Max) | 返回最近一份完整日报 |
| `/api/twitter-digest/{date}` | GET | user_token + `twitter_digest` entitlement(Max) | 返回指定日期完整日报 |
| `/api/twitter-digest/teaser/latest` | GET | open | 返回最近一期轻量预览(标题/热榜/intro preview) |
| `/api/twitter-digest/teaser/{date}` | GET | open | 返回指定日期轻量预览 |
| `/api/twitter-digest/archive` | GET | user_token + `twitter_digest` entitlement(Max) | 分页返回完整归档列表元数据 |
| `/api/twitter-digest/archive/teaser` | GET | open | 分页返回公开归档预览 |
| `/api/twitter-digest/preview` | GET | open | 渲染指定/最新日报为 email HTML(供 `/email-test` 预览) |

完整读取端点是 Max-only，统一检查 `payment.entitlements.has_entitlement(user_id, "twitter_digest")`。
公开 teaser 端点只能返回轻量字段，不能包含 `ticker_theses` / `macro_threads` / `watchpoints`
等全文证据链。

## Curate 后处理(post-LLM)

LLM 输出不能直接信。`service._enforce_provenance()` 和 `_enforce_caps()` 做这些事:

1. **Provenance**:每个 Argument 的 `tweet_url` / `kol` 必须能 trace back 到输入 tweets;
   不在的丢掉。`primary_kols` / `tweet_count` 从存活论据重算。
2. **Watchpoint evidence backfill**(`_backfill_watchpoint_evidence`):LLM 经常忘记
   填 evidence,后端根据 watchpoint 的 KOL/ticker/keywords 在原 tweets 里抓 2-3 条
   填回去。evidence 仍为空的 watchpoint 一律丢弃。
3. **Caps**:`ticker_theses ≤ 8`,`macro_threads ≤ 6`,`watchpoints ≤ 7`。
4. **Ticker thesis 硬门槛**:卡片必须有 ≥1 条 `buy_arguments` 或 `sell_arguments`。
   只有 `observation_arguments` 的卡片在 `_enforce_caps` 被丢弃 — enrichment 放宽后
   会带进很多"signal 级"信号(纯立场 / 行为 / 叙事 / 事件提及),这类信号上不到论据,
   只在 stance tally / other_tickers 尾部出现。
5. **must_include_tickers**:`_compute_top_tickers_priors()` 算窗口内 top-5
   tickers(distinct KOL count)灌进 prompt,LLM 不能 silently 丢掉最热门 ticker。

## 数据库 schema

`kol_daily_digests` 列(Insforge):

- meta: `date` (unique), `generated_at`, `window_hours`, `input_tweet_count`,
  `tracked_kols`, `model_version`
- editorial: `headline`, `intro`
- 主体:`ticker_theses`, `macro_threads`, `watchpoints` (JSONB)
- transparency tail: `other_tickers` (JSONB)
- hot lists: `hot_sectors`, `hot_tickers`, `hot_events` (JSONB)

`input_tweet_count` 是**窗口内 raw 推文数**(filter 前),不是输入 LLM 的过滤后数。
`pull_candidate_tweets()` 通过时间分片绕过单次查询 1000 行默认截断,所以这个数字应
接近真实窗口 raw 总量,而不是最新 1000 条的采样。

## Cron

- `kol-tweets-enrich.yml` — 北京 05:30 Mon-Fri(UTC 21:30 Sun-Thu)
- `twitter-digest-generate.yml` — 北京 06:00 Mon-Fri(UTC 22:00 Sun-Thu)

Enrichment 比 generate 早 30 分钟,确保 generate 拿到的 36h 窗口里有 enrichment。

## 不要做的事

- 不要在 digest 阶段再做质量判定 — 它在 enrichment 已经做过。
- 不要把 quality=drop 推文喂给 pro 模型(`pull_candidate_tweets` 已过滤)。
- 不要让 LLM 直接生成 `participating_kols` / `tweet_count` / `kols_watching` 计数 —
  后端从存活 evidence 重算(LLM 数数不可靠)。
- 不要在 generate 失败时清空已有 row(`generate_daily_digest` 的 empty-guard
  会保留已存在的非空 digest)。

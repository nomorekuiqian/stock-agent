## 模块职责

把多形态摄取（截图 / 粘贴文本含自然语言·CSV / PDF）汇聚到一个 Review/Confirm
屏，唯一写路径 = `service.reconcile_and_upsert` → `portfolio.db.reconcile_portfolio`
（replace-by-source + P1 COALESCE 保护）。手敲 (a) 保持现状走 `PUT /api/portfolio/bulk`，
不经本模块。

**不属于这里**：Track C（SnapTrade / `user_broker_connections` / `holdings-sync.js`）；
直接 ALTER / 自开打 `user_portfolios` 的 EF 连接（geba：经 portfolio.db 单一属主）。

## 边界与不变量

1. `NormalizedHolding` **结构上无** thesis/target/stop_loss/conviction —— source
   适配器无法携带 P1（全设计最重要的正确性决策）。
2. **commit 完整集契约**：`CommitRequest.rows` 必为该 source 完整目标集（非增量）；
   续修/部分提交由 FE 发「已落库该 source 行 ∪ 本轮接受行」，否则 replace-by-source
   反删先存行。空 rows 仅 `clear_source=true` 放行。
3. symbol 全程过 `portfolio.models._SYMBOL_RE` 才下传 EF（PostgREST not.in 注入边界）。
4. L2 缓存 key 仅安全规范 key（ticker-shaped 或 `h:<hex>`）；自由文本不进 L2（§2bis.A.3）。
5. 日志 `get_logger(__name__)` `%s` lazy；**绝不记原始粘贴/文件内容**；不 import
   `app/services|models`（DEAD）。

## 配额故障策略（Codex [high]）

LLM/vision 路径配额 EF 宕 → **fail-closed**（拒 + 503 可恢复错误，提示改用
CSV/手敲）；非成本路径（报价回环 / L2 缓存）仍 fail-open。异于 `quota/service.py`
全局 fail-open。

## 模型契约

抽取统一 `gemini-3.1-flash-lite-preview`（设计 §5；不用 pro）。PoC 硬约束：
`response_schema` 不得带 `maxItems`+多 nullable 数值（Gemini 400）；60 上限解析后
应用层截断。参考实现 `backend/scripts/holdings_sync_poc/`。

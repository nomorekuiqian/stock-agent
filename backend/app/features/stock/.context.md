# Stock - 个股投研

## 功能概述

个股研究模块，提供公司资料、实时报价、财务数据、估值对比、AI 基本面分析、AI 技术分析、新闻面分析和宏观面分析。数据来自 OpenBB、yfinance、FMP、tvscreener、pandas-ta、FRED 多个源，通过三级缓存（内存 -> DB -> API）减少外部调用。AI 分析使用 Gemini Pro 生成中文投研报告。四个分析维度独立触发、独立缓存。

## 数据流

### 获取完整股票数据 (GET /stock/{symbol})
```
请求
  |
  +-- StockService.get_stock_data()  并行获取:
  |   +-- Profile    (内存 30min -> DB 30天 -> OpenBB API)
  |   +-- Quote      (实时, OpenBB, 不缓存)
  |   +-- Financials (内存 30min -> DB 按季度 -> OpenBB API)
  |   +-- yf_metrics (yfinance Ticker.info, 10min 缓存, 一次调用)
  |
  +-- yf_metrics 直接提供:
  |   +-- TTM 指标 (营收, 净利, EPS, EBITDA, OCF, FCF)
  |   +-- 估值指标 (P/E, P/S, P/B, EV/EBITDA, PEG, 股息率)
  |   +-- 远期估值 (Forward PE, 隐含EPS增速)
  |   +-- 盈利能力 (毛利率, 营业利润率, 净利率, ROE, ROA)
  |   +-- YoY 增长 (营收增速, 盈利增速)
  |
  +-- QoQ 增长 (营收环比) 仍从 Financials 手算
  |
  +-- 返回 profile、quote、fundamentals、financials 聚合字典
```

### AI 分析 (POST /stock/{symbol}/analysis)
```
请求
  |
  +-- 检查缓存 (DB, 24小时过期)
  |   +-- 命中且未过期 -> 直接返回
  |   +-- 未命中/force=true -> 生成新分析
  |
  +-- 获取完整股票数据 + 估值对比数据
  +-- _prepare_stock_data_for_analyst() 精简数据
  +-- Gemini Pro Agent 生成 7 段式分析报告
  +-- 保存到 DB (24小时过期)
  +-- 返回分析结果
```

## 关键业务逻辑

### 三级缓存架构
| 资源 | 内存缓存 | DB 缓存 | API 源 | TTL |
|------|----------|---------|--------|-----|
| Profile | 30min, LRU 500 | 30天 | OpenBB | 30min / 30天 |
| Financials | 30min, LRU 500 | 按季度 | OpenBB | 30min / 45天窗口 |
| Quote | 不缓存 | 不缓存 | yfinance | 实时 |
| Analysis (基本面) | 不缓存 | 24小时 | Gemini Agent | 24小时 |
| Analysis (技术面) | 不缓存 | 24小时 | Gemini Agent | 24小时 |
| Analysis (新闻面) | 不缓存 | 8小时 | Gemini Agent | 8小时 |
| Analysis (宏观面) | 不缓存 | 24小时 | Gemini Agent | 24小时 |
| tvscreener 快照 | 15min | 不缓存 | tvscreener API | 15min |
| pandas-ta 趋势 | 30min | 不缓存 | yfinance + pandas-ta | 30min |
| Price History | 30min (router层) | 不缓存 | OpenBB | 30min |
| Industry PE | 6小时 | 不缓存 | FMP | 6小时 |
| Market Overview | 10min (router层) | 不缓存 | FMP + news data_tools | 10min |

### 缓存实现细节
- 线程安全: 使用 `threading.Lock` 保护并发访问
- 返回浅拷贝: 防止外部修改缓存内容
- LRU 淘汰: 内存缓存上限 500 条，超出时删除最旧的
- DB 异步写入: 获取新数据后异步写入 DB 缓存，不阻塞响应

### AI 技术分析 (POST /stock/{symbol}/technical)
```
请求
  |
  +-- 检查缓存 (DB, analysis_type="technical", 24小时过期)
  |   +-- 命中且未过期 -> 直接返回
  |   +-- 未命中/force=true -> 生成新分析
  |
  +-- 获取技术指标数据:
  |   +-- tvscreener (primary): 当前指标快照 + TV 评级 (15min 内存缓存)
  |   +-- pandas-ta (secondary): 历史趋势 + 支撑阻力 (30min 内存缓存)
  |   +-- tvscreener 失败时降级为纯 pandas-ta
  |
  +-- _prepare_technical_data_for_agent() 精简数据
  +-- Gemini Pro Agent 生成 4 段式技术分析
  +-- 保存到 DB (24小时过期, analysis_type="technical")
  +-- 返回分析结果
```

### AI 基本面分析输出结构 (7 段式)
1. `title` — 有观点的中文标题 (15-40字)
2. `fundamentals_analysis` — 估值 + 成长性 + 盈利能力 (600-1000字)
3. `financials_analysis` — 营收/盈利质量 + 资产负债表 + 趋势 (600-1000字)
4. `company_overview` — 商业模式 + 竞争壁垒 + 市场定位 (400-600字)
5. `opportunities` — 短/中/长期催化剂 (400-600字)
6. `risks` — 业务/财务/估值风险 (400-600字)
7. `investment_summary` — 核心论点 + 多空观点 + 关键 KPI (300-500字)

### AI 技术分析输出结构 (4 段式)
1. `title` — 有观点的技术面中文标题 (15-40字)
2. `trend_analysis` — 趋势方向 + 动能状态 + 多周期共振 + TV 评级 (600-1000字)
3. `entry_exit_signals` — 支撑阻力位 + 交易信号条件 (400-600字)
4. `pattern_analysis` — 均线交叉 + BB 形态 + 量价分析 + 指标背离 (400-600字)
5. `technical_summary` — 技术评级 + 关键价位 + 情景推演 (300-500字)

### AI 新闻面分析输出结构 (5 段式)
1. `title` — 新闻面中文标题 (15-40字)
2. `news_summary` — 最重要的 2-3 条新闻 + 投资影响 + 竞品动态 (500-800字)
3. `analyst_activity` — 分析师评级/目标价变动、共识看法 (300-500字)
4. `upcoming_catalysts` — 下次财报 + 产品发布 + 行业事件 (300-500字)
5. `sentiment_assessment` — 新闻情绪判断 + 与股价走势一致性 (300-500字)

**数据输入**: FMP 个股新闻 (7天)、竞品 peer 新闻 (FMP peers API)、财报日历、分析师目标价

### AI 宏观面分析输出结构 (5 段式)
1. `title` — 宏观面中文标题 (15-40字)
2. `macro_impact` — 利率/通胀/GDP 对该公司的具体影响 + 跨资产联动 (500-800字)
3. `sector_positioning` — 板块表现 + 该股在板块中的定位 (400-600字)
4. `market_regime` — F&G 子项 + VIX + 对该个股的 risk/reward 影响 (300-500字)
5. `outlook_and_risks` — 3-6 个月宏观展望 + 个股专属宏观观察清单 (300-500字)

**数据输入**: 宏观风险仪表盘 (FRED)、F&G 指数 (CNN 7 子项)、VIX/VVIX、通胀利率快照 (Fed Funds/10Y/CPI/PCE)、跨资产数据 (DXY/金/油/铜/国债曲线)、板块摘要

### Market Tab 数据
- `market-overview` 已精简为页面 KPI 所需数据，不再暴露独立 `analyst-activity` 端点、市场排名徽章、市场热度卡片数据或同行比较数据。
- 公开响应只包含 `header.next_earnings` 和 `kpis`（`current_price`、`news_24h`、`sector_relative_perf_today`、`stock_sector`）。
- 板块相对表现仍内部使用 FMP sector snapshot 计算，但不向前端返回完整 market heat payload。

### 数据精简 (_prepare_stock_data_for_analyst)
- 财报只保留最近 4 个季度
- 过滤 null/zero 值字段
- 历史估值保留 5 年数据
- 同行对比保留前 5 名
- 目的: 减少 token 消耗

### 财报 Tab 数据聚合
- 完整三表来自 FMP `income-statement` / `cash-flow-statement` / `balance-sheet-statement`，按 fiscal quarter end date 排序。
- EPS surprise 历史优先来自 yfinance `get_earnings_history()`，但 yfinance 经常晚于 FMP 更新。
- 若 FMP earnings-calendar 已有最新 `epsActual`，后端会把该条合并进 `earnings_history` 并按季度日期降序排序。
- 一个季度只有一条 statement 记录。`_merge_calendar_into_statements`（service.py）做合并：earnings-calendar 的 actuals 通过日期邻近性（公告日前 ≤90 天的 statement 即视为同一季度）匹配到完整 income statement 上，把 `eps_calendar_actual` / `revenue_calendar_actual` / `eps_estimated` / `revenue_estimated` 等字段写进去；91-180 天的边界情况用 EPS/营收数值二次确认。
- 若公告日的 statement 还没出现在 FMP（公告当天到 1-3 个工作日内会发生），则合成一条 stub statement 加到 `income_statements` 列表头部，只填 calendar 字段（`revenue` / `eps_diluted` / `eps_estimated` / `revenue_estimated`），其余明细字段为空。前端按"字段缺失就空着或显示占位"处理，无 `is_pending` 之类的状态标记。

### 指标来源
- **TTM/估值/盈利能力/YoY增长**: 全部来自 `yfinance Ticker.info` (一次调用)
- **远期估值**: Forward PE 来自 yfinance, implied_eps_growth 由 forward_eps 和 trailing_eps 计算
- **QoQ 增长**: 从 OpenBB 财报数据手算 (yfinance 不提供环比)

## 注意事项

- StockService 是单例模式，整个应用生命周期复用
- AI 分析内容（包含缓存读取）是 Max-only：后端必须通过 `verify_user_token` + `has_entitlement(user_id, "stock_research")`，前端必须发送 Bearer token。不能只依赖页面级 PaywallGuard。
- 批量报价 (`/quotes`) 用一次 yfinance 调用获取 70+ 只股票，效率远高于逐个查询
- DB 的 JSONB 字段返回可能是字符串，db.py 中做了 JSON 解析兼容
- OpenBB 的财务数据需要合并三张表 (income, balance, cashflow) 为一条季度记录
- 估值对比端点 (`/valuation`) 会并行获取同行、行业、历史三个维度的数据

## 产品愿景

> 对应产品模块：个股深研（详见 Obsidian 产品策略.md）

**当前阶段**：四维分析已上线（基本面+技术面+新闻面+宏观面），但 DAU ~0。

**已完成**：
- 新闻面分析：FMP 个股新闻 + 竞品新闻 + 分析师动态 + 催化事件 + 情绪判断
- 宏观面分析：FRED 利率/通胀 + CNN F&G 7 子项 + 跨资产 (DXY/商品/国债) + 板块定位 + 个股化宏观观察清单

**下一步升级**：
- **组合语境**：登录用户看到"这只股票对你的组合意味着什么"
- **多空视角**：Bull case vs Bear case 双视角分析，避免确认偏误

**长期定位**：日报和持仓体检的"深挖着陆点"，从孤立分析变为有上下文的深度研究。

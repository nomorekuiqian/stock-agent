# job_monitor — 通用后台任务监控（admin）

让 admin 控制台用**一个界面**监控任意周期性后台任务的每次运行结果/产出/健康。第一个接入的是知识星球采集（zsxq）；将来 Twitter 爬取等只需实现同一 `JobSource` 协议并注册，**前端不用改**。

## 为什么要它
zsxq 改成每 4h 定时（无人值守）后，「每次触发到底抓了什么、入了几条、为什么丢、cookie 还活着吗」必须可见。数据本来就全在 `zsxq_ingest_runs`/`zsxq_thread_ledger`/`zsxq_credentials`/`zsxq_ingest_state`，缺的只是「人看得到」。

## 结构
- `sources.py` — `JobSource` 协议（`overview()` / `list_runs()` / `get_run()`）+ 注册表（`register`/`get_source`/`list_sources`）+ 归一化常量（`STATE_*`/`TONE_*`）+ 时长/ISO 助手。**UI 只见归一化形状**，故跨任务通用。
- `zsxq_source.py` — zsxq 适配器，包 `zsxq_ingest.db` 的只读函数。**绝不暴露 cookie**，只给 `status`。run.status→state 映射；curated 展示指标（抓取/入库/跳过/失败/附件）；overview 健康= cookie 主导 + 末次 run 失败/降级则 warn。模块导入即 `sources.register(ZsxqJobSource())`。
- `router.py` — `/api/admin/jobs`（列源）、`/{source}/overview`、`/{source}/runs?limit=`、`/{source}/runs/{run_id}`，全 `Depends(verify_admin_user)`。导入 `zsxq_source` 触发注册。

## 归一化形状
- run：`{id,type,status,state(ok|running|warn|fail),started_at,finished_at,duration_seconds,metrics:[{label,value}],error,detail?}`
- overview：`{health(ok|warn|fail), stats:[{label,value,tone}]}`
- run detail（zsxq）：`detail.ledger`（aggregate_ledger 的 stage 计数 + drop_reasons）+ `detail.report`

## 不变量 / 注意
- **只读**：所有 source 方法只读 Insforge，绝不写。
- **不泄密**：任何返回形状都不得含 cookie/token —— 见 `test_zsxq_source.py::test_overview_health_fail_and_cookie_never_leaks`。
- **永不 500**：`zsxq_source._safe` 把读失败降级为空，监控页不因后端抖动崩。
- 前端：`frontend/src/app/admin/jobs/`（SSR token gate 的 `page.tsx` + 客户端 `JobMonitorPanel.tsx`，30s 轻量自动刷新 + 行展开看 detail）。

## 加一个新 source（如 twitter）
实现 `key`/`label`/`overview`/`list_runs`/`get_run`（返回归一化形状，别泄密），在模块底部 `sources.register(...)`，并让 `router.py` 导入该模块。前端自动多出一个 tab。

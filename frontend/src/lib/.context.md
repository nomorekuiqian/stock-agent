# Lib - 共享工具库

## 功能概述

`src/lib/` 提供前端共享工具。认证相关代码当前完全走 `@insforge/sdk` 客户端直接调用（SDK Direct），不经过 `/api/auth` server bridge。

## 核心文件

| 文件 | 职责 |
|------|------|
| `api.ts` | 统一 API 客户端，所有后端调用入口 |
| `auth-cookies.ts` | Auth cookie 工具函数 |
| `auth-error-presentation.ts` | 认证错误展示逻辑 |
| `auth-redirect.ts` | 登录后的 redirect path 管理（sessionStorage） |
| `auth-verification.ts` | 邮箱验证逻辑 |
| `digest-utils.ts` | Digest 数据转换工具 |
| `insforge.ts` | 浏览器侧 Insforge SDK client 单例 |
| `insforge-server.ts` | 服务器侧 Insforge SDK client 单例 |
| `onboarding-status.ts` | userId 维度 onboarding completed localStorage marker |
| `portfolio-templates.ts` | 投资组合模板预设 |
| `pricing.ts` | 定价常量与逻辑 |
| `stock-names.ts` | 股票名称映射 (STOCK_NAMES) |
| `timezone.ts` | 时区工具函数 (marketTodayStr 等) |
| `utils.ts` | 通用工具函数 (cn 等) |
| `wechat.ts` | 微信相关工具 |

## `api.ts`

`api.ts` 保持简单边界：

- 需要登录的请求统一调用 `_authHeaders()`
- `_authHeaders()` 通过 `getAccessToken()` 拿 Bearer token
- `api.subscriptions.syncUser()` 也必须带 Bearer token；后端使用 token 中的 `user_id/email` 校验 body，避免客户端伪造 Resend contact 账号关联。
- 后端继续负责 `verify_user_token`
- 需要 401 refresh + retry 的受保护请求走 `fetchProtected()`；`api.user.onboardingStatus()` 和 `api.user.completeOnboarding()` 必须走这个路径。`onboardingStatus()` 只有在后端明确返回 `{"completed": false}` 时才表示未完成，认证、网络、5xx 失败必须抛错，不能伪装成 `{ completed: false }`。
- `onboarding-status.ts` 的 marker key 是 `onboarding_completed:{userId}`。`OnboardingGate` 先读这个 marker，已完成用户不再请求 `/user/onboarding-status`；后端返回 `completed:true` 或用户完成 onboarding 时写入 marker。
- `api.twitterDigest.*` 区分 Max-only 全文接口和公开 teaser 接口：`getLatest` / `getByDate` / `listArchive` 需要 Bearer token + `twitter_digest` entitlement；`getLatestTeaser` / `getTeaserByDate` / `listArchiveTeaser` 用于转化预览
- `api.research.conversations.list({ limit, offset, search })` 支持服务端搜索标题和对话正文；`search` 会 trim 后作为 query param 发送，返回的 `ConversationSummary.search_matches` 可用于展示命中来源和片段。重命名仍复用 `conversations.update()` 的全量保存契约，调用方必须传原始 `data/message_count`，只改标题时用 `touch:false` 避免刷新历史排序。
- `api.research.chatStream()` 的 `ResearchRequest` 支持可选
  `conversation_id`。普通 `/research` 页面会把预分配或已有 conversation id
  传给后端，供 `agent_sessions` / `agent_session_events` 写入普通 Research
  runtime 记录。`ConversationSaveRequest.id` / `KolConversationSaveRequest.id`
  用于把最终保存的 `picker_conversations.id` 对齐同一个 runtime session id。
- `api.kolResearch.*` 提供 KOL Persona 投研助手 8 个方法 (`personas` / `chat` / `chatStream` + `conversations.list/get/create/update/delete`)；`chatStream()` 同样解析 SSE，事件类型为 `skill_activated` / `tool_call_start` / `tool_call_end` / `final` / `error`。相关类型: `KolPersonaSummary`、`KolPersonaChunk`、`KolToolCallSummary`、`KolResearchMessage`、`KolResearchRequest`、`KolResearchResponse`、`KolResearchStreamEvent`、`KolConversationSaveRequest`
- `KolResearchStreamEvent.error` 支持 `code` / `detail` / `status`。后端 SSE error 透传 `agent_timeout`、`context_too_long`、`model_schema_error`、`agent_setup_error`、`agent_error`；前端 fetch 层会把非 2xx 响应转成 `http_error` 或 `auth_error`，把 135 秒 Abort 转成 `client_timeout`，把真正网络异常转成 `network_error`，不再把所有失败都抛给页面层变成泛化错误。

## 注意事项

- 认证逻辑分散在 `auth-cookies.ts`、`auth-error-presentation.ts`、`auth-redirect.ts`、`auth-verification.ts` 等文件中
- 当前登录态使用 `app_access_token` / `app_refresh_token` first-party httpOnly cookies，客户端通过 `/api/auth/session` 读取和刷新 session。
- 不要引入 `@insforge/nextjs`

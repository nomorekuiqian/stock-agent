# Lib - 共享工具库

## 功能概述

前端所有页面共享的核心工具库，包含 API 客户端、认证、数据库连接、工具函数。

## 核心文件

| 文件 | 职责 | 大小 |
|------|------|------|
| `api.ts` | 统一 API 客户端，所有后端调用入口 | ~1300 行 |
| `auth.ts` | 认证逻辑 (登录/注册/OAuth/密码重置) | ~250 行 |
| `auth-verification.ts` | 邮箱验证 redirect / pending signup 状态工具 | 小 |
| `auth-storage.ts` | Server auth() -> SDK localStorage 恢复 helper | 小 |
| `insforge.ts` | Insforge SDK 客户端实例 | ~15 行 |
| `digest-utils.ts` | Digest 数据格式转换 | 小 |
| `stock-names.ts` | 股票代码→名称映射常量 | 小 |
| `portfolio-templates.ts` | 预设投资组合模板 | 小 |
| `timezone.ts` | 时区工具（业务日期按市场时区，展示时间自动带明确时区标签） | 小 |
| `utils.ts` | 通用工具函数 | 小 |

## api.ts 架构

```
_authHeaders(base, { required })     // 认证 header 工具 (Bearer Token)
// 缓存由 TanStack Query 管理 (hooks/queries/)

api.reports.*                        // 日报 (公开)
api.watchlist.*                      // 自选股 (需认证)
api.digests.*                        // 摘要历史 (需认证)
api.generateDigest()                 // 生成摘要 (body 传 user_id)
api.subscriptions.*                  // 订阅管理
api.sectors.*                        // 板块
api.searchStocks() / getStockQuotes() // 股票
api.getLiquidityMetrics() / ...      // 宏观
api.weeklyReport.*                   // 周报
```

**缓存机制**:
- CSR 页面通过 TanStack Query (`@tanstack/react-query`) 管理缓存
- 各 hook 按数据类型配置 `staleTime` / `gcTime`（详见 `hooks/queries/` 下各文件）
- 写操作通过 mutation 的 `onSuccess` 自动失效相关缓存
- `api.ts` 方法为纯 fetcher，不包含缓存逻辑

## 认证架构 (SDK + Server Proxy Refresh)

### 层级关系

```
InsforgeBrowserProvider (@insforge/nextjs)
  ├── 自动 session 恢复 (mount 时通过 insforge_refresh_token cookie)
  ├── OAuth 回调处理 (insforge_code 交换)
  ├── onSignIn  → POST /api/auth (SDK handler)
  ├── onSignOut → DELETE /api/auth (SDK handler)
  └── onRefresh → POST /api/auth (SDK handler)

AuthContext (useAuth hook)
  ├── 用 useInsforge() 读取 SDK 状态 (user, isLoaded)
  ├── 映射 InsforgeUser → 我们的 User 类型
  ├── signIn → sdk.signIn()
  ├── signUp → sdk.signUp() + emailRedirectTo=/verify-email?redirect=...
  ├── signOut → sdk.signOut() + clear React Query cache
  ├── resendVerificationEmail → sdk.resendVerificationEmail()
  ├── verifyEmail → sdk.verifyEmail()
  └── 纯 auth 包装，不再承载登录后订阅 side effect

auth.ts (纯函数，非 hook)
  ├── getAccessToken() — SDK session → cachedToken → Server Proxy refresh 三级降级
  ├── isTokenExpired() — 检查 JWT exp 字段（含 60 秒提前量）
  ├── resetStaleAuthState() — 清理陈旧 auth 状态并强制回登录页
  └── 密码重置函数 (3个) — 薄 SDK 封装

auth-verification.ts
  ├── buildVerifyEmailPath() — 统一生成 `/verify-email?redirect=...`
  ├── buildAbsoluteVerifyEmailUrl() — 给 `sdk.signUp()` 的 `emailRedirectTo`
  └── pending signup email/name 的 sessionStorage 辅助

auth-storage.ts
  └── seedClientAuthFromServer() — 因 SDK `initialState` 只 hydrate `user/userId`，
      仍需把 server token 写入 `insforge-auth-token` / `insforge-auth-user`
```

### Token 获取

```
getAccessToken():
  1. cachedToken 有效 → 直接返回（跳过 SDK + refresh）
  2. SDK session (insforge.auth.getCurrentSession(), 5s 超时) → accessToken
  3. SDK 返回 null 或过期 token → POST /api/auth { action: 'refresh' }（Server Proxy）
     - 成功后缓存 token 到 cachedToken，避免后续重复 refresh
     - 同时更新 SDK httpClient auth header 和 localStorage
  4. 两条路径都失败 → 返回 null

为什么 SDK refresh 会失败？
  SDK getCurrentSession() 内部尝试 POST /api/auth/refresh 到 Insforge 域名，
  但 refresh cookie 存在我们域名（themarketbrew.com），跨域不发送。
  所以我们用 Server Proxy refresh：Next.js server 读自己域名的 httpOnly cookie
  转发到 Insforge API 换新 token。

_authHeaders(..., { required: true }):
  短暂轮询 getAccessToken()
  等待登录态恢复，避免 “user 已恢复但 token 未恢复” 时过早打出匿名请求

resetStaleAuthState():
  先做 SDK signOut()，清掉内存态 user/session
  清理 insforge-auth-token / insforge-auth-user
  DELETE /api/auth 清当前域名 cookies
  跳到 /login?error=session_*
```

### 身份边界

- `api.generateDigest()` 不再接受 `userId`
- `api.sectors.subscribe()/unsubscribe()/getSubscriptions()` 不再接受 `userId`
- `api.watchlist.*` / `api.digests.*` / `api.screener.*` 这类受保护请求会在发起前短暂等待 token 恢复
- 这些接口统一依赖 `_authHeaders()` 提供 Bearer token，让后端从 token 决定身份

## 注意事项

- `api.ts` 的类型定义和 API 方法在同一文件，修改接口时注意同步
- `timezone.ts` 现在对所有“具体时刻”格式统一追加时区缩写/偏移（如 `PST` / `GMT+8`），避免仅显示时间造成歧义
- 需要认证的 API 方法用 `_authHeaders(..., { required: true })`，不需要认证的直接 fetch
- 受保护请求如果仍收到 401，会统一转成“登录已过期”；如果 token 恢复超时，会提示刷新或重新登录
- SDK 的内置 refresh 在跨域场景下不工作（cookie 在我们域名，不在 Insforge 域名），所以 `getAccessToken()` 总是会降级到 Server Proxy refresh
- `tryRefreshToken()` 成功后缓存 token 到模块级 `cachedToken`，后续调用直接返回缓存值，避免每次 API 请求都触发 SDK + refresh
- 受保护请求在检测到会话损坏时，会触发 `resetStaleAuthState()`，避免用户一直停留在半登录状态
- `api.ts` 方法为纯 fetcher，缓存由 TanStack Query 在 hooks 层管理
- `insforge.ts` 只负责创建 SDK client 实例
- 当前是 SDK 为主 + Server Proxy refresh 代理：`/api/auth` 大部分动作交给 SDK handler，refresh 由项目自己的 route 包装
- `Providers.tsx` 通过 `seedClientAuthFromServer()` 做最小兼容注入，不在其它模块散落写 localStorage

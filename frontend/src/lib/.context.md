# Lib - 共享工具库

## 功能概述

`src/lib/` 提供前端共享工具。认证相关代码当前走 server-cookie bridge：server actions / route handlers 调 `@insforge/sdk`，客户端通过 httpOnly cookies 和 `/api/auth/session` 恢复 session。

## `api.ts`

`api.ts` 保持简单边界：

- 需要登录的请求统一调用 `_authHeaders()`
- `_authHeaders()` 通过 `getAccessToken()` 拿 Bearer token
- `api.subscriptions.syncUser()` 也必须带 Bearer token；后端使用 token 中的 `user_id/email` 校验 body，避免客户端伪造 Resend contact 账号关联。
- 后端继续负责 `verify_user_token`
- 需要 401 refresh + retry 的受保护请求走 `fetchProtected()`；`api.user.onboardingStatus()` 和 `api.user.completeOnboarding()` 必须走这个路径。`onboardingStatus()` 只有在后端明确返回 `{"completed": false}` 时才表示未完成，认证、网络、5xx 失败必须抛错，不能伪装成 `{ completed: false }`。
- `onboarding-status.ts` 的 marker key 是 `onboarding_completed:{userId}`。`OnboardingGate` 先读这个 marker，已完成用户不再请求 `/user/onboarding-status`；后端返回 `completed:true` 或用户完成 onboarding 时写入 marker。
- `api.twitterDigest.*` 区分 Max-only 全文接口和公开 teaser 接口：`getLatest` / `getByDate` / `listArchive` 需要 Bearer token + `twitter_digest` entitlement；`getLatestTeaser` / `getTeaserByDate` / `listArchiveTeaser` 用于转化预览
- `api.getWatchlistMonitor()` 调用 `GET /api/watchlist-monitor`，返回 cached ticker briefs 组成的监控台数据；该接口需要 Bearer token 和 `for_you_website` entitlement，是 read path，不应触发 LLM 生成。`api.backfillWatchlistMonitor(symbols?)` 调用 `POST /api/watchlist-monitor/backfill`，只用于用户点击后补生成当前用户 watchlist 中缺失/过期/缺 market discussion cache 的 ticker；不传 `force`，也不触发 paid universe。`MonitorTickerRow` 同时包含列表字段和详情字段：`signal_types` / `top_signal` / `next_watchpoint` 用于列表聚合，完整 `signals` / `watchpoints` / `event_candidates` / `source_refs` 用于 `/for-you/monitor` 的单 ticker 工作台详情。`technical_monitor` 包含 monitor 页专用的技术面 summary、`technical_view`、关键价位和 deterministic 技术硬信号；完整图表由页面通过 `useTechnicalData(symbol, "daily")` 读取。`technical_view` 是技术面 tab 的主要展示契约，前端只渲染一段较完整的 `verdict` 和趋势/动能/位置/波动四个模块；动能维度覆盖 RSI/MACD，波动维度覆盖布林带/成交量。旧缓存没有该字段时前端回退到 summary。`event_candidates` 是未来 14 天监控项，包含财报/公司事件/社交观察点等；`market_discussion` 是后台生成的 Market Discussion tab payload，形状与 `TwitterTickerDiscussionResponse` 一致，同时其 overview/themes 压缩版会参与后台最终 `ai_take` 生成；monitor pipeline 不再使用 Twitter Digest 的 ticker thesis/hot tickers/watchpoints。前端只渲染缓存数据，不发起实时搜索或 LLM。
- `api.getTwitterTickerDiscussion(symbol, hours, limit)` 调用 `GET /api/twitter/ticker-discussion`，返回指定 ticker 近期缓存 Twitter/KOL 讨论：中文 `overview`（计数、多空、one-line summary）、可变数量 `themes`（主题摘要、证据 tweet id）和原文 `data`（stance、content_type、key_claim、sectors 等）。后端只读 DB 缓存，不触发 TwitterAPI.io 抓取；主题摘要是确定性中文聚合模板，不展示 representative quote，偏空观点/分歧/风险折叠进对应主题，不再返回独立 `risks` 展示契约。该 API 目前保留为调试/兼容入口，Monitor 页面主路径应读取 `api.getWatchlistMonitor()` 返回的 `market_discussion`。
- `paywall-analytics.ts` 的 checkout product 只支持 `pro`、`max`；旧 `ultra` / `creator_max_qinbafrank` 只在 payment backend / success page 做兼容归一化。
- `api.research.conversations.list({ limit, offset, search })` 支持服务端搜索标题和对话正文；`search` 会 trim 后作为 query param 发送，返回的 `ConversationSummary.search_matches` 可用于展示命中来源和片段。`ConversationSummary` 还带可选 `is_pinned/pinned_at/agent_id`，Research 页据此本地排序并在置顶时精确定位 runtime agent。重命名仍复用 `conversations.update()` 的全量保存契约，调用方必须传原始 `data/message_count`，只改标题时用 `touch:false` 避免刷新历史排序。置顶/取消置顶走 `api.research.conversations.pin(id, isPinned, agentId?)` 的轻量 `PATCH /research/conversations/{id}/pin`，更新 `agent_sessions.metadata.is_pinned/pinned_at`，不提交完整 conversation data。
- `api.research.chatStream()` 的 `ResearchRequest` 支持可选
  `conversation_id`。普通 `/research` 页面会把预分配或已有 conversation id
  传给后端，供 `agent_sessions` / `agent_session_events` 写入普通 Research
  runtime 记录。`ConversationSaveRequest.id` / `KolConversationSaveRequest.id`
  用于把最终保存的 `picker_conversations.id` 对齐同一个 runtime session id。
- `api.kolResearch.personas(scope)` 支持 page scope，默认 `scope=research`，用于让普通 `/research` 只展示主站 personas。Panda persona 不再通过普通 KOL chat 使用。
- `api.kolResearch.*` 提供 KOL Persona 投研助手方法 (`personas` / `chat` / `chatStream` + `conversations.list/get/create/update/delete`)；`chatStream()` 同样解析 SSE，事件类型为 `skill_activated` / `tool_call_start` / `tool_call_end` / `final` / `error`。相关类型: `KolPersonaSummary`、`KolPersonaChunk`、`KolToolCallSummary`、`KolResearchMessage`、`KolResearchRequest`、`KolResearchResponse`、`KolResearchStreamEvent`、`KolConversationSaveRequest`
- `api.communityPanda.*` 是 Panda Agent 专属客户端：`me` 读 email grant 状态，`chatStream` 调 `/api/community/panda/chat/stream`，`conversations.*` 只保存/读取/搜索/置顶 Panda 对话。它必须固定 `persona_username=pandacircle`，不能回退到通用 `/api/kol_research/chat/stream`。
- `api.adminPandaGrants.*` 供 `/admin/panda` 批量 dry-run/apply/revoke Panda email grants。
- `KolResearchStreamEvent.error` 支持 `code` / `detail` / `status`。后端 SSE error 透传 `agent_timeout`、`context_too_long`、`model_schema_error`、`agent_setup_error`、`agent_error`；前端 fetch 层会把非 2xx 响应转成 `http_error` 或 `auth_error`，把 135 秒 Abort 转成 `client_timeout`，把真正网络异常转成 `network_error`，不再把所有失败都抛给页面层变成泛化错误。

## 注意事项

- 认证逻辑分散在 `auth-cookies.ts`、`auth-error-presentation.ts`、`auth-redirect.ts`、`auth-verification.ts` 等文件中
- `currency.ts` 是股票金额显示的单一入口：显式 `profile.currency` 优先；缺失时按 symbol 后缀推断 (`.T`/纯 4 位日股 -> JPY, `.KS`/`.KQ` -> KRW, `.SS`/`.SZ` -> CNY, `.HK` -> HKD 等)。股票价格、持仓成本/市值、Research/KOL 面板不要手写 `$`。
- 头部股价、走势图刻度、52 周价格区间等密集 UI 使用 `compactPrice`，KRW/JPY/CNY 用 ISO 代码加原始报价（如 `KRW 193,500`、`JPY 2,752`、`CNY 11.31`），避免中文单位或字体中过重的货币符号；市值、营收、现金流继续使用普通 `compact`。
- 当前登录态使用 `app_access_token` / `app_refresh_token` first-party httpOnly cookies，客户端通过 `/api/auth/session` 读取和刷新 session。
- 不要引入 `@insforge/nextjs`

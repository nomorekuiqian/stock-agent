# Lib - 共享工具库

## 功能概述

`src/lib/` 提供前端共享工具。认证相关代码当前完全走 `@insforge/sdk` 客户端直接调用（SDK Direct），不经过 `/api/auth` server bridge。

## 核心文件

| 文件 | 职责 |
|------|------|
| `api.ts` | 统一 API 客户端，所有后端调用入口 |
| `auth.ts` | 登录、注册、OAuth、读取会话、Bearer token 获取、登出 |
| `auth-redirect.ts` | 登录后的 redirect path 管理（sessionStorage） |
| `auth-debug.ts` | 开发环境 auth 调试日志工具 |
| `insforge.ts` | 浏览器侧 Insforge SDK client 单例 |

## 认证架构

### `auth.ts`

当前 `auth.ts` 直接调用 `@insforge/sdk`，不走 `/api/auth`：

```text
signIn(email, password)
  -> insforge.auth.signInWithPassword({ email, password })
  -> setCachedSession(user, accessToken)

getCurrentAuthSession()
  1. 先看模块级内存缓存（_sessionCache，含 JWT 过期检查）
  2. 再读 SDK tokenManager in-memory session（getSdkSession）
  3. 都没有则调 insforge.auth.refreshSession()
  -> 返回 { authenticated, user, accessToken }

getAccessToken()
  -> 复用上面同一条链路，返回 accessToken

OAuth callback 场景（/auth/callback 页面）
  -> isOAuthCallbackRoute() 返回 true
  -> 委托给 getCallbackRouteSession()
  -> 调 insforge.auth.getCurrentUser()（内部 await SDK 的 authCallbackHandled，即 PKCE code exchange Promise）
  -> 读取 tokenManager 缓存结果，不再重复调 refreshSession
```

### 模块级缓存

`auth.ts` 维护一层模块级内存缓存 `_sessionCache`：

- 含 JWT 过期时间（`expiresAt`）
- 读取时有 60 秒缓冲，接近过期提前刷新
- 页面刷新后清零（纯内存，不持久化）

### OAuth Callback 竞态处理

SDK 在构造函数中启动 `detectAuthCallback()`，将 PKCE code exchange 封装为 `authCallbackHandled` Promise。只有 `getCurrentUser()` 内部会 `await authCallbackHandled`，其他方法（包括 `refreshSession()`）不等待。

因此：
- `/auth/callback` 页面挂载时，`AuthContext` 的初始 hydration 调 `getSessionWithRefresh()`
- `isOAuthCallbackRoute()` 检查当前路径，命中则走 `getCallbackRouteSession()` → `getCurrentUser()`
- 不走 `refreshSession()`，避免在 code exchange 完成前发出 401 请求

## `api.ts`

`api.ts` 保持简单边界：

- 需要登录的请求统一调用 `_authHeaders()`
- `_authHeaders()` 通过 `getAccessToken()` 拿 Bearer token
- 后端继续负责 `verify_user_token`

## 注意事项

- 刷新页面后 session 依赖 Insforge 域名的 refresh cookie（第三方 cookie）。无痕模式/Safari 下会失败，刷新后需重新登录。根本解决方案是实现 `/api/auth/route.ts` Server Bridge，见 `app/api/auth/.context.md`
- `insforge.auth.*` 在前端有完整使用：signIn、signUp、OAuth、session 刷新、登出均直接调 SDK
- 不要引入 `@insforge/nextjs`

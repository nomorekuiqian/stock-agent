# Lib - 共享工具库

## 功能概述

前端所有页面共享的核心工具库，包含 API 客户端、认证、数据库连接、工具函数。

## 核心文件

| 文件 | 职责 | 大小 |
|------|------|------|
| `api.ts` | 统一 API 客户端，所有后端调用入口 | ~1300 行 |
| `auth.ts` | 认证逻辑 (token 获取/刷新/密码重置) | ~250 行 |
| `auth-error-presentation.ts` | 认证错误 -> 用户提示语映射 | 小 |
| `auth-verification.ts` | 邮箱验证 redirect / pending signup 状态工具 | 小 |
| `auth-storage.ts` | localStorage token/user 存取 + 清理 | 小 |
| `auth-token.ts` | JWT 过期检查 | 小 |
| `auth-redirect.ts` | 重定向路径管理 | 小 |
| `insforge.ts` | Insforge SDK 客户端实例 | ~15 行 |
| `digest-utils.ts` | Digest 数据格式转换 | 小 |
| `stock-names.ts` | 股票代码->名称映射常量 | 小 |
| `portfolio-templates.ts` | 预设投资组合模板 | 小 |
| `timezone.ts` | 时区工具（业务日期按市场时区，展示时间自动带明确时区标签） | 小 |
| `utils.ts` | 通用工具函数 | 小 |

## api.ts 架构

```
_authHeaders(base, { required })     // 认证 header 工具 (Bearer Token)
// 缓存由 TanStack Query 管理 (hooks/queries/)

api.reports.*                        // 日报 (公开)
api.watchlist.*                      // 自选股 (需认证)
api.digests.*                        // 摘要历史 (需认证)
api.generateDigest()                 // 生成摘要 (body 传 user_id)
api.subscriptions.*                  // 订阅管理
api.sectors.*                        // 板块
api.searchStocks() / getStockQuotes() // 股票
api.getLiquidityMetrics() / ...      // 宏观
api.weeklyReport.*                   // 周报
```

**缓存机制**:
- CSR 页面通过 TanStack Query (`@tanstack/react-query`) 管理缓存
- 各 hook 按数据类型配置 `staleTime` / `gcTime`（详见 `hooks/queries/` 下各文件）
- 写操作通过 mutation 的 `onSuccess` 自动失效相关缓存
- `api.ts` 方法为纯 fetcher，不包含缓存逻辑

## 认证架构 (SDK + Server Proxy)

### 层级关系

```
Providers.tsx
  └── QueryClientProvider > ThemeProvider > AuthProvider > AuthSubscriptionSync > SubscriptionProvider
      (无 InsforgeBrowserProvider, 无 initialState)

AuthContext (useAuth hook) — 唯一 auth 状态源
  ├── useState<User | null> 管理用户状态
  ├── init effect: localStorage 恢复 -> Server Proxy refresh 降级
  ├── signIn -> POST /api/auth { action: 'sign-in' } (Server Proxy)
  ├── signUp -> insforge.auth.signUp({ email, password, emailRedirectTo })
  ├── signOut -> clearStaleAuthStateWithoutRedirect() + DELETE /api/auth
  ├── updateProfile -> insforge.auth.setProfile({ name })
  ├── verifyEmail -> POST /api/auth { action: 'verify-email', otp, email? }
  ├── resendVerificationEmail -> insforge.auth.resendVerificationEmail({ email })
  ├── signInWithGoogle -> insforge.auth.signInWithOAuth({ provider, redirectTo: '/auth/callback' })
  ├── completeOAuthCallback -> POST /api/auth { action: 'oauth-exchange', code, codeVerifier }
  └── refreshUser -> POST /api/auth { action: 'refresh' }

auth.ts (纯函数，非 hook)
  ├── getAccessToken() — localStorage -> Server Proxy refresh 降级
  ├── getAccessTokenResolution() — 区分 authenticated / no_session / transient_failure
  ├── isTokenExpired() — 检查 JWT exp 字段（含 60 秒提前量）
  ├── cleanupAuthCallbackUrlParams() — 清理回调 URL 参数
  ├── bridgeAuthSessionToCookies() — 用 access token 补写 first-party session cookie
  ├── syncClientAuthSession() — 统一同步 localStorage + SDK httpClient
  ├── clearStaleAuthStateWithoutRedirect() — 清缓存 / SDK header / cookies，不跳转
  ├── resetStaleAuthState() — 清理陈旧 auth 状态并强制回登录页
  └── 密码重置函数 (3个) — 薄 SDK 封装

auth-error-presentation.ts
  └── getAuthErrorPresentation() — 底层 auth 错误 -> 用户可读提示

auth-verification.ts
  ├── buildVerifyEmailPath() — 统一生成 /verify-email?redirect=...
  ├── buildAbsoluteVerifyEmailUrl() — 给 signUp 的 emailRedirectTo
  └── pending signup email/name 的 sessionStorage 辅助

auth-storage.ts
  ├── INSFORGE_AUTH_TOKEN_KEY / INSFORGE_AUTH_USER_KEY — localStorage key 常量
  └── clearClientAuthStorage() — 清除 localStorage 中的 auth token 和 user 数据
```

### Token 获取

```
getAccessToken():
  1. localStorage 有 insforge-auth-token 且未过期 -> 直接返回
  2. token 不存在或已过期 -> POST /api/auth { action: 'refresh' } (Server Proxy)
     - 成功后通过 syncClientAuthSession() 缓存 token
     - 同时更新 SDK httpClient auth header 和 localStorage
     - 对网络抖动/5xx 做短重试，减少误判
  3. refresh 失败 -> 返回 null

为什么不用 SDK 内置 refresh?
  SDK getCurrentSession() 内部尝试 POST /api/auth/refresh 到 Insforge 域名，
  但 refresh cookie 存在我们域名（themarketbrew.com），跨域不发送。
  所以我们用 Server Proxy refresh：Next.js server 读自己域名的 httpOnly cookie
  转发到 Insforge API 换新 token。

_authHeaders(..., { required: true }):
  短暂轮询 getAccessToken()
  等待登录态恢复，避免 "user 已恢复但 token 未恢复" 时过早打出匿名请求

resetStaleAuthState():
  清理 insforge-auth-token / insforge-auth-user
  DELETE /api/auth 清当前域名 cookies
  跳到 /login?error=session_*
```

### 身份边界

- `api.generateDigest()` 不再接受 `userId`
- `api.sectors.subscribe()/unsubscribe()/getSubscriptions()` 不再接受 `userId`
- `api.watchlist.*` / `api.digests.*` / `api.screener.*` 这类受保护请求会在发起前短暂等待 token 恢复
- 这些接口统一依赖 `_authHeaders()` 提供 Bearer token，让后端从 token 决定身份

## 注意事项

- `api.ts` 的类型定义和 API 方法在同一文件，修改接口时注意同步
- `timezone.ts` 对所有"具体时刻"格式统一追加时区缩写/偏移（如 `PST` / `GMT+8`）
- 需要认证的 API 方法用 `_authHeaders(..., { required: true })`，不需要认证的直接 fetch
- 受保护请求如果仍收到 401，会统一转成"登录已过期"；前端不再自动强制登出，而是提示用户先 `Command + Shift + R` 刷新
- SDK 的内置 refresh 在跨域场景下不工作，`getAccessToken()` 会降级到 Server Proxy refresh
- `tryRefreshToken()` 成功后缓存 token 到模块级 `cachedToken`，后续调用直接返回缓存值
- `AuthContext.signIn()` 和 init effect 恢复都会调用 `syncClientAuthSession()`，避免半登录状态
- 邮箱验证和 OAuth callback 不能只停留在 SDK 本地 session；必须再走一次 Server Proxy，把 `insforge-session` / `insforge-refresh` / `insforge-csrf` 同步回应用域名
- `bridgeAuthSessionToCookies()` 只负责补写 first-party cookie，不会替代真正的 refresh token bridge；能走 `verify-email` / `oauth-exchange` proxy 时优先走 proxy
- `AuthContext` 初始化完成后调用 `cleanupAuthCallbackUrlParams()` 清理回调 URL 参数
- 受保护请求在恢复窗口内如果只遇到 `transient_failure`，会返回可重试错误，不触发强制重登
- 受保护请求如果第一次因过期 token 收到 401，但 `forceRefresh` 成功，`api.ts` 会自动重试一次
- production canonical host 是 `www.themarketbrew.com`；`/api/auth` cookie 用 `.themarketbrew.com` 域
- Server Proxy refresh 成功后同时更新 `insforge-csrf` 和 `insforge_csrf_token`
- `api.ts` 方法为纯 fetcher，缓存由 TanStack Query 在 hooks 层管理
- `insforge.ts` 只负责创建 SDK client 实例
- `@insforge/sdk` 所有 auth 方法返回 `{ data, error }` wrapper，调用时必须解构

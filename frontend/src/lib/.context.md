# Lib - 共享工具库

## 功能概述

前端所有页面共享的核心工具库，包含 API 客户端、认证、数据库连接、工具函数。

## 核心文件

| 文件 | 职责 | 大小 |
|------|------|------|
| `api.ts` | 统一 API 客户端，所有后端调用入口 | ~1300 行 |
| `auth.ts` | 认证逻辑 (登录/注册/OAuth/密码重置) | ~290 行 |
| `insforge.ts` | Insforge SDK 客户端实例 | ~15 行 |
| `digest-utils.ts` | Digest 数据格式转换 | 小 |
| `stock-names.ts` | 股票代码→名称映射常量 | 小 |
| `portfolio-templates.ts` | 预设投资组合模板 | 小 |
| `timezone.ts` | 时区工具 (美西时间为主) | 小 |
| `utils.ts` | 通用工具函数 | 小 |

## api.ts 架构

```
_authHeaders(base)                   // 认证 header 工具 (Bearer Token)
// 缓存由 TanStack Query 管理 (hooks/queries/)

api.reports.*                        // 日报 (公开)
api.watchlist.*                      // 自选股 (需认证)
api.digests.*                        // 摘要历史 (需认证)
api.generateDigest()                 // 生成摘要 (body 传 user_id)
api.subscriptions.*                  // 订阅管理
api.sectors.*                        // 板块
api.searchStocks() / getStockQuotes() // 股票
api.getLiquidityMetrics() / ...      // 宏观
api.weeklyReport.*                   // 周报
```

**缓存机制**:
- CSR 页面通过 TanStack Query (`@tanstack/react-query`) 管理缓存
- 各 hook 按数据类型配置 `staleTime` / `gcTime`（详见 `hooks/queries/` 下各文件）
- 写操作通过 mutation 的 `onSuccess` 自动失效相关缓存
- `api.ts` 方法为纯 fetcher，不包含缓存逻辑

## 认证架构

### 层级关系

```
InsforgeBrowserProvider (@insforge/nextjs)
  ├── 自动 session 恢复 (mount 时)
  ├── OAuth 回调处理 (insforge_code 交换)
  ├── onSignIn  → POST /api/auth (sync-token, 由 SDK 处理)
  ├── onSignOut → DELETE /api/auth (清除所有 cookies)
  └── onRefresh → POST /api/auth (sync-token, 由 SDK 处理)

AuthContext (useAuth hook)
  ├── 用 useInsforge() 读取 SDK 状态 (user, isLoaded)
  ├── 映射 InsforgeUser → 我们的 User 类型
  ├── 自定义 signIn → server proxy (/api/auth login) + sdk.setUser()
  ├── Cookie recovery (页面刷新时 fetch /api/auth/session → sdk.setUser())
  ├── isRecovering 状态 (初始 true, 防止 auth guard 竞态)
  ├── signOut → sdk.signOut() (触发 onSignOut 回调)
  └── Subscription sync (唯一的自定义业务逻辑)

auth.ts (纯函数，非 hook)
  ├── signIn() — server proxy 登录 (捕获 refresh token)
  ├── getAccessToken() — 供 api.ts 的 _authHeaders() 使用
  ├── signUp/signOut/signInWithGoogle/updateProfile — 薄 SDK 封装
  └── 密码重置函数 (3个) — 薄 SDK 封装
```

### Token 恢复链

```
getAccessToken():
  1. SDK session (insforge.auth.getCurrentSession())
  2. httpOnly Cookie recovery (/api/auth/session → refresh token)
```

### Cookies (由 /api/auth 管理)

| Cookie | 来源 | 用途 |
|--------|------|------|
| `insforge-session` | SDK handler + server proxy | Access token |
| `insforge-user` | SDK handler | 用户信息 (SSR) |
| `insforge-refresh` | Server proxy login only | Refresh token |
| `insforge-csrf` | Server proxy login only | CSRF token |

## 注意事项

- `api.ts` 的类型定义和 API 方法在同一文件，修改接口时注意同步
- 需要认证的 API 方法用 `_authHeaders()`，不需要认证的直接 fetch
- `api.ts` 方法为纯 fetcher，缓存由 TanStack Query 在 hooks 层管理
- `insforge.ts` 只负责创建 SDK client 实例，不再有额外的 token 缓存
- Server proxy login (`/api/auth` POST login) 是唯一不能替代的自定义代码，因为 Insforge 的 refresh token 只在 Set-Cookie 头中返回

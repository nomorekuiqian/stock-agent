# Contexts - React Context Providers

## 功能概述

全局状态通过 React Context 提供，挂载在 `components/Providers.tsx` 中。

当前认证体系完全走 `@insforge/sdk` 客户端直接调用（SDK Direct）：

- `Providers.tsx` 不再包 `InsforgeBrowserProvider`
- `AuthContext` 成为唯一前端 auth 状态源
- 路由保护由项目自定义 `middleware.ts` 完成（检查 `insforge_csrf_token` first-party cookie）
- 无 `/api/auth` server bridge（当前不存在）

## 文件

| 文件 | 职责 |
|------|------|
| `AuthContext.tsx` | 认证状态、登录/注册/验证邮箱/登出、登录后用户同步 |
| `SubscriptionContext.tsx` | 订阅状态与支付入口 |

## AuthContext

### 提供的值

```typescript
{
  user: User | null,
  isLoading: boolean,
  isAuthenticated: boolean,
  setAuthenticatedUser: (user: User | null) => void,
  signIn(email, password): Promise<AuthActionResult>,
  signUp(email, password, name?, redirectPath?): Promise<SignUpResult>,
  signOut(): Promise<AuthActionResult>,
  signInWithGoogle(): Promise<AuthActionResult>,
  updateProfile({ name }): Promise<AuthActionResult>,
  resendVerificationEmail(email): Promise<AuthActionResult>,
  verifyEmail(otp, email?): Promise<AuthActionResult>,
  refreshUser(): Promise<void>,
}
```

### 状态来源

启动流程：

```text
mount
  -> AuthContext 调 getCurrentAuthSession()（lib/auth.ts）
  -> auth.ts：模块缓存 → SDK tokenManager → insforge.auth.refreshSession()
  -> 返回 { authenticated, user, accessToken }
  -> AuthContext setUser / setIsLoading(false)
```

不依赖：
- `useInsforge()`
- `sdk.isLoaded`
- `sdk.reloadAuth()`
- `/api/auth` server bridge

### 登录

邮箱密码登录：
- `signIn()` → `lib/auth.ts signIn()` → `insforge.auth.signInWithPassword()`
- 成功后 `setUser(result.user)`

Google OAuth：
- `signInWithGoogle()` → `lib/auth.ts signInWithGoogle()` → `insforge.auth.signInWithOAuth({ provider: 'google', redirectTo: '/auth/callback' })`
- 浏览器跳转到 Google 授权页
- 回跳 `/auth/callback` → `completeOAuthSignIn()` → `insforge.auth.getCurrentUser()`（等待 PKCE code exchange）
- `setAuthenticatedUser(result.user)` 直接注入用户状态，不再调 `refreshUser()`

### 注册与邮箱验证

- `signUp()` → `insforge.auth.signUp()`
- 需要验证邮箱时返回 `requiresEmailVerification`，跳转 `/verify-email`
- `verifyEmail()` → `insforge.auth.verifyEmail({ otp, email })`
- 验证成功后直接 `setUser(result.user)`

### 登出

1. `authSignOut()` → `insforge.auth.signOut()`
2. 清 `_sessionCache`，清 SDK http auth header
3. 清 `AuthContext` user
4. `queryClient.clear()`

## SubscriptionContext

`SubscriptionContext` 没有因为本轮 auth 改造改变职责，仍然：

- 依赖 `AuthContext`
- 负责订阅状态、checkout、billing portal
- 通过 `getAccessToken()` 为付费接口补 Bearer token

## 注意事项

- 不要再把 `@insforge/nextjs` provider/hook 接回 `Providers.tsx`
- `AuthContext` 是前端唯一 auth 状态源
- 刷新页面后 session 恢复依赖第三方 cookie（Insforge 域名），无痕模式/Safari 下失效；根本修复需实现 `/api/auth/route.ts` Server Bridge

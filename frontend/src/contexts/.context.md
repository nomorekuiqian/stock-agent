# Contexts - React Context Providers

## 功能概述

全局状态管理，通过 React Context 提供认证和订阅状态。挂载在 `components/Providers.tsx` 中。

## 文件

| 文件 | 职责 | 依赖 |
|------|------|------|
| `AuthContext.tsx` | 用户认证状态 (登录/登出/用户信息) | `@insforge/nextjs`, `@/lib/auth` |
| `SubscriptionContext.tsx` | 订阅状态 (isPro/plan/checkout) | `AuthContext`, `@/lib/auth` |

## AuthContext

### 提供的值

```typescript
{
  user: User | null,       // 当前用户
  isLoading: boolean,      // SDK 加载中 (!sdk.isLoaded)
  isAuthenticated: boolean, // user !== null
  signIn(email, password): Promise<void>,
  signOut(): Promise<void>,
}
```

### Session 恢复流程 (纯 SDK 模式)

```
mount → InsforgeBrowserProvider 初始化
  ├── SDK 自动尝试 refresh (发送 insforge_refresh_token cookie 到 Insforge 服务器)
  ├── 成功 → sdk.user 更新 → AuthContext.user 更新
  └── 失败 → sdk.user = null → 未登录状态
```

SDK 通过 `useInsforge()` hook 提供用户状态，AuthContext 只做类型映射和业务逻辑（订阅同步）。

## SubscriptionContext

### 提供的值

```typescript
{
  isPro: boolean,              // 是否 Pro 用户
  isLoading: boolean,          // 订阅状态查询中
  plan: string,                // 'free' | 'pro'
  status: string,              // 'active' | 'trialing' | ...
  createCheckout(returnPath?),  // 发起支付
  openBillingPortal(),          // 打开账单管理
  refreshSubscription(),        // 刷新订阅状态
}
```

### PAYWALL_ENABLED 开关

`NEXT_PUBLIC_ENABLE_PAYWALL=true` 时才查询订阅 API，否则 `isPro=true` 跳过所有付费墙。

模块级常量，运行时不可改变。测试中无法通过 `vi.stubEnv()` 修改。

### 缓存

localStorage `sub_status` 缓存订阅状态，TTL 5 分钟，按 userId 隔离。

## 注意事项

- 两个 Context 都是 `'use client'`，只在客户端组件中可用
- 嵌套顺序: `AuthProvider` > `SubscriptionProvider` (订阅依赖认证)
- 在 Provider 外调用 `useAuth()` / `useSubscription()` 会抛错

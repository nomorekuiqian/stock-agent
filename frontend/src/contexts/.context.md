# Contexts - React Context Providers

## 功能概述

全局状态管理，通过 React Context 提供认证和订阅状态。挂载在 `components/Providers.tsx` 中。

## 文件

| 文件 | 职责 | 依赖 |
|------|------|------|
| `AuthContext.tsx` | 用户认证状态 (登录/登出/用户信息) | `@insforge/nextjs`, `@/lib/auth` |
| `SubscriptionContext.tsx` | 订阅状态 (isPro/plan/checkout) | `AuthContext`, `@/lib/auth` |

## AuthContext

### 提供的值

```typescript
{
  user: User | null,       // 当前用户
  isLoading: boolean,      // SDK 加载中 (!sdk.isLoaded)
  isAuthenticated: boolean, // user !== null
  signIn(email, password): Promise<void>,
  signUp(email, password, name?, redirectPath?): Promise<{ success, requiresEmailVerification? }>,
  resendVerificationEmail(email): Promise<void>,
  verifyEmail(otp, email?): Promise<void>,
  signOut(): Promise<void>,
}
```

### Session 恢复流程 (initialState + SDK 模式)

```
页面请求 → layout.tsx (Server Component)
  -> getAuthFromCookies() 从 httpOnly cookie 读取 user
  -> initialState = { user, userId } 传给 Providers

mount → InsforgeBrowserProvider 初始化
  ├── 有 initialState → 立即设置 user + isLoaded=true (无闪烁)
  │   └── 异步 getCurrentSession() 刷新完整 session (含 access token)
  ├── 无 initialState → SDK 自动尝试 refresh (发送 cookie 到 Insforge 服务器)
  ├── 成功 → sdk.user 更新 → AuthContext.user 更新
  └── 失败 → sdk.user = null → 未登录状态
```

SDK 通过 `useInsforge()` hook 提供用户状态，AuthContext 现在只做认证状态映射和基础 auth 动作封装。

登录后的订阅同步、副作用逻辑已拆到 `components/AuthSubscriptionSync.tsx`，避免认证层混入业务 side effect。

邮箱密码登录和 mount 时的 refresh 恢复，现在都会先把返回的 `accessToken` 同步到客户端 session 层（SDK http client + localStorage），再更新 `sdk.user`。这样可以避免出现“UI 看起来已登录，但受保护 API 还拿不到 token”的半登录状态。

OAuth / callback 场景下，`AuthContext` 还会在 SDK 初始化和恢复链结束后，兜底清理 URL 中残留的 `insforge_code` / `access_token` / `user_id` / `email` 参数，避免用户在目标页持续看到回调参数。

**关键**: `initialState` 解决了页面刷新时的"闪烁未登录"问题 — 在 SDK 异步初始化完成前，用户就已经看到登录状态。详见 `frontend/docs/auth.md` 的"SDK 自动登录架构"章节。

## SubscriptionContext

### 提供的值

```typescript
{
  isPro: boolean,              // 是否 Pro 用户
  isLoading: boolean,          // 订阅状态查询中
  plan: string,                // 'free' | 'pro'
  status: string,              // 'active' | 'trialing' | ...
  createCheckout(returnPath?),  // 发起支付
  openBillingPortal(),          // 打开账单管理
  refreshSubscription(),        // 刷新订阅状态
}
```

### PAYWALL_ENABLED 开关

`NEXT_PUBLIC_ENABLE_PAYWALL=true` 时才查询订阅 API，否则 `isPro=true` 跳过所有付费墙。

模块级常量，运行时不可改变。测试中无法通过 `vi.stubEnv()` 修改。

### 缓存

localStorage `sub_status` 缓存订阅状态，TTL 5 分钟，按 userId 隔离。

## 注意事项

- 两个 Context 都是 `'use client'`，只在客户端组件中可用
- 嵌套顺序: `AuthProvider` > `SubscriptionProvider` (订阅依赖认证)
- 在 Provider 外调用 `useAuth()` / `useSubscription()` 会抛错
- `signInWithGoogle()` 会优先使用 `sessionStorage.auth_redirect`，默认回到 `/today`
- 登录/注册成功后的跳转现在由登录页监听 `isAuthenticated` 统一处理
- 注册后如果 SDK 返回 `requireEmailVerification=true`，登录页会跳到 `/verify-email`
- `AuthContext.signUp()` 现在会构造 `emailRedirectTo=/verify-email?redirect=...`，兼容邮件链接验证
- `AuthContext.resendVerificationEmail()` 会把 SDK 空返回归一成失败，避免 UI 误报“已发送”

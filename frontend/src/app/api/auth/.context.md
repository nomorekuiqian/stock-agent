# Auth API Route - SDK 认证路由

## 功能概述

`/api/auth` 只做一件事：把认证相关请求委托给 `@insforge/nextjs/api` 的 `createAuthRouteHandlers`。

这里没有自定义登录逻辑，也没有手写 refresh/csrf cookie 管理。真实 session 生命周期由 Insforge SDK 负责。

## 文件

| 文件 | 职责 |
|------|------|
| `route.ts` | 导出 SDK 的 `POST/GET/DELETE` handlers |

## 端点

| 方法 | 路径 | 功能 |
|------|------|------|
| `POST` | `/api/auth` | SDK 保存/同步认证态 |
| `GET` | `/api/auth` | SDK 查询当前认证态 |
| `DELETE` | `/api/auth` | SDK 清理认证态 |

## 协作关系

认证恢复依赖这几层一起工作：

1. `frontend/src/app/api/auth/route.ts`
2. `frontend/middleware.ts`
3. `frontend/src/app/layout.tsx` 的 `auth()`
4. `frontend/src/components/Providers.tsx` 的 `InsforgeBrowserProvider`
5. `frontend/src/contexts/AuthContext.tsx`

## 注意事项

- 这里不是旧文档里的“server proxy 登录入口”
- 页面鉴权和接口鉴权分离，后端业务接口仍要自己做 `verify_user_token`

# Auth API Route - Server Proxy 认证

## 功能概述

Next.js API Route，作为 Insforge 认证服务的 server proxy。解决浏览器无法读取跨域 `Set-Cookie` 的问题。

## 文件

| 文件 | 职责 |
|------|------|
| `route.ts` | POST (login/sync-token) + DELETE (logout) |
| `session/route.ts` | GET (session) - cookie recovery 独立端点 |
| `helpers.ts` | 纯函数: `buildCookieOptions`, `extractRefreshToken` |

## 端点

| 方法 | 路径 | 功能 | 触发者 |
|------|------|------|--------|
| `POST` (action=login) | `/api/auth` | 代理登录请求到 Insforge，从 Set-Cookie 头提取 refresh token 存入我们域名的 cookie | `auth.ts signIn()` |
| `POST` (action=sync-token) | `/api/auth` | SDK 登录/刷新回调，同步 token 到 cookie | Insforge SDK handler |
| `GET` | `/api/auth/session` | 从 cookie 恢复 session (refresh token → 新 access token) | `AuthContext` cookie recovery |
| `DELETE` | `/api/auth` | 清除所有认证 cookie | `auth.ts signOut()` |

## Cookie 管理

| Cookie | 内容 | 来源 |
|--------|------|------|
| `insforge-session` | Access token | login + sync-token |
| `insforge-refresh` | Refresh token | login only (从 Set-Cookie 头提取) |
| `insforge-csrf` | CSRF token | login only |
| `insforge-user` | 用户信息 JSON | sync-token |

## 注意事项

- 这是前端唯一不能删除的自定义代码：Insforge 的 refresh token 只在 `Set-Cookie` 响应头中返回
- `helpers.ts` 已提取为纯函数，有独立的单元测试
- Refresh 请求需要三个 header: `Cookie: insforge_refresh_token`, `X-CSRF-Token`, `Authorization: Bearer <anonKey>`
- `rememberMe` 控制 cookie `maxAge` (7天 vs session)

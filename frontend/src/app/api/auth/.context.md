# Auth API Route - 当前状态

## 当前情况

前端认证已经迁移到 server-cookie bridge：

- 登录/注册/邮箱验证通过 `frontend/src/app/actions/auth.ts` server actions 调 Insforge SDK
- OAuth 回调通过 `frontend/src/app/auth/callback/route.ts` 在服务端 exchange code
- Session 恢复通过 `frontend/src/app/api/auth/session/route.ts`
- Token 存在本域 first-party httpOnly cookies：`app_access_token` / `app_refresh_token`

根目录 `/api/auth/route.ts` 仍不存在；当前公开的 session route 是 `/api/auth/session`。

## Cookie 与 Session

- `app_access_token`: 15 分钟 TTL
- `app_refresh_token`: 7 天 TTL
- `middleware.ts` 只检查是否存在任一 cookie，真正校验和刷新由 `/api/auth/session` 完成
- `AuthContext` 在客户端缓存 access token，并每 12 分钟刷新一次；业务 API 的 401 retry 由 `fetchProtected()` 调 `refreshSession()` 完成

`/api/auth/session` 流程：

```text
读取 app_access_token / app_refresh_token
  -> 有 access token 时先 getCurrentUser() 验证
  -> access 缺失或失效时用 refresh token refreshSession()
  -> refresh 成功后续写 cookies 并返回 { user, accessToken }
  -> refresh 失败时清 cookies，返回 unauthenticated
```

## OAuth Callback

`/auth/callback` 服务端处理：

```text
读取 insforge_code/code
  -> 读取并清理 app_oauth_cv
  -> exchangeOAuthCode()
  -> setAuthCookies(accessToken, refreshToken)
  -> 非阻塞查询 /user/onboarding-status
  -> brand-new / 未完成用户跳 /onboarding，否则跳 redirect
```

Onboarding 状态查询失败必须回落到原 redirect，不应阻断登录。

## 注意事项

- 不要引入 `@insforge/nextjs`
- 不要回退到浏览器直连 Insforge refresh cookie；生产恢复能力依赖本域 first-party cookies
- `OnboardingGate` 会先读 `onboarding_completed:{userId}` localStorage marker，已完成用户不再请求后端；`api.user.onboardingStatus()` 必须只在后端明确返回 `completed:false` 时触发 onboarding；401、5xx、网络失败不能被当成未完成

# Auth API Route - Server Proxy 认证路由

## 功能概述

`/api/auth` 是认证的 Server Proxy 层，解决 Insforge SDK 跨域 cookie 问题：

- `POST { action: 'sign-in' }`：Server Proxy 登录。服务端调用 Insforge 登录 API，从 Set-Cookie 响应头提取 refresh token，存储为我们域名的 httpOnly cookie。这是登录的**主链路**（SDK 直接登录无法在我们域名存储 refresh token）
- `POST { action: 'refresh' }`：Server Proxy 刷新。读取我们域名的 refresh cookie，转发给 Insforge 换新 access token
- `DELETE`：在 SDK 清理基础上，额外删除所有 auth cookies

## 文件

| 文件 | 职责 |
|------|------|
| `route.ts` | Server Proxy 登录/刷新 + SDK 的 `POST/GET/DELETE` handlers |

## 端点

| 方法 | 路径 | 功能 |
|------|------|------|
| `POST` | `/api/auth` | `action=sign-in`: 代理登录；`action=refresh`: 刷新 token；其他: SDK 处理 |
| `GET` | `/api/auth` | SDK 查询当前认证态 |
| `DELETE` | `/api/auth` | SDK 清理认证态 + 清除所有 auth cookies |

## 登录流程

```
AuthContext.handleSignIn(email, password)
  → POST /api/auth { action: 'sign-in', email, password }
    → Server: POST Insforge/api/auth/sessions
    → 提取 Set-Cookie 中的 refresh token
    → 设置我们域名的 cookies (session, user, refresh, csrf)
    → 返回 { accessToken, user, csrfToken }
  → 前端同步 accessToken 到 SDK/httpClient/localStorage
  → sdk.setUser(user) 更新 React 状态
```

## 管理的 Cookies

| Cookie 名 | 内容 | 用途 |
|-----------|------|------|
| `insforge-session` | access token | SSR 认证 |
| `insforge-user` | 用户 JSON | SSR 用户数据 |
| `insforge-refresh` | refresh token | Server Proxy 刷新 |
| `insforge_refresh_token` | refresh token (兼容) | 旧格式兼容 |
| `insforge-csrf` | CSRF token | 刷新请求验证 |

## 注意事项

- 登录必须通过 Server Proxy（`action=sign-in`），不能用 SDK 直接登录。原因：SDK 登录时 Insforge 的 refresh token 设在 Insforge 域名的 cookie 上，跨域 SameSite 策略阻止我们读取
- 代理转发到 Insforge `/api/auth/sessions` 和 `/api/auth/refresh` 时，需要同时带 `Authorization: Bearer <anonKey>` 与 `apikey: <anonKey>`，保持和服务端校验接口一致
- 页面鉴权和接口鉴权分离，后端业务接口仍要自己做 `verify_user_token`

# app/api/mcp — MCP Authorization Route Handlers

## Purpose

Server-side bridge between a logged-in website session and the backend MCP
device authorization flow.

## Routes

- `POST /api/mcp/authorize` accepts form data with `user_code`, reads
  `app_access_token` from first-party auth cookies, and calls
  `POST /api/kol_research/mcp/auth/device/authorize` with
  `Authorization: Bearer <website_access_token>`.

## Failure Behavior

- Missing `user_code` redirects back to `/mcp/authorize` with an error.
- Missing website access token redirects to `/login?redirect=/mcp/authorize?...`.
- Backend errors redirect back to the authorize page with a short error query.

This route never returns or stores MCP bearer tokens. Token exchange happens in
the MCP adapter through `market_lens_auth_status`.

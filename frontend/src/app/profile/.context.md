# Profile - 用户资料与订阅设置页

## 页面概述

`/profile` 是用户账户页，包含昵称、订阅状态、Stripe portal、邮件偏好和权益说明。

## 文件结构

| 文件 | 职责 |
|------|------|
| `page.tsx` | profile 表单、订阅状态、邮件偏好编辑 |
| `__tests__/page.test.tsx` | auth/subscription/entitlement 状态回归 |

## 数据流

- `useAuth()` 提供 user、登录态和 `updateProfile()`。
- `useSubscription()` 提供 plan/status、checkout、billing portal。
- `useSubscription()` 也提供 Stripe scheduled cancellation 字段；已取消但仍在当前周期内的付费订阅继续展示会员档位，同时显示“订阅已取消 / 权益有效至 ...” indicator。
- `useSubscription()` 暴露后端从当前 Stripe subscription item 同步的真实计费字段：`billingAmountCents`、`billingCurrency`、`billingInterval`、`billingIntervalCount`。订阅卡的自动续费价格必须优先使用这些字段，不要用公开价格常量推断历史/早鸟价用户的续费金额。
- `useSubscription().openBillingPortal()` 是统一“管理订阅”入口；后端会按本地 subscription 所属账号选择 primary 或 legacy Stripe account 创建 Portal session。`useSubscription().cancelSubscription()` 仍提供不依赖 Stripe Portal 的直接取消兜底；Profile 的“取消自动续费”按钮先确认，再把订阅设为周期末取消。
- 进入或切换到 `subscription` tab 时会主动调用 `refreshSubscription()`，避免 React Query 的 5 分钟缓存让用户看到后台/Stripe 已更新前的旧 plan/status。
- `useEntitlements()` 决定邮件偏好是否可开启。
- 偏好保存调用 `api.subscriptions.updatePreferences(diff)`。

## 注意事项

- 未登录时跳 `/login?redirect=/profile`。
- 订阅卡直接按 API 返回的 `plan/status` 展示 Free/Pro/Max/Ultra/已取消等状态；Ultra 显示为 Max 权益 + Qinbafrank 资料包，不依赖 `isPro/isMax` 推断。
- Stripe Portal 周期末取消时仍保留付费权限到 `cancel_at` / `current_period_end`；订阅卡要显示“已取消”“权益有效至”，但仍保留管理订阅入口。
- 当真实计费字段缺失时，订阅卡显示“原订阅价格 · 自动续费”，不能回退到当前公开 Max `$20/月`，以免误导早鸟价用户。
- “管理订阅”不要在前端按账号分叉；调用 `openBillingPortal()` 即可。迁移前 Stripe 账户的 customer/subscription 由后端用 `STRIPE_LEGACY_SECRET_KEY` 创建旧账号 Portal session；如果 Portal 配置不可用，直接取消 endpoint 仍可 fallback 到旧账户 API key。
- 邮件偏好必须按 entitlement 强制约束，不能只依赖 UI disabled。
- `openBillingPortal()` 通常会页面跳转，按钮 loading 状态不要假设 promise 一定返回。

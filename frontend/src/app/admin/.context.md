# Admin - 管理后台页面

## 页面概述

`/admin` 是运营/CRM 管理后台，包含用户列表、用户详情、feature flags、LLM 用量和活跃趋势。所有页面都通过 server-side cookie 读取 access token，再调用后端 admin API。

## 路由

| 路由 | 页面 | 数据来源 | 认证 |
|------|------|----------|------|
| `/admin` | 用户管理看板 | `GET /api/admin/dashboard` | admin |
| `/admin/activity` | DAU / WoW / MoM 活跃趋势 | `GET /api/admin/activity?days=60` | admin |
| `/admin/flags` | Feature Flag 管理 | `/api/admin/flags` | admin |
| `/admin/llm-usage` | LLM token/cost 面板 | `GET /api/admin/llm-usage?days=N` | admin |
| `/admin/users/[id]` | 用户详情/CRM 操作 | `/api/admin/crm/*` | admin |

## 文件结构

| 文件 | 职责 |
|------|------|
| `page.tsx` | dashboard server page，刷新 cookie 后调用 admin dashboard |
| `_components/AdminDashboard.tsx` | 用户列表、筛选、分页、bulk profile 更新 |
| `activity/page.tsx` | 活跃趋势 server page |
| `activity/_components/ActivityComparisonPanel.tsx` | 活跃趋势图表与区间比较 |
| `flags/page.tsx` / `flags/_components/FlagsAdminPanel.tsx` | feature flag 查询、写入、删除 |
| `llm-usage/page.tsx` / `llm-usage/_components/LlmUsagePanel.tsx` | LLM 用量查询与展示 |
| `users/[id]/page.tsx` / `users/[id]/_components/UserDetail.tsx` | 用户详情、CRM 资料、互动记录、授权操作 |

## 认证与错误处理

- 页面先通过 `getAuthCookies()` 读取 `app_access_token` / `app_refresh_token`。
- access token 缺失但 refresh token 存在时，server page 会调用 Insforge refresh 并续写 cookies。
- `/admin` 和 `/admin/users/[id]` 对 401/403 使用 `notFound()` 隐藏后台存在性。
- `/admin/activity` 对无 token / 401 显式跳 `/login?redirect=/admin/activity`。

## 注意事项

- 后端 admin 权限由 `ADMIN_EMAILS` 白名单控制，前端只做体验层 gate。
- 新增 admin 写操作后，同步检查 `backend/app/features/admin/.context.md` 的缓存失效契约。
- 不要在前端硬编码 service-role key；所有 admin 数据必须经后端 admin API。

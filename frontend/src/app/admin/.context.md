# Admin - 管理后台页面

## 页面概述

`/admin` 是运营/CRM 管理后台，包含用户列表、用户详情、feature flags、LLM 用量、反馈和活跃趋势。所有页面都通过 server-side cookie 读取 access token，再调用后端 admin API。

## 路由

| 路由 | 页面 | 数据来源 | 认证 |
|------|------|----------|------|
| `/admin` | 用户管理看板 | `GET /api/admin/dashboard` | admin |
| `/admin/activity` | DAU / WoW / MoM 活跃趋势 | `GET /api/admin/activity?days=60` | admin |
| `/admin/flags` | Feature Flag 管理 | `/api/admin/flags` | admin |
| `/admin/llm-usage` | LLM token/cost 面板 | `GET /api/admin/llm-usage?days=N` | admin |
| `/admin/feedback` | 用户反馈 dashboard | `GET /api/admin/feedback` | admin |
| `/admin/users/[id]` | 用户详情/CRM 操作 | `/api/admin/crm/*` | admin |

## 文件结构

| 文件 | 职责 |
|------|------|
| `page.tsx` | dashboard server page，Suspense 先流式显示骨架屏，刷新 cookie 后调用 admin dashboard |
| `_components/AdminDashboard.tsx` | 用户列表、筛选、分页、bulk profile 更新 |
| `activity/page.tsx` | 活跃趋势 server page |
| `activity/_components/ActivityComparisonPanel.tsx` | 活跃趋势图表与区间比较 |
| `flags/page.tsx` / `flags/_components/FlagsAdminPanel.tsx` | feature flag 查询、写入、删除 |
| `llm-usage/page.tsx` / `llm-usage/_components/LlmUsagePanel.tsx` | LLM 用量查询与展示 |
| `feedback/page.tsx` / `feedback/_components/FeedbackDashboard.tsx` | 邮件反馈趋势、邮件明细、Contact 反馈 inbox |
| `users/[id]/page.tsx` / `users/[id]/_components/UserDetail.tsx` | 用户详情、CRM 资料、互动记录、授权操作 |

## Dashboard 数据流

- `page.tsx` 先在 Suspense 外读取/刷新 cookie 并调用 `GET /api/admin/whoami` 做 admin gate，避免未授权 404 在流式响应开始后才发生；通过 gate 后用 `Suspense` 包住 async dashboard content，先流式返回 skeleton，随后首屏请求 `GET /api/admin/dashboard?page=1&page_size=50&sort_key=last_active_at&sort_dir=desc`，返回用户页和轻量 DAU 后替换成真实 dashboard。
- `AdminDashboard.tsx` 只持有当前页 `users`；搜索、筛选 chip、状态卡、排序、翻页都会重新请求 `/api/admin/dashboard&include_activity=false`，并保留首屏已有的 `activity`，避免每次筛选都重算 DAU。
- `/api/admin/dashboard` 返回：
  - `users`：当前页用户，不是全量用户。
  - `pagination`：当前 query 的 `page/page_size/total/total_pages`。
  - `summary`：全局 category counts。
  - `chip_counts`：全局 chip facet counts。
  - `engagement`：全局互动摘要。
  - `activity`：DAU 趋势数据。

## 认证与错误处理

- 页面先通过 `getAuthCookies()` 读取 `app_access_token` / `app_refresh_token`。
- access token 缺失但 refresh token 存在时，server page 会调用 Insforge refresh 并续写 cookies。
- `/admin` 和 `/admin/users/[id]` 对 401/403 使用 `notFound()` 隐藏后台存在性。
- `/admin/activity` 对无 token / 401 显式跳 `/login?redirect=/admin/activity`。

## 注意事项

- 后端 admin 权限由 `ADMIN_EMAILS` 白名单控制，前端只做体验层 gate。
- 用户详情页的 Agent 对话只展示 runtime sessions：summary 来自 `agent_sessions` / `agent_session_events`，展开详情通过 `{agent_id}:{session_id}` 读取完整 runtime messages；不再调用或展示 `picker_conversations`。
- 新增 admin 写操作后，同步检查 `backend/app/features/admin/.context.md` 的缓存失效契约。
- 不要在前端硬编码 service-role key；所有 admin 数据必须经后端 admin API。
- 不要在前端把 `data.users` 当全量用户做 filter/sort/slice；它只代表当前页。
- 筛选语义由后端/DB 保证：chip 组内 OR、组间 AND。
- 批量选择只针对当前页；跨页批量操作需要新接口设计，不能偷偷在前端拉全量。
- “复制本页邮箱”只复制当前页邮箱。如需复制全部匹配结果，需要新增服务端 export/search endpoint。

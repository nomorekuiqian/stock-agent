# Pricing - 定价与 Checkout 成功页

## 页面概述

`/pricing` 展示简化后的 Free / Pro / Max 订阅方案并触发 Stripe 付费流程。页面保留价格、每档核心功能、当前方案状态、CTA、用户好评和少量 FAQ；不展示折扣、原价、早鸟名额或促销标签。新用户创建 Checkout；已有 Pro 订阅的用户升级 Max 时走 Billing Portal subscription update confirm。`/pricing/success` 处理 Checkout/Portal 回跳后的订阅激活轮询。

## 路由

| 路由 | 页面 | 数据来源 | 认证 |
|------|------|----------|------|
| `/pricing` | 定价页 | `SubscriptionContext` + `lib/pricing.ts` | 否，checkout 需登录 |
| `/pricing/success` | Checkout/Portal 回跳激活等待页 | `/payment/checkout-session/complete` + `/payment/subscription-status?fresh=true` + `/payment/me/entitlements?fresh=true` | 需要用户 session |

## 文件结构

| 文件 | 职责 |
|------|------|
| `page.tsx` | Free/Pro/Max 简化定价、当前方案状态、checkout CTA、用户好评、少量 FAQ |
| `success/page.tsx` | 轮询订阅/权益激活，刷新 React Query cache 后跳转 |
| `success/__tests__/page.test.tsx` | Max 激活等待和 legacy checkout 参数归一化回归 |

## 数据流

```text
/pricing
  -> 未登录点击订阅: /login?redirect=/pricing
  -> 已登录点击订阅: useSubscription().createCheckout(tier)
  -> 新订阅: Stripe Checkout
  -> 已有订阅升级: Stripe Billing Portal subscription_update_confirm
  -> /pricing/success?tier=<pro|max>&product=<product>&next=<path>[&session_id=...]
  -> 如有 session_id，先 POST /payment/checkout-session/complete
  -> 轮询 subscription-status + entitlements
  -> invalidate feature flags
  -> router.replace(next)
```

## 注意事项

- `normalizeNext()` 只允许站内 `/` 开头路径，防止 open redirect。
- Pro 为 $10/月，Max 为 $20/月。价格显示来自 `lib/pricing.ts`，Stripe 实际金额以 backend price id 对应的 Price 为准；页面不展示折扣/划线原价。
- Max 激活要求 `ai_research_engine` entitlement 到位后才跳转。
- `subscription-status?fresh=true` 会触发后端从 Stripe Subscription 拉取一次最新状态，用于 Portal 升级回跳和 webhook 延迟兜底。
- 旧 `tier=ultra` / `product=creator_max_qinbafrank` checkout 回跳会被成功页归一化为 Max，用于兼容历史链接。

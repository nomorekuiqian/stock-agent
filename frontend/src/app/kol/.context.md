# KOL Persona Pages

## 功能概述

KOL 专属投研驾驶舱页面，路由 `/kol/[username]`。首个 persona 是 qinbafrank，把已蒸馏的方法论 + 真实推文历史包装成可浏览、可下钻的前端入口。

不是普通博主页，也不声称代表博主本人；它是 TheMarketBrew 基于公开推文蒸馏 + 聚合的研究界面。

## 路由结构

| 路径                      | 页面                   | 用途                                                                                  |
| ------------------------- | ---------------------- | ------------------------------------------------------------------------------------- |
| `/kol/[username]`         | Overview（首页）       | qinbafrank 四入口总览：过往精华 / 个股 / 全量内容库 / Chat；其他 persona 保持 2x2 mini 模块网格 |
| `/kol/[username]/latest`  | Content Library / Latest | qinbafrank 全量内容库：过往精华 + 全量 Live Feed；其他 persona 保持全量原文流        |
| `/kol/[username]/sectors` | Frank Highlights / Sectors | qinbafrank 过往精华内容库：7 个主题板块；其他 persona 保持 Sector Atlas              |
| `/kol/[username]/macro`   | Macro Content / Macro  | qinbafrank 宏观内容：流动性 / 财政扩张 / 贸易战与地缘；其他 persona 保持宏观主题浏览 |
| `/kol/[username]/history` | Redirect               | qinbafrank 旧美股规律入口，重定向到 `/sectors?topic=market-rules`                   |
| `/kol/[username]/stocks`  | Company Recommendations | qinbafrank 个股：推荐档案 + 价格验证 + 原文时间线；其他 persona 保持标的列表          |
| `/kol/[username]/chat`    | Chat                   | 手动追问启动页；页面内 CTA / chips 跳 `/research` 执行真实对话                        |

整体 chrome 在 `layout.tsx`：`PersonaHero`（顶部）+ `SubNav`（PC 60px 侧边栏 / 移动端横向 strip）+ 内容流末尾的 `TransparencyNote`。

## 首页（page.tsx）结构

```
[Hero]                                    ← layout 渲染
[qinbafrank 首页]
[一句话定位]                              ← 历史内容档案馆 + 框架地图
[Chat 按钮]                               ← 直接进入研究工具，不在首页放输入框
[四入口总览]                              ← 过往精华 / 个股 / 全量内容库 / Chat
[快速预览网格]
  ① 过往精华    │  ② 个股
  ③ 全量内容库  │  ④ Chat

[其他 persona 首页]
[博主研究室一句话定位]
[Chat 按钮]
[2x2 模块网格]
  ① 最新观点    │  ② 宏观视角
  ③ 板块视角    │  ④ 个股视角
[TransparencyNote]                        ← layout 在 main 内容流末尾渲染
```

| 模块           | 内容                                                                          | 数据来源                           |
| -------------- | ----------------------------------------------------------------------------- | ---------------------------------- |
| qinbafrank 定位 | `这是他的历史内容档案馆：先看框架，再回到原文验证。` | `frankContentData.ts` + 静态产品定位 |
| Chat 按钮      | 单个大按钮，点击进入 `/research?agent=kol&persona=X`，不自动发送问题          | 静态 CTA                           |
| 四入口总览     | 过往精华 / 个股 / 全量内容库 / Chat                                            | `FRANK_SECTIONS`                   |
| 过往精华       | 7 个主题：AI 大趋势、资本开支战争、过往推荐公司、美股调整规律、美股行情判断、宏观与地缘、加密基建与 RWA；每个主题下按子话题分组 | `FRANK_HIGHLIGHT_TOPICS` + `FRANK_FEATURED_GROUPS` + `FRANK_FEATURED_CONTENT` |
| 个股           | PLTR / HOOD / MU / 7709 / EWY / AVGO / BB / IBM 等推荐档案，结合 live price     | `FRANK_COMPANY_RECOMMENDATIONS` + `cockpitTickers` |
| 全量内容库     | 过往精华 tab + 全量原文 tab                                                     | `FRANK_FEATURED_CONTENT` + `LiveFeed` |
| Chat           | 跳转 `/research?agent=kol&persona=X`，用精华主题和个股档案继续追问              | 静态 CTA                           |

> 不保留：「这个驾驶舱是什么·怎么用」教程卡 —— 老用户冗余,新用户应被价值打动而非教程。

    - 旧美股规律不再是独立一级入口，而是 `topic=market-rules` 下的精华主题
    - 交互沿用原产业地图的资料库阅读器形态：顶部主题 tab；左侧为检索输入 + 子话题卡片列表；右侧为当前子话题阅读器

    - 右侧原文阅读器必须在原文上方展示导读和“为什么重要”，再展示站内原文；外部 X 原文链接放在标题旁，并带 X 标识；阅读器内不再放独立「原文阅读」工具条
    - 卡片只使用已提供 tweet id；IBM 这类已点名但无链接的公司显示「待补原文」
    - 该页不放顶部「按当前主题追问」按钮，也不放单条「追问这条」按钮；追问入口保留在 SubNav / Chat 页面

## 关键设计决策

- **粉丝优先 + 驾驶舱质感**：首页 dashboard 用 2x2 mini grid（每卡有 mini 数据：价格涨跌 / mention 次数）；追问入口收敛为单个 Chat 按钮，避免首页出现重复输入框。
- **追问入口保持轻量**：首页按钮和 `SubNav` 里的 Chat 入口只跳 `/research?agent=kol&persona=X`，不带 `q` 或 `symbol`，让研究工具首页负责承接真实输入；`/chat` 子页仍可用重点 CTA 区解释方法论 / 数据 / 原文三类上下文。
- **ChatComposer 不接 SSE**：如果页面内使用 ChatComposer，只收集输入并跳到 `/research` 触发真实对话（research 页 useEffect 监听 `q=` 自动 handleSend）。首页已简化为单个 Chat 按钮，不再内嵌输入框。
- **带问题深链只用于明确上下文**：板块 / 宏观主题 / 个股详情顶部 CTA 等具体追问入口可使用 `buildKolAgentHref()` 生成 `/research?agent=kol&persona=X&q=...`，保留对应上下文；首页主 CTA 和 `SubNav` Chat 入口只进入研究工具首页，不自动发送问题。
- **ticker 抽取靠中文名字典**：qinbafrank 不用 `$cashtag`、按中文名写公司，后端 `cockpit.TICKER_ALIASES` 维护 `{ticker: [中文名,英文别名]}` (~24 个核心标的) 匹配原文。不依赖 enrichment。
- **多空上色 MVP 不做**：提及点单色；stance 留后续。
- **写死 username 形参，前端不抽 persona 路由**：后端端点保留 `{username}`。
- **Frank 主入口改为四入口档案馆**：`/kol/qinbafrank` 不再突出旧的“研究地图/宏观视角”两块，而是把用户动作收敛为过往精华、个股、全量内容库和 Chat。
- **过往精华取代产业地图但保留阅读形态**：`/kol/qinbafrank/sectors` 不再渲染 `IndustryMap`，改为 `FrankHighlights`，完整承载 Frank 主动点名的 7 个主题板块；交互仍是左侧检索卡片、右侧导读 + 原文 reader，但卡片粒度从单条推文升级为子话题组。
- **AI 大趋势与资本开支战争分开**：AI 大趋势独立承载渗透率、产业进化和竞争格局；资本开支战争独立承载 capex、算力瓶颈、存储、光、CPU、800V HVDC、电力和边缘/端侧 AI。
- **美股规律并入过往精华**：`/kol/qinbafrank/history` 只保留为旧链接 redirect，跳到 `/sectors?topic=market-rules`。导航里不再出现独立“美股规律” section。
- **公司推荐结合 stocks 页面**：`/kol/qinbafrank/stocks` 保留价格、提及时间线和 ticker 搜索，同时新增推荐档案，避免另起一个孤立公司页。
- **全量内容库结合 latest 页面**：`/kol/qinbafrank/latest` 从单纯时间流升级为“过往精华 + 全量原文”，避免同时维护 library 和 latest 两套入口。
- **Frank 宏观页保留兼容**：`/kol/qinbafrank/macro` 仍可承载宏观传导地图，但宏观与地缘的主动反馈内容同时进入过往精华主题。非 Frank persona 仍走旧 `MacroPerspectivePanel`。
- **缺失推文不占位**：`researchMapData.ts` 只放当前已命中的 tweet id；Frank 反馈里暂未入库的早期推文后续补齐后再接入，不显示“缺失卡”。
- **板块页改为 Atlas 而不是左侧列表（non-frank / legacy）**：非 Frank `/sectors` 仍列出产品顶层板块。当前语料中的 HBM / 电力 / Fintech 文件作为子主题并入顶层板块，不单独成为入口。
- **板块页避免文章化阅读（non-frank / legacy）**：旧 `SectorExplorer` 首屏用 icon / badge / attention bar 区分 4 条主线；正文按「他的观点 → 过往评论 → 打脸条件 → 下钻产业链」组织。用户界面不暴露内部语料版本词。
- **宏观内容独立入口**：旧宏观页从 `/sectors` 抽出到 `/macro`。Frank 的 `/macro` 暴露为「宏观内容」，承接流动性、财政扩张、贸易战和地缘政治；非 Frank 仍使用旧宏观主题框架。
- **宏观框架页只保留主题下钻（non-frank / legacy）**：旧宏观页首屏引导用户在 4 个宏观主题间切换；每个主题只回答「看什么数据」「怎么判断」「有哪些历史原文」三件事。
- **移动端 Atlas 优先（non-frank / legacy）**：`SectorExplorer` 在移动端先显示板块地图，再逐个展示 narrative panel；展开态只保留一个板块，避免长文堆叠。Frank 过往精华移动端以主题 tab、检索卡片和阅读器纵向展开，点选卡片后滚动到 reader。
- **移动端个股页先露出详情**：`StockExplorer` 在移动端把 ticker rail 限高为可滚动面板，避免 80+ 标的列表把个股详情推到页面深处。
- **SubNav Chat 入口要和内容项区分**：`SubNav` 的 Chat/追问入口使用实心 `primary`（emerald）按钮样式，PC 侧边栏表现为绿色实心图标按钮，移动端横向导航表现为绿色实心入口。
- **Frank 页面组经过 sweep 统一**：过往精华、首页预览、个股档案和追问入口共享同一套中文眉标、`text-xs`/`text-sm` 字号层级、8px 以内圆角和 44px 左右触控目标。可点击 mini preview 头部统一带箭头提示，避免用户把卡片误解成静态内容。

## 注意事项

- 浏览公开；只有进入 `/research` 使用 KOL agent 时才需登录 + `kol_research_agent` flag。
- 方法论内容标「已蒸馏,非本人发言」；个股摘录均为原文逐字 + 原文链接。
- 不把回答写成「qinbafrank 本人认为」；命中原推才说「原文支持」。
- 页面内容流末尾保留 **内容边界** 提示，不作为网页 footer；不展示价格数据来源。
- 后端聚合见 `backend/app/features/kol_research/cockpit.py` + `.context.md`。
- 字号 / 字体严格遵守 `docs/constraints/design-system.md`。

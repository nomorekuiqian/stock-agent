# Frank Agent Beta Landing Page

## 功能概述

`/frank-agent` 是 TheMarketBrew Frank Agent Beta 的公开落地页，主要承接 Frank / qinbafrank 的 X/Twitter 流量和 UTM 归因。页面目标是用一个克制的 Beta offer 验证用户是否愿意为“Frank 公开研究框架 + AI 投研助手”付费。

页面按三段组织，整体文案必须短：

1. **介绍 Frank**：一句话说明他长期研究宏观、美股科技、AI 供应链和 Crypto。文案必须克制，不写成正式背书或“顶级投资人”式神化表达。
2. **Agent 核心功能与卖点**：突出查旧观点、判断新闻、用框架看股票、整理下一步清单。
3. **Beta 权益与 CTA**：使用现有 Max 早期价承接，说明限量 Beta、可退款、非投资建议。

页面主卖点是：在 TheMarketBrew 里复用 Frank 公开研究框架，而不是让用户重翻 X 时间线。

## 文件结构

| 文件 | 职责 |
|------|------|
| `page.tsx` | Server page wrapper + SEO metadata |
| `_components/FrankAgentLandingClient.tsx` | 落地页交互、CTA、订阅/登录分流、埋点 |

数据和行为：

```text
/frank-agent
  -> 未登录 CTA: /login?redirect=/frank-agent
  -> 已登录非 Max CTA: createCheckout("max", "/frank-agent")
  -> 已是 Max CTA: /research?agent=kol&persona=qinbafrank
  -> 观点库次级入口: /kol/qinbafrank
```

Stripe Checkout 成功页仍由现有 `/pricing/success` 统一处理，成功后根据 `next` 返回目标路径。

## 埋点

页面使用 Vercel Analytics 和 PostHog product analytics：

- `frank_beta_landing_view`
- `frank_beta_cta_click`
- `frank_beta_checkout_started`
- `frank_beta_signup`
- `frank_beta_secondary_cta_click`
- `frank_beta_cockpit_click`
- `frank_beta_example_question_click`

事件会携带 `utm_source`、`utm_medium`、`utm_campaign`、`ref`、CTA 位置、登录状态、是否已是 Max 和 `tier=max`。

## 设计决策

- 独立路由，适合 Frank 的 Twitter/UTM 流量，不默认放入主导航。
- 首屏标题直接写产品名：`Frank AI 投研助手 Beta`，卖点放在副标题。
- 首屏右侧不再展示“Agent 工作流程”式预览；改为产品入口卡、三项核心能力、语料覆盖数字和 `/kol/qinbafrank` 观点库入口。
- 页面内容控制在三段：介绍 Frank、Agent 能力、Beta CTA。避免长段落和流程解释。
- Frank 介绍强调跨市场研究框架、产业链视角、公开内容沉淀；不承诺收益、胜率、荐股，也不暗示 Frank 本人逐条回复。
- Agent 功能按真实后端能力表达：KOL skill lens、历史公开观点 RAG、市场数据 brief、证据/事实/推断分离、后续观察清单。
- Watchlist 只作为可追问示例，不作为 P0 主卖点。
- 付费 offer 使用现有 Max 订阅能力，避免新增 beta pass 计费分支。
- 视觉沿用 TheMarketBrew 金融编辑风：深色背景、emerald 主 CTA、少量 amber/sky 语义色、8px 圆角、克制边框和原生产品 UI。
- 页面内容统一使用 `font-editorial`，避免标题、问题、价格数字在不同字体间跳变。

# Qinbafrank Agent Waitlist Landing Page

## 功能概述

`/frank-agent` 是 TheMarketBrew Qinbafrank Agent 的公开 waitlist 落地页，主要承接 Qinbafrank 的 X/Twitter 流量和 UTM 归因。页面目标是收集试用申请，而不是直接销售订阅或启动 Stripe checkout。

页面按三段组织，整体文案必须短：

1. **介绍 Qinbafrank**：一句话说明他长期研究宏观、美股科技、AI 供应链和 Crypto。文案必须克制，不写成正式背书或“顶级投资人”式神化表达。
2. **Agent 核心功能与卖点**：突出四个入口：向博主 Agent 直接提问、查阅过往内容库、使用博主专属投研工作流、通过博主视角看市场。
3. **Waitlist 与 CTA**：引导用户注册账号后填写 `/request-access?source=qinbafrank-agent`，申请早期试用名额。

页面主卖点是：在 TheMarketBrew 里复用 Qinbafrank 公开研究框架，而不是让用户重翻 X 时间线。

## 路由与数据流

| 路由 | 页面 | 数据来源 | 需要认证 |
| --- | --- | --- | --- |
| `/frank-agent` | Qinbafrank Agent waitlist landing | 静态文案 + Auth context | 否 |

数据和行为：

```text
/frank-agent
  -> 未登录 CTA: /login?mode=signup&redirect=/request-access?source=qinbafrank-agent
  -> 已登录 CTA: /request-access?source=qinbafrank-agent
  -> 观点库次级入口: /kol/qinbafrank
```

`/frank-agent` 必须保留在 `frontend/middleware.ts` 的 `PUBLIC_ROUTES`，否则 Twitter 冷流量会在看到落地页前被 cookie gate 拦到登录页。

## 埋点

页面使用 Vercel Analytics 和 PostHog product analytics：

- `qinbafrank_waitlist_landing_view`
- `qinbafrank_waitlist_cta_click`
- `qinbafrank_waitlist_signup_started`
- `qinbafrank_waitlist_secondary_cta_click`
- `qinbafrank_waitlist_library_click`

事件会携带 `utm_source`、`utm_medium`、`utm_campaign`、`ref`、CTA 位置和登录状态。

## 设计决策

- 独立路由，适合 Qinbafrank 的 Twitter/UTM 流量，不默认放入主导航。
- 首屏标题直接写产品名：`Qinbafrank AI 投研助手 Waitlist`，不加额外 badge；卖点放在副标题。
- 首屏右侧不展示“Agent 工作流程”式预览；改为产品入口卡、四项核心能力和 `/kol/qinbafrank` 观点库入口。不要在首屏展示未解释口径的覆盖数字。
- 页面内容控制在三段：介绍 Qinbafrank、Agent 能力、waitlist CTA。避免长段落和流程解释。
- Qinbafrank 介绍强调跨市场研究框架、产业链视角、公开内容沉淀；不承诺收益、胜率、荐股，也不暗示本人逐条回复。
- Agent 功能按真实后端能力表达：KOL skill lens、历史公开观点 RAG、市场数据 brief、证据/事实/推断分离、后续观察清单。
- Watchlist 只作为可追问示例，不作为 P0 主卖点。
- 本页不触发 Stripe checkout，不展示价格，也不承诺正式开放时间。
- 视觉沿用 TheMarketBrew 金融编辑风：深色背景、emerald 主 CTA、少量 amber/sky 语义色、8px 圆角、克制边框和原生产品 UI。
- 页面内容统一使用 `font-editorial`，避免标题、问题、数字在不同字体间跳变。

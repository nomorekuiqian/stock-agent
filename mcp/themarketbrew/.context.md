# TheMarketBrew MCP Package

## Purpose

Installable stdio MCP server that acts as a thin local adapter for the
TheMarketBrew backend lens engine. The local package exposes MCP tools, reads
configuration from environment variables, calls backend endpoints, and
returns context packs for the user's own agent to write the final answer. The
package is persona-neutral: clients should list available personas, choose one
based on the user's query and material coverage, then pass `persona`
explicitly. Serenity is available as `aleabitoreddit` when the backend exposes
that material source.

This package no longer ships distilled methodology assets. Core assets,
ticker/sector playbooks, Evidence Map, vector search, market context, and
workflow logic live on the backend. Adding a persona such as Serenity should
change backend material sources and tests, not the NPM package file list.

## Runtime Configuration

```text
THEMARKETBREW_BACKEND_URL=http://127.0.0.1:8000/api
```

`THEMARKETBREW_BACKEND_URL` points at the backend `/api` base URL.
`THEMARKETBREW_PERSONA` is optional and should only be used when a client or
workspace intentionally wants to pin one default persona. Legacy
`MARKET_LENS_BACKEND_URL` and `MARKET_LENS_PERSONA` variables remain accepted
as fallback.

## Tools

Primary tools are persona-neutral and accept a `persona` argument. If the user
has not named a persona, call `market_lens_personas` first and select one based
on query fit and lens coverage:

- `market_lens_status`
- `market_lens_personas`
- `market_lens_list_lenses`
- `market_lens_get_lens`
- `market_lens_search_lenses`
- `market_lens_search_evidence`
- `market_lens_get_evidence_by_ids`
- `market_lens_build_context`
- `market_lens_stock_diagnosis`
- `market_lens_market_regime`
- `market_lens_compare`
- `market_lens_research_memo`

Material tools expose the backend distilled lens index across
`core/framework/macro/sector/ticker`. `market_lens_get_lens` returns the full
distilled markdown body, parsed sections, metadata, and Evidence Map tweet IDs.
Evidence tools return historical tweets/chunks. Workflow tools return composed
backend context packs, not final investment advice.

The backend must keep persona material roots independent. Frank uses its own
methodology root; Serenity uses its own registered skill directory. The adapter
only passes the `persona` argument through to backend endpoints.

## Backend Endpoints

```text
GET  /api/kol_research/mcp/personas
GET  /api/kol_research/personas/{username}/mcp/status
GET  /api/kol_research/personas/{username}/mcp/lenses
GET  /api/kol_research/personas/{username}/mcp/lenses/{lens_type}/{lens_id}
POST /api/kol_research/personas/{username}/mcp/lenses/search
POST /api/kol_research/personas/{username}/mcp/evidence/by-ids
POST /api/kol_research/personas/{username}/mcp/search
POST /api/kol_research/personas/{username}/mcp/market-brief
POST /api/kol_research/personas/{username}/mcp/context
POST /api/kol_research/personas/{username}/mcp/workflow
```

All listed MCP endpoints are public backend context endpoints. They do not use
the old Market Lens invite-code beta path.

## Validation

Run from `mcp/themarketbrew`:

```bash
npm run build
npm run inspect
npm run smoke
npm run smoke:adapter
```

Local MCP validation for Serenity requires a running backend with
`aleabitoreddit` exposed in `/api/kol_research/mcp/personas`:

```bash
THEMARKETBREW_BACKEND_URL=http://127.0.0.1:8000/api \
npm run smoke:live
```

Packaging verification should confirm no local assets are included:

```bash
npm pack --dry-run
```

## Safety Contract

- Never impersonate the selected persona.
- Only cite returned `kol_chunks` as direct historical evidence.
- Separate historical evidence, live market data, and methodology inference.
- No direct buy/sell/add/reduce position instructions.
- No exact price targets.

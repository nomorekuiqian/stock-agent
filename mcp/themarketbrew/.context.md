# TheMarketBrew MCP Package

## Purpose

Installable stdio MCP server that acts as a thin local adapter for the
TheMarketBrew backend lens engine. The local package exposes MCP tools, reads
configuration from environment variables, calls backend endpoints, and
returns context packs for the user's own agent to write the final answer.
Content tools require the user to authorize the local adapter with a
TheMarketBrew account through `market_lens_login`; the adapter never asks for
or stores the user's website password. The package is persona-neutral: clients
should list available personas, choose one based on the user's query and
material coverage, then pass `persona` explicitly. Serenity is available as
`aleabitoreddit` when the backend exposes that material source.

This package no longer ships distilled methodology assets. Core assets,
ticker/sector playbooks, Evidence Map, vector search, market context, and
workflow logic live on the backend. Adding a persona such as Serenity should
change backend material sources and tests, not the NPM package file list.

## Runtime Configuration

```text
THEMARKETBREW_BACKEND_URL=http://127.0.0.1:8000/api
THEMARKETBREW_AUTH_FILE=~/.themarketbrew/mcp-auth.json
THEMARKETBREW_ACCESS_TOKEN=optional-preissued-token
```

`THEMARKETBREW_BACKEND_URL` points at the backend `/api` base URL.
`THEMARKETBREW_PERSONA` is optional and should only be used when a client or
workspace intentionally wants to pin one default persona. Legacy
`MARKET_LENS_BACKEND_URL` and `MARKET_LENS_PERSONA` variables remain accepted
as fallback.

`market_lens_login` starts a browser/device authorization flow and returns a
verification URL plus user code. After the user approves the code in the
website session, `market_lens_auth_status` exchanges the device code for an
opaque MCP bearer token and stores it in `THEMARKETBREW_AUTH_FILE` (default
`~/.themarketbrew/mcp-auth.json`, mode `0600` where supported). The cache is
scoped to the backend URL. `THEMARKETBREW_ACCESS_TOKEN` and legacy
`MARKET_LENS_ACCESS_TOKEN` remain accepted for automation or manual testing,
but normal clients should use the login tool.

## Tools

Primary tools are persona-neutral and accept a `persona` argument. If the user
has not named a persona, call `market_lens_personas` first and select one based
on query fit and lens coverage:

- `market_lens_status`
- `market_lens_login`
- `market_lens_auth_status`
- `market_lens_logout`
- `market_lens_data_catalog`
- `market_lens_get_brief`
- `market_lens_get_stock_data`
- `market_lens_get_market_data`
- `market_lens_get_news`
- `market_lens_personas`
- `market_lens_list_lenses`
- `market_lens_get_lens`
- `market_lens_search_lenses`
- `market_lens_search_evidence`
- `market_lens_get_evidence_by_ids`
- `market_lens_build_context`
- `market_lens_stock_diagnosis`
- `market_lens_market_regime`
- `market_lens_compare`
- `market_lens_research_memo`

Material tools expose the backend distilled lens index across
`core/framework/macro/sector/ticker`. `market_lens_get_lens` returns the full
distilled markdown body, parsed sections, metadata, and Evidence Map tweet IDs.
Evidence tools return historical tweets/chunks. Data tools return backend data
envelopes with `data`, `errors`, `freshness`, and limits. Workflow tools return
composed backend context packs, not final investment advice.

P0 data tools:

- `market_lens_data_catalog` lists available data tools, section names, limits,
  and freshness policy.
- `market_lens_get_brief` fetches coarse-grained stock, peer, macro, or
  industry briefs and should be the default current-facts entry point.
- `market_lens_get_stock_data` fetches requested fine-grained ticker sections:
  quote, profile, fundamentals, valuation, technical, news, earnings/calendar,
  price history, transcript, insider trading, press releases, and market
  overview.
- `market_lens_get_market_data` fetches market overview, macro/risk/liquidity
  and sentiment sections, economic/earnings calendars, morning/weekly reports,
  and Twitter digest context.
- `market_lens_get_news` fetches source-attributed recent stock, market, press
  release, morning report, and Twitter digest news.

The backend must keep persona material roots independent. Frank uses its own
methodology root; Serenity uses its own registered skill directory. The adapter
only passes the `persona` argument through to backend endpoints.

## Backend Endpoints

```text
POST /api/kol_research/mcp/auth/device/start
POST /api/kol_research/mcp/auth/device/token
GET  /api/kol_research/mcp/auth/status
POST /api/kol_research/mcp/auth/revoke
GET  /api/kol_research/mcp/data/catalog
POST /api/kol_research/mcp/data/brief
POST /api/kol_research/mcp/data/stock
POST /api/kol_research/mcp/data/market
POST /api/kol_research/mcp/data/news
GET  /api/kol_research/mcp/personas
GET  /api/kol_research/personas/{username}/mcp/status
GET  /api/kol_research/personas/{username}/mcp/lenses
GET  /api/kol_research/personas/{username}/mcp/lenses/{lens_type}/{lens_id}
POST /api/kol_research/personas/{username}/mcp/lenses/search
POST /api/kol_research/personas/{username}/mcp/evidence/by-ids
POST /api/kol_research/personas/{username}/mcp/search
POST /api/kol_research/personas/{username}/mcp/market-brief
POST /api/kol_research/personas/{username}/mcp/context
POST /api/kol_research/personas/{username}/mcp/workflow
```

`/mcp/status` and device start/token polling are public diagnostics/auth
helpers. Content, material, evidence, data, context, and workflow endpoints
require `Authorization: Bearer <mcp_token>` issued to a TheMarketBrew account.
They do not use the old Market Lens invite-code beta path.

## Validation

Run from `mcp/themarketbrew`:

```bash
npm run build
npm run inspect
npm run smoke
npm run smoke:adapter
```

Live MCP validation requires a running backend. Without a stored MCP token or
`THEMARKETBREW_ACCESS_TOKEN`, `smoke:live` only verifies that gated content
returns `auth_required`; with a token it also validates persona, data, and
workflow calls. Serenity validation requires `aleabitoreddit` exposed in
`/api/kol_research/mcp/personas`:

```bash
THEMARKETBREW_BACKEND_URL=http://127.0.0.1:8000/api \
npm run smoke:live
```

Packaging verification should confirm no local assets are included:

```bash
npm pack --dry-run
```

## Safety Contract

- Never impersonate the selected persona.
- Only cite returned `kol_chunks` as direct historical evidence.
- Separate historical evidence, live market data, and methodology inference.
- No direct buy/sell/add/reduce position instructions.
- No exact price targets.

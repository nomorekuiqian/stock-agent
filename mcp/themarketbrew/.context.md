# TheMarketBrew OKX Context MCP Package

## Purpose

Installable stdio MCP server that acts as a thin adapter for the OKX-facing
TheMarketBrew context backend. It exposes three tools, calls
`/api/okx-mcp/*`, and returns context/data packs for the user's own agent to
write the final answer.

The package does not ship distilled methodology assets and no longer performs
TheMarketBrew browser/device account authorization. Access to paid backend
resources is expected to be handled by OKX x402 payment middleware or reverse
proxy at the HTTP service boundary.

## Package Layout

```text
mcp/themarketbrew/
├── src/index.ts                 # MCP stdio server registration
├── src/tools.ts                 # three-tool definitions and routing
├── src/prompts.ts               # reusable MCP prompts for caller agents
├── src/live.ts                  # OKX backend API client
├── scripts/inspect.mjs          # package metadata sanity check
├── scripts/smoke-test.mjs       # no-backend MCP tool-list smoke test
├── scripts/adapter-smoke-test.mjs # mocked-backend adapter smoke test
├── scripts/live-smoke-test.mjs  # real backend smoke test
├── README.md                    # install and MCP client setup guide
└── package.json
```

## Runtime Configuration

```text
THEMARKETBREW_BACKEND_URL=https://stock-agent-production.up.railway.app/api
OKX_MCP_BACKEND_URL=optional fallback
MARKET_LENS_BACKEND_URL=legacy fallback
```

The URL must point at the backend `/api` base. The adapter itself does not hold
TheMarketBrew account tokens. If the backend returns HTTP 402, `live.ts`
returns a structured `payment_required` payload so OKX/wallet-aware callers can
pay and retry.

## Tools

- `themarketbrew_discovery`
  - Calls `GET /api/okx-mcp/discovery`
  - Returns personas, data capability catalog, payment model, routing guidance,
    and safety contract.
- `themarketbrew_persona_context`
  - Calls `POST /api/okx-mcp/persona-context`
  - Returns selected persona, methodology lenses, Evidence Map tweets, optional
    vector evidence, answer discipline, and suggested answer shape.
- `themarketbrew_market_data`
  - Calls `POST /api/okx-mcp/market-data`
  - `data_type` selects catalog / brief / stock / market / news.
  - Returns backend data envelopes with section-level `errors` and `freshness`.

The MCP package intentionally hides the old 20+ raw `market_lens_*` tools. The
backend still retains most capabilities; they are aggregated behind the three
OKX tools.

## Validation

Run from `mcp/themarketbrew`:

```bash
npm run build
npm run inspect
npm run smoke
npm run smoke:adapter
```

Live validation requires the OKX backend app running:

```bash
THEMARKETBREW_BACKEND_URL=http://127.0.0.1:8000/api npm run smoke:live
```

Packaging verification should confirm no local assets are included:

```bash
npm pack --dry-run
```

## Safety Contract

- Never impersonate the selected persona.
- Only cite returned `evidence_map_tweets` or `kol_chunks` as direct historical
  evidence.
- Separate historical evidence, live market data, and methodology inference.
- No direct buy/sell/add/reduce position instructions.
- No exact price targets.

# Frank Lens MCP Package

## Purpose

Installable stdio MCP server for qinbafrank methodology and KOL research
context. The package supports two modes:

- Offline tools read packaged markdown assets and require no backend.
- Live tools call the Stock Agent backend for vector evidence and market brief
  data.

It is a context/briefing provider, not a chat agent. It returns
evidence/methodology packs or loose narrative workflow briefings for a
user-owned agent to answer with its own model and tokens.

## Package Layout

```text
mcp/frank-lens/
├── assets/qinbafrank/           # packaged methodology markdown copied from backend
├── src/index.ts                 # MCP stdio server and tool registration
├── src/live.ts                  # backend API bridge for live tools
├── src/methodology.ts           # markdown parser, search, lens builders
├── scripts/inspect.mjs          # direct package sanity check
├── scripts/smoke-test.mjs       # offline JSON-RPC stdio smoke test
├── scripts/live-smoke-test.mjs  # live JSON-RPC stdio smoke test
├── README.md                    # Chinese install and MCP client setup guide
└── package.json
```

## Live Data Source

Live tools default to:

```text
FRANK_LENS_BACKEND_URL=http://127.0.0.1:8000/api
FRANK_LENS_PERSONA=qinbafrank
```

Backend endpoints:

```text
GET  /api/kol_research/personas/{username}/profile
POST /api/kol_research/personas/{username}/mcp/search
POST /api/kol_research/personas/{username}/mcp/market-brief
POST /api/kol_research/personas/{username}/mcp/context
```

All live tools are public read MVP calls (no per-user auth yet).

## Tools

Offline:

- `frank_list_lenses`
- `frank_get_methodology`
- `frank_search_evidence`
- `frank_get_ticker_lens`
- `frank_get_sector_lens`
- `frank_build_context`
- `frank_stock_diagnosis`
- `frank_market_regime`

Live:

- `frank_live_status`
- `frank_live_search_evidence`
- `frank_live_market_brief`
- `frank_live_build_context`
- `frank_live_stock_diagnosis`
- `frank_live_market_regime`

`frank_live_build_context` is the primary structured live context tool. It
combines packaged methodology with backend vector evidence and optional market
brief data.

The MVP user-facing workflows are:

- `frank_stock_diagnosis` / `frank_live_stock_diagnosis`: judge a stock through
  Frank's loose three-kill lens: valuation, earnings, or logic. These return
  markdown briefing text so the downstream agent can improvise the final answer
  rather than fill a rigid schema.
- `frank_market_regime` / `frank_live_market_regime`: judge market conditions
  through macro/risk-regime variables: liquidity/rates, earnings expectations,
  sector narrative, and logic breaks. These also return markdown briefing text.

## Safety Contract

- Never impersonate qinbafrank.
- Only say a historical view is directly supported when returned context
  includes evidence IDs/chunks.
- No direct buy/sell/add/reduce position instructions.
- Separate historical Frank evidence, current facts, and methodology
  inference.
- No exact price targets.

## Validation

Run from `mcp/frank-lens`:

```bash
npm run build
npm run inspect
npm run smoke
```

Live validation requires backend on `127.0.0.1:8000` or
`FRANK_LENS_BACKEND_URL`:

```bash
FRANK_LENS_BACKEND_URL=http://127.0.0.1:8000/api npm run smoke:live
```

Installed binary verification:

```bash
npm pack
TMP_PREFIX=/tmp/frank-lens-mcp-install
rm -rf "$TMP_PREFIX"
npm install --prefix "$TMP_PREFIX" -g ./themarketbrew-frank-lens-mcp-0.2.0.tgz
FRANK_LENS_MCP_BIN="$TMP_PREFIX/bin/frank-lens-mcp" npm run smoke
FRANK_LENS_BACKEND_URL=http://127.0.0.1:8000/api \
  FRANK_LENS_MCP_BIN="$TMP_PREFIX/bin/frank-lens-mcp" \
  npm run smoke:live
```

## Commercialization Notes

hosted/paid MCP, add auth, rate limits, usage metering, and creator-pack access
control at the backend boundary.
